# 网页性能评估与优化清单

评估日期：2026-10-09。代码基准：`cf88c1a`。

优先处理 **环境声指示动画、关于页布局偏移、首页晶苞的调度与加载、中文字体，以及项目页的首次切面初始化**。这些已有浏览器测量或临时对照支持。当前 JavaScript 包较小，较大的成本来自持续样式计算、字体和逐帧图像。

本次新增评估文档与[测量数据](performance/2026-10-09-evidence.json)。下文原型均只在独立浏览器中临时运行，网站源码保持原样。

### 01 · 环境声指示动画

**证据：** [Sound.astro](../src/components/chrome/Sound.astro) 第 151 行起的三组关键帧持续改变 `height`。在醒态阅读页，静音静置约 12ms/s，启声后约 994ms/s；保持音频播放，只改指示线动画后约 13ms/s。原实现每秒布局约 22–24ms，样式计算约 639ms。

**建议：** 固定三根线的布局高度，通过 `scaleY` 表达原有高度变化，保留中心对齐、三个周期、颜色和减少动态效果分支。这项优先实施，收益大且改动集中。

**验收：** 同一段音频持续播放，比较三个静置窗口；开声后的常驻任务增量应接近静音状态。按样式预览规范检查线宽、圆角和振幅，确认音频本身不受影响。

### 02 · 关于页首次布局偏移

**证据：** 手机三次 CLS 均为 0.5983，桌面为 0.5297–0.5793，来源均指向 `.about-slices`。[about-exit.ts](../src/scripts/about-exit.ts) 第 74 行在客户端加 `data-exit-on`，随后计算高度；[about.astro](../src/pages/about.astro) 对应规则把普通文档流切为 sticky，并设置负外边距。提前声明同一模式的手机对照三次 CLS 均为 0。

**建议：** 让支持该交互的页面在首次绘制前确定布局模式，保证初始化前后的占位稳定。继续保留无 JS、减少动态效果及初始化失败时的完整正文。

**验收：** 同条件三次 CLS ≤0.1，并查看加载录像。当前偏移发生在揭幕前，需区分装饰层计入 CLS 与用户实际看到的位移，不能把 0.598 解释为正文移动了相同比例的屏幕。

### 03 · 晶苞调度频率

**证据：** [home-bud.ts](../src/scripts/home-bud.ts) 第 288 行的 `tick` 每次进入便重新请求 rAF，再判断是否需要绘制。即使梦态只需 4fps，主线程仍不断被唤起。临时暂停该调度后，首页静置中位数从 696 降至 61ms/s。

**建议：** 根据当前状态的下一个目标帧时刻再请求 rAF；醒态补间、梦态跳格和换面分别使用所需节拍。可参考已有 [lib.ts](../src/scripts/lib.ts) 的延迟请求方式，保持真实时间差驱动，避免长按对齐变速失真。

**验收：** 同时测醒态、梦态、按住未满、中途释放、换面完成、收拢与重新进入。临时暂停用于定位成本；正式实现须保留动画节奏和相位。

### 04 · 晶苞资源与解码内存

**证据：** `home-bud.ts` 第 340 行起在 `load` 后串行加载四组序列；开始播放前先等待醒态 40 帧。预取没有按当前面、滚动离开首屏或用户长按意图进一步收敛。位图缓存虽有上限，实际常驻 10 张 800 × 800 位图，RGBA 像素约 **24.4 MiB**，短暂峰值 11 张约 **26.9 MiB**，另有 Blob 和画布成本。

**建议：** 先显示开场所需的一张静帧，按当前序列与临近换面意图分批补帧；非必要序列降低优先级，离开首屏时暂停后续预取。解码尺寸匹配实际显示尺寸，尤其是手机；尺寸变化时重新管理缓存并释放旧位图。`ready` 应反映真正可用的帧，避免中止预取后误判完整。

**验收：** 记录无操作、快速滚走、长按换面三种情况下的帧请求数、总字节和首帧出现时刻；验证慢网与单帧失败。减少动态效果和模拟 `saveData` 已各只请求 2 帧，应保留。

### 05 · 中文字体体积与发现时机

**证据：** 首页请求 405.7KiB 字体，样张随笔 461.2KiB，瞬间 521.9KiB。500 与 600 两个核心包各约 109–110KiB。[fonts.mjs](../scripts/fonts.mjs) 收集全部 `src/` 用字，再按共享源码和文件出现频率分包；这不完全等同于各页面实际渲染的文字及字重需求。手机首页字体就绪中位时刻约 3.82s。

**建议：** 保留当前字体与 500/600 体系，核查核心包、正文包和标题包的实际命中字符；将样张、源码注释等需求与普通页面需求合理分离，同时显式保留动态文案和乱码字池。比较共享包与按页面补包的冷访、跨页复用成本。预载只针对时间线确认迟发现的关键小包。

**验收：** 对首页、目录、随笔、瞬间各记录字体请求清单；检查中文、标点、英文、双态文字及后续新文章是否缺字。字体体积下降后还需复测换字体时的 CLS，保持既定排版。

### 06 · 首次醒梦状态与段落淡入

**证据：** FancyText 手机 LCP 中位数 5.10s，命中梦态正文；CLS 为 0.0854。`reality.ts` 初始化时设置 `body[data-reality='dream']`，使静态醒态正文替换为更长的梦态正文。[global.css](../src/styles/global.css) 第 1196 行起还为新出现的双态块设置约 0.9s 的透明度/位移过渡。取消过渡后 LCP 中位数降为 4.30s，仍存在较大的初始化成本。

**建议：** 在首次绘制前统一确定会话状态及减少动态效果偏好，使初始 CSS 和后续脚本一致；首次显示正文直接采用稳定状态，用户主动换面继续保留过渡。结合字体与构块初始化进一步缩短内容出现时间。

**验收：** 首访梦态、已保存醒态、减少动态效果和无 JS 四种情况均需检查。对 LCP、CLS 同时设目标；原型有一次 CLS 0.1021，说明仅移除淡入还不充分。

### 07 · 文本动效与共享构块的渲染成本

**证据：** 真实随笔梦态静置中位数约 257ms/s；分别暂停文本动效组、隐藏构块后约为 91、117ms/s。样张页的主线程时间线以样式计算为主。`.float-ch`、`.ord-digit` 等关键帧引用 `--still`，需要兼顾稳定态与换面期；构块又增加了参与样式/合成处理的元素数量。

**建议：** 优先减少不必要的主线程帧和样式失效，研究稳定态与换面阶段的不同实现、屏外正文动效的活动范围。任何字面关键帧或调度调整都要保留连续换面与既有相位。移动端可评估更轻的装饰档位。

**验收与边界：** 同时测普通随笔、样张、醒态与梦态。三秒窗口有较大随机波动，应使用更长静置样本复核。现有记录已否定若干 `--still` 量化、`@property` 及构块出视口暂停方案；遵循[排版文档](design/content-typography.md)的既有结论。整体把构块改画进 WebGL 的方案继续作为高成本候选，先完成前面的集中改动。

### 08 · 开屏与正文可见时间

**证据：** [boot.ts](../src/scripts/boot.ts) 等待纹理、字体与稳定帧，设 1200ms 上限，然后再等 1450ms 开始揭幕、2350ms 移除面纱；定时器也可能被长任务延迟。首页 `boot="always"`，返首页仍重复开屏，文字还有独立入场时间。

**建议：** 给“主要正文可读”和“主要链接可操作”增加独立标记与预算。评估首次等待条件和返首页的开屏时长，避免把与主要内容无关的初始化串在前面。

**验收：** 用加载录像和应用标记核对实际感知；保留现有视觉主题。是否保留每次返首页的完整开屏属于体验取舍，需在实施时明确。

### 09 · 静态资源缓存

**证据：** 线上 HTML、带哈希 CSS、带哈希字体、晶苞帧均返回 `Cache-Control: max-age=600`，有 ETag。请求接受 `gzip, br` 时，HTML 与 CSS 实际返回 gzip。本轮未观测到 Brotli，不能据此概括所有节点的支持情况。

**建议：** 若复访成本明显，可通过可控 CDN/托管配置给内容寻址的资源较长不可变缓存，HTML 保留更新检查。晶苞当前固定文件名，应先加内容版本；`font.css` 也需考虑版本一致性。GitHub Pages 的任意响应头不能直接靠仓库内 `_headers` 文件配置。

**验收：** 区分新访、10 分钟内复访与超过缓存时长的复访，记录缓存复用、200/304 和发布后更新情况。现有 ETag 可能避免完整重传，收益应以实际复访瀑布图判定。

### 10 · 音频内存和首次启声

**证据：** 未开启时没有音频请求。开启醒态音频后取得当前 open 与两态 loop，解码得到的三个 AudioBuffer 共 **65.25 MiB PCM**。`sound.ts` 的 `buffers` Map 保留它们，关声主要是停源和 suspend。音频开关在本机实验中有数百毫秒交互延迟，最大记录 840ms；这是单会话 Event Timing，不能当作现场 INP。

**建议：** 短时关闭保留续播能力；较长关闭后可释放开场或其他不再需要的 PCM。围绕 `new AudioContext()`、`buildGraph()` 与首次界面反馈单独拆分时间线，再决定初始化调整。异步 MP3 解码不能直接认定为点击回调阻塞的来源。

**验收：** 在目标手机上测首次启声、短关重开、长关重开、站内续播和两态交叉；保留同相位、采样边界和等响要求。音频格式变更需遵循 [BGM 文档](design/bgm.md)。

### 11 · 大图格式选择

**证据：** 四张 Nexus 原 PNG 共 **171.2KiB**；[MomentLightbox.astro](../src/components/moments/MomentLightbox.astro) 第 21 行统一转成最长边 1800px 的 WebP 后共 **438.8KiB**，约为原文件的 **2.56 倍**。大图确实按需加载：打开第一张只新增该张大图请求。

**建议：** 对这类截图/线条图，在同尺寸和可接受清晰度下比较 PNG、WebP、AVIF，再选产物。保留大图的按需加载。网格缩略图现为固定 480px，手机实测显示约 169 CSS px，可增加合适的尺寸候选；单图已有响应式候选。

**验收：** 对比产物字节、文字/细线清晰度和点击大图后的加载时间。照片与截图分别选择编码方式。

### 12 · 专属代码与公共样式

**证据：** 全站实测 JS 含 Worker 约 30–41KiB gzip；`BaseLayout` 公共 CSS 约 17.7KiB gzip，体积已有较好基础。`overnight.ts` 仍经共享入口导入，进入非首页后才提前返回。

**建议：** 将首页专属逻辑移至首页入口；梳理只属于某页的样式。按构建后实际请求判断收益。当前构建未把 Three.js 整库发给浏览器，依赖清单大小不应作为首屏包体依据。

**验收：** 比较产物及各路线请求，确保拆分没有增加关键路径请求或改变初始化顺序。这项排在字体、图像和常驻渲染优化之后。

### 13 · 无 JS 时的不可用控件

**证据：** 五条抽查路线无 JS 时首屏正文可见、没有音频或晶苞帧请求；首页与随笔截图已查看。不过环境声按钮仍可见：首页还保留长按提示。`BaseLayout` 中 `[data-sound-toggle] { display:none }` 的优先级低于组件生成的 `.snd[...]` 显示规则，隐藏意图未生效。

**建议：** 完善无脚本选择器的优先级或使用 `scripting: none` 分支，隐藏无法工作的按钮与提示。继续保证正文、链接和纯 `:target` 大图可用。

**验收：** 真正禁用 JavaScript 后检查，不能用“脚本尚未加载”替代；对首页各幕和内容页分别核对。

## 4. 应保留的有效措施与低优先候选

- Astro 静态输出有效；正式基线 30 次导航没有网站运行时错误，当前构建通过。
- WOFF2 子集、`font-display: swap` 和本地字体已有基础；下一轮改善其分包与使用范围。
- 未开声时零音频请求，outro 未被运行时请求；不要把整份音频目录体积算进首屏。
- 减少动态效果的五条路线都进入醒态，记录到的运行中 CSS 动画为 0；首页只请求两张静帧。模拟省流量时晶苞也只请求两帧，其他效果仍运行。
- 首页与阅读页在未开声的后台标签页里，主线程任务约 0–2ms/s。Worker、可见性控制和已有暂停机制应保留。
- 地形已经使用 WebGL Worker、DPR 上限与降档；把几何继续搬入顶点着色器保留为后续候选。
- 瞬间目前只有 3 则、5 张配图，当前 DOM 规模有限；分页与列表虚拟化留给内容增长后的复测。
- 原待办中的“第二幕首次滤镜光栅化偶发卡顿”仍可保留。本轮没有独立确认其复现频率；修改 blur、增加 `will-change` 或提层前，需要针对该场景的时间线与像素对照。

## 5. 实施顺序与验收预算

1. **集中改动：** 环境声指示动画、关于页首次布局模式；随后处理大图格式和无 JS 控件。
2. **首页持续成本：** 晶苞目标帧率调度、首帧显示、分批预取和合适尺寸解码。
3. **首访内容路径：** 字体分包、首次醒梦状态、段落初始化与开屏时序；联合复测 LCP 和 CLS。
4. **后续整理：** 根据新基线决定文本动效/构块的进一步改造、音频内存策略、缓存托管和小幅代码拆分。

建议在实施前固定以下预算。运行时与资源预算是项目建议值，需结合视觉验收调整；Core Web Vitals 的正式判断采用真实用户 p75。

| 项目 | 建议验收目标 |
| --- | --- |
| Core Web Vitals | 真实用户 p75：LCP ≤2.5s、INP ≤200ms、CLS ≤0.1；本地同条件也观察这些值 |
| 关于页 | 消除本次初始化导致的约 0.60 CLS；三次冷访均 ≤0.1 |
| 环境声指示 | 稳定播放相对静音的主线程常驻增量 ≤20ms/s（相同手机模拟条件） |
| 首页静置 | CPU ×4、资源已就绪时，争取中位任务占用 ≤200ms/s；同时保留既有动画节奏 |
| 晶苞加载 | 首帧独立可显示；未操作、离开首屏时不自动取得所有无关序列；记录请求数量与字节 |
| 字体 | 按路由设上限并较当前明显减重；以无缺字、500/600 字重与排版一致为前提 |
| 音频 | 未开启仍为零请求；长期关声后的 PCM 有明确释放策略，短时续播与相位正确 |
| 静态与降级 | 无 JS 正文可读；减少动态效果保持静帧；图像尺寸固定、链接正常 |

每批按相同条件做三次导航，报告中位数与范围；运行时增加足够长的静置窗口，避免入场及随机文字扰动主导结果。样式改动按项目要求执行 `npm run build`，并使用样式预览及对应截图流程。

后续可用 `web-vitals` 建立按路线、设备和版本区分的真实用户基线。GitHub Pages 本身不提供 `/rum` 接收服务，需明确接收端后再实施。真机 Android/iOS、暖缓存跨页导航、长时间内存与耗电仍需独立验证。
