# c-halftone · 半调网点（14° 网线）

slug：`c-halftone`
成品：`favicon.svg`（发货那一份）· `favicon-dream.svg`（梦面）
标记名：**「十四度网点」** / screen 14

---

## 1. 风格一句话

**这枚标记是一张斜 14° 的半调网屏；网线本身成象，象的是主页左上那团冷光。**

制版时半调网屏必须定一个 screen angle（15° / 45° / 75°，为了避开摩尔纹）。
这里取 **14°** —— 就是全站那根发丝线的角度。于是标记圆边上一级一级的台阶，
和主页那根台阶状斜线是**同一个成因**：不是画了一根斜线，是斜排的网点在圆的边界上被裁出来的齿。

## 2. 形从哪来

对着 `_ref/home-1440.png` 看，主页整片背景铺着一层极细的网点（夜里像纸也像屏）。
这枚标记做的事只有一件：**把那张网放大到能看清一粒一粒**，然后让它去成象。

- **象 = 左上那团冷光。** 亮度从 `(12.3, 12.1)`（偏左上）向外衰减，点的半径跟着衰减 ——
  于是左上角最大、右下角最小，整枚标记自带一个方向：光从左上进来，往右下化开。
- **形状 = 一个圆盘。** 哪些格有点由圆盘决定，圆盘边缘按格子抖一点，所以边界是齿不是圆弧。
- **网线 = 14°。** 整张方形网线绕圆心转 14°，点不再轴对齐。
- **台阶。** 14° 的网线被圆界裁掉，边界自然出现"横 4 竖 1"的台阶 —— 和主页那根发丝线同源，
  也和右下角 NEXUS 那套 Silkscreen 像素字是远亲。

颜色分工照 tokens：醒面 ink `#232830` 印在昼面 `#f0f3f6` 上；梦面 ink `#e2e9f2` 浮在靛夜 `#0c0f18` 上；
薄暮紫 `#9a86c4`（`--amber`）只在梦面出现。

## 3. 两套网线（这是 16px 的解）

网点成像有个物理矛盾：**要灰阶就得点多，点多了 16px 就糊。** 所以不硬扛，换线数。

| | 网距（viewBox 单位） | 16px 下的网距 | 点直径 | 点数 | 用在哪 |
|---|---|---|---|---|---|
| **粗**（发货） | 4.0 | 2.0px | 1.0–1.7px | 25 | 16 / 24 / 32 / 48px |
| **细**（大尺寸） | 1.78 | —（糊） | 0.5–1.6px | 132 | ≥96px、OG、apple-touch |

关键是**形状靠「点还在不在」定，不靠「点多小」定**：
圆盘边界上，点在就是点、不在就没有，不存在"缩到 0.2px 看不清"的中间态。
外缘因此不糊，只是齿变得粗一点 —— 而这恰好就是粗网线该有的样子。

还有一条硬约束写在生成器里：**任何点的半径 ≤ 0.44 × 网距**。
真半调在暗端会让网点互相吃掉（那才是 100% 网点），但标签页图标要每一粒都数得清，所以禁止相碰。

`detail-16px.png` 是 16px 那格放大 16 倍的原样：25 粒点全部可辨，不是一块灰。

## 4. 醒 / 梦差在哪

**同一组点（同一批 i, j），一枚都没多、一枚都没少。** 差的是四件事：

| | 醒 | 梦 |
|---|---|---|
| 格 | 严格在 14° 网线上 | 每点离格 ±0.45（粗）/ ±0.2（细） |
| 大小 | 只有 3 / 6 档整数半径（印刷灰阶） | 每点再叠 ±10% 的呼吸 |
| 外缘 | 实心 | 外缘的点**变淡**（opacity → 0.34），化进夜里 |
| 紫 | 无 | 光源那一枚 + 环带最远的一枚偏成薄暮紫 |

注意梦面**不删点**。删了就成另一枚图标了。它只是离格、变淡、上浮 ——
"疏密关系松开"是这个方向要的，而"点还在"是"同一枚图标"这个要求要的。

`index.html` 第 02 节有一根 `--reality-mix` 滑杆，醒梦两层叠着交叉淡入淡出，拖着看它化开。

## 5. 16px 与单色下退化成什么

**16px（粗网线）**：25 粒直径 1.0–1.7px 的点，间隔 0.3–1.0px。
点全在，但圆盘的边只剩十来粒点，于是轮廓从"圆"退成"带齿的圆团"。
左上角那一枚**方点**是全图唯一一枚方点，周围还退让出一圈空 —— 它是 16px 下唯一可辨的锚。
再小（<12px）会开始粘连，那时该换一枚更简单的标记，不是继续缩这枚。

**单色（`currentColor`）**：灰阶层次整个丢掉，只剩「点的大小差」与「点在不在」；
梦面的「紫」也退成「在格 / 离格 + 外缘浓淡」。光源那一枚仍然最大，所以还认得出来。
薄暮紫 `#9a86c4` 单色走：深底上最稳，浅底上偏淡（约 2.3:1），看得见但确实软。

## 6. 小巧思

**一枚方点。**

光源那一枚是**方的**，其余 24 粒都是圆的。这不是装饰 ——
真半调网屏在**极高光端**，网点本来就退化成一小块方/菱形（那是网屏的"高光点"形状）。
所以这一枚方点同时是三件事：

1. 印刷上的诚实（高光点的真实形状）；
2. 全站唯一的「像素」—— 和右下角 NEXUS 那套 Silkscreen 字同族，
   而它偏偏长在"网线斜 14°"的那张网上，**网是斜的，这一点光是正的**；
3. 16px 下唯一可辨的锚（方点比同面积的圆点抗锯齿得多，2px 的方块仍然是方块）。

周围四点退让到 55%，于是那一点亮周围是空的 —— 光有自己的余地。

第二个小东西：梦面里除了光源那一点，环带最远处还有**一枚**偏紫的点。
两点一近一远，像是"记忆留在边缘上"。

## 7. 真要做两态，怎么落地

标签页图标的两态只能靠 JS 换 `<link rel="icon">`。建议：

```html
<!-- 粗网线那份当 16/32 的图标；细网线那份（本目录没出，由 gen.mjs 的 RULING.fine 直接生成）
     留给书签栏大图标 / OG / apple-touch -->
<link rel="icon" href="/favicon.svg" sizes="any" type="image/svg+xml">
<link rel="icon" href="/favicon.svg" sizes="16x16" type="image/svg+xml">
<link rel="icon" href="/favicon.svg" sizes="32x32" type="image/svg+xml">
<link rel="icon" href="/favicon-dream.svg" media="(prefers-color-scheme: dark)">
```

换态时机照站点现有的 `--reality-mix`：`reality.ts` 每帧覆写它，
但**不要每帧换 icon**（浏览器会反复重解析）。做法是给 `reality.ts` 挂一个跨越 0.5 的**滞回阈值**
（例如 >0.62 换醒面、<0.38 换梦面），只在跨过阈值那一下换一次 `href`。
另外注意：**16px 下醒梦两态几乎看不出差别**（jitter 只有 0.225px，是亚像素）。
两态真正起作用的是书签栏 32px 以上、OG 图与 apple-touch。

## 8. 风险 / 我不确定的地方

1. **16px 的轮廓是"带齿的圆团"，不是干净的圆。** 这是粗网线 + 25 粒点的必然结果。
   我认为这正是"被印刷出来的"该有的样子，但它确实不如一枚实心字形图标"脆"。
   如果验收要的是"一眼一个形状"，这个方向可能要往"更少、更大的点"再走一步（比如 13 粒）。
2. **细网线在 24–32px 会起摩尔纹**（`detail-sizes.png` 里的"32 细 / 24 细"）。
   真半调本来就会起摩尔纹，所以它算"对"，但它看起来也可能像渲染坏了。
   发货只发粗网线那一份，就是为了绕开这个。
3. **方点是我最不确定的一处。** 我判断它读起来是"刻意的"，但存在被读成"画错了"的可能。
   若要更保险，把 `RULING.*.sq` 改成 0 附近、并去掉退让（`r *= 0.55` 那行），就退回一枚纯圆的半调球 ——
   代价是 16px 少一个锚。
4. **`favicon.svg` 用 `currentColor`**，按简报要求"可退成 currentColor"。
   但独立打开的 SVG favicon 里 `currentColor` 落到初值（黑），深色标签栏上会消失。
   要一份直接能用的，把 `fill="currentColor"` 换成固定 ink；或用第 7 节的 `prefers-color-scheme` 双份。
5. **光源位置**取 `(12.3, 12.1)`，是我对着主页截图估的（冷光在左上角而非正中）。
   主页那团光更靠角落、更散，我没敢把光源推到那么偏 —— 太偏会让圆盘的重心歪掉，标签栏里不好看。

## 10. 实际跑过的截图命令

```bash
# 主图（简报指定的那一支）
node design/mocks/favicon/.shot.cjs \
  design/mocks/favicon/batch-01/c-halftone/index.html \
  design/mocks/favicon/batch-01/c-halftone/shots/sheet.png 1200 1500 --full

# 生成（改完 gen.mjs 先跑这个）
node design/mocks/favicon/batch-01/c-halftone/gen.mjs
```

输出：`1200×4249 @2x`，无横向溢出，无页面报错。

`detail-*.png` 是把同一页的某个区块按 3–16 倍放大截的（用了一支一次性的 clip 变体，
和 `.shot.cjs` 同一个 Chrome 口径，用完删了，没留在交付目录里）。
