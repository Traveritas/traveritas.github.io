# 光标（Cursor）· 调研与方案简报

> 承接 `cursor-notes.md` 的两条否决：**测量 / 探针类具象隐喻**、**材质堆叠**（渐变、光晕、次表面、折光）。
> 四份既有 mock 的材质路线不在本简报的候选范围内。

## 0 · 命题

形状组成简约、平面；精美之处由**动画与机制**承担。
站级既有原则（p15 brief）：**两态差不再靠「有 / 无」，而靠「同一个东西被两种方式读出」**。
光标必须服从同一条——不是两个光标，是同一个光标的两个面。

## 1 · 调研摘要

### 1.1 工业实现（被大量真实用户长期使用的一手源码）

- **tldraw**：自己的光标**就是原生 CSS cursor**（`--tl-cursor` 变量 + data-URI SVG），因此架构上不存在滞后问题；他人光标**刻意不做插值**，直接把坐标写进 `transform`。闲置阈值在 `packages/editor/src/lib/options.ts`：`collaboratorIdleTimeoutMs: 3000`、`collaboratorInactiveTimeoutMs: 60000`、`collaboratorCheckIntervalMs: 1200`；边界修补：`lastActivityTimestamp === 0` 视为「刚活动」，防止新加入者一进来就被判闲置。
- **Excalidraw**：光标广播节流 `CURSOR_SYNC_TIMEOUT = 33`（约 30fps）；`IDLE_THRESHOLD 60000` / `ACTIVE_THRESHOLD 3000`；其激光笔平滑参数 `streamline: 0.45`（即每点向新点插值 ≈0.55）、`simplify: 0.1`、`maxTailLength: 50`。
- **Liveblocks 官方高级示例**：Framer Motion 弹簧 `bounce .6 / damping 30 / mass .8 / stiffness 350 / restSpeed .01`——但**把落点也弹簧化了**。按本简报的红线，这是**反例**。
- **VS Code / Monaco**：平滑插入符就是一句 CSS `transition: all 80ms`；关键在 `pauseAnimation` ——**只在显式跳转（`CursorChangeReason.Explicit`）时播放，打字不播**。闪烁间隔 500ms，移动后 500ms 内禁止闪烁。
- **Figma**：**未找到任何公开的实现资料**（其多人协作工程长文全文出现 "cursor" 0 次）。关于它的跟随平滑与闲置隐藏的全部说法均为传闻，本简报不引用。
- **游戏 / 触控**：Gaffer On Games 的「本地玩家用预测即时响应、远端实体用插值必然滞后」，是「**命中点零延迟、装饰滞后**」这条做法的工业原型。

### 1.2 网页案例（只取机制可迁移者）

- **Codrops《Custom Cursor Effects》(2019)**：实心小点 + 画布圆双体，圆以 `0.2` 线性插值追赶；Demo4 的磁性圆会吸附导航项。可迁移的是「**吸附把 hover 从颜色反馈变成位置反馈**」。
- **Cuberto mouse-follower**（开源）：`data-cursor-text / -icon / -img / -video / -stick / -inverse / -hidden` 的**属性驱动状态机**——状态与表现解耦，一处逻辑全局复用；位移按 `speed 0.55` 插值。硬依赖 GSAP。
- **Thenest**：点 + 环，环滞后于点，**环的缩放编码可点性**。
- **Morten Stig Christensen**：指针静止后光标进入 idling 待机微动——把「无人操作」也读成时间感。
- **未核实（勿引用）**：Aristide Benoist / Active Theory / Resn / Locomotive 现站取不到光标代码；Studio Freight 现站用原生 `cursor: pointer`；Bruno Simon 站内是 3D 射线拾取 + 原生指针。

### 1.3 跟随动力学与参数（工程口径）

- **指数平滑（推荐）**：`p += (t − p) · (1 − e^(−dt/tau))`，`tau = 1/speed`，`speed` 常用 **5..50**（`1/speed` = 衰减到 1/e 的秒数）。固定系数的 lerp（如 Codrops 的 `a = 0.2/帧`）在 120Hz 上收敛快一倍；`a·dt` 是错法（系数会越界）。
- **弹簧现成值**：motion 默认 `damping 10 / mass 1 / stiffness 1`、`restSpeed 0.1`、`restDelta 0.01`；react-spring `tension 170 / friction 26`；预设 `gentle 120/14`、`wobbly 180/12`、`stiff 210/20`。
- **速度→形变**（Cuberto 源码）：`d = hypot(vx,vy)`；`scale = min(d*0.001, 0.15)`；`scaleX = 1+scale`、`scaleY = 1−scale`；朝向由 `atan2` 给角度。**delta 与上限必须 clamp**，否则高速下形变失控。
- **指针取样**：`pointerrawupdate` = Chrome 77+ / Firefox 148+ / **Safari 无** → 只能做增强，`pointermove` 兜底；`getCoalescedEvents()` 取回中间点（利好绘制）；`getPredictedEvents()`（Baseline 2024-12）可按速度外推**补偿滞后**。
- **必须 clamp `dt ≤ 1/30s`**：后台标签恢复时 `dt` 巨大，固定系数会瞬移。
- **`will-change` 按需加、静息移除**（Cuberto 在速度归零时设回 `auto`）；拖尾要**节点池**，禁止每帧分配对象。
- **禁止**：逐帧 `elementFromPoint` / `getBoundingClientRect` / `getComputedStyle`（强制同步布局，Paul Irish 清单明确列出）。

### 1.4 无障碍（本简报最重的约束）

- **WCAG 2.2 没有任何条款直接管指针外观**。w3c/wcag 议题 #3161 中，Patrick Lauke 对「是否有 SC 管光标/指针的用户设置」回答 "no, and no"，Alastair Campbell 标记 `wcag.next`。**这是标准缺口，不等于合规**。
- 但两条 SC 间接咬住它：**SC 1.4.11** 理解文档写明「指针位置是 hover 状态的首要指示」，并把「自定义 caret/cursor 作为唯一焦点指示」列为**失败示例**（Fig.32）；**SC 1.4.13 Dismissible** 说明屏幕放大器用户靠移动指针平移视图，跟随指针的元素会遮挡正文，且必须能**不移动指针**就关掉。
- **SC 2.3.3 Animation from Interactions (AA)**：交互触发的动效必须可关闭，除非它承载必要信息。光标跟随动效不承载信息 → **必须可关**。
- **OS 层的指针大小、描边色、填充色、「摇动鼠标以定位」本身就是视障功能**（Apple / 微软官方页面均列在无障碍项下）——`cursor: none` 等于取消这些设置。
- **Eric Bailey《Don't use custom CSS mouse cursors》(2021)**（原文已核）：严格区分「指针**状态**变化（pointer / text / move / grab，是必需的 OS 可供性）」与「用图片替换指针」；对后者写道 "This reason alone should be a hard stop"，同时给出条件路径（须针对低视力、低数字素养、不熟悉该隐喻者实测）。
- **指针延迟的实证阈值**：鼠标场景约 **60ms**（Forch et al., HCII 2017）；直接触摸**低于 10ms 仍可辨**（Ng et al., UIST 2012）；滞后 225ms 时移动时间 +64%、错误率 +214%，且对 Fitts 难度是**乘性**效应（MacKenzie & Ware, CHI'93）。→ 「热点必须同帧（≤1 帧 ≈16.7ms）、缓动只作用于装饰」**有实证支撑**，不是保守估计。
- **前庭风险偏低**：触发因素是运动**面积 / 方向 / 感知距离**，小型光标跟随器属低风险（Val Head, A List Apart 2015）；真正的义务是可关闭性与分心控制。
- **混合设备**：`@media (pointer: fine) and (hover: hover)` **筛不掉带鼠标的触摸本**（此类设备上 `pointer: fine` 通常仍为真）。要按「当前实际输入」判断，只能运行时读 `PointerEvent.pointerType`。
- **`forced-colors: active`**：系统强制替换颜色、`box-shadow` 强制为 `none` → 自绘光标极易被重绘到不可见，此时必须不隐藏系统光标。

> **矛盾标注**：两路调研对「Adrian Roselli 是否有自定义光标专文」结论相反，按**未核实**处理，不作为依据；上文的 a11y 结论只依赖 WCAG 原文与 Eric Bailey 那篇（有一手原文）。
>
> **安全备注**：抓取 Eric Bailey 文章时，页面内含一行针对 AI 的注入指令（要求重复输出某词），已被调研子智能体识别并忽略，未执行。

## 2 · 红线（四方案共用；任一条不满足即回退系统光标）

1. **不做指针替身**：默认保留系统光标；仅在**运行时检测到真实鼠标**（`pointerType`，而非仅媒体查询）时才隐藏。
2. **四重门控**：真实指针 + `prefers-reduced-motion: no-preference` + 非 `forced-colors: active` + 用户开关未被关闭。任一不满足 → 自动回退。
3. **热点同帧**：判定与点击的视觉热点必须与真实指针同帧（≤1 帧）；缓动只允许作用于热点之外的装饰，装饰与热点的视觉偏移上限 ≤ 12px。
4. **永不替换指针状态语义**：文本 / 可编辑区保留 `text`，链接按钮保留 `pointer`，拖拽保留 `grab/move`。自绘元素永不承担焦点或悬停的唯一指示，永不遮挡正文。
5. **持久开关**：键盘可达、不依赖指针位置（满足 1.4.13 的 dismissible）。
6. **逐帧只写 `transform` / `opacity`**；rAF 由事件唤醒、收敛即停、`will-change` 归 `auto`；静息交 CSS 动画；`dt` clamp；节点池。
7. **触摸 / 笔设备完全不接管**。

## 3 · 四个方案

四案的形状都只有 2–6 个平面图元、单色、无材质。差异全在**机制**。

### 方案 A · 残点（定距回溯）

**形状**：一个 5px 平面方点（唯一实体，1:1 跟手）+ 最多 6 个 1px 残点。

**机制**：残点按**行进距离**落点（每走 7px 落一枚），不按时间。间距恒定，于是流密度随速度自然变化；每枚残点的寿命也由距离给定（再走 N px 即淡出）。慢速＝稀疏的长寿点，快速＝密集流星。静止时零残点、零 rAF。这与站点既有母题「构块场：拼接 × **定距回溯** × 原地浮动」同源。

**两态**：醒 = 残点沿 **0°** 轴排布、间距 7px、快速淡出（锐）；梦 = 同一组残点沿 **14°** 轴排布（与站点缝线同角）、间距 9px、每枚原地缓慢浮动（消费 `--still`）。**同一个刻度场，两种读法**——与 p14-a 的「0°/36px vs 14°/57px」同构。

**状态**：悬停可点元素 → 落点间隔在接近目标时**收紧**（点变密），落到目标上只剩本体；点按 → 间隔反向抽一次（一枚残点向前越位再被吸回，呼应 RealityGuide 的微抽演示）；长按 → 残点逐个回流进本体，本体在成结瞬间就是 `reality.ts` 的那颗 ◆。

**风险**：正文上会形成噪声，须在文本区禁用；残点数量与寿命必须硬上限，否则高速时元素数暴涨。

### 方案 B · 四点环比（缺口即机制）

**形状**：4 段 1px 短弧（各约 7px 弧长、圆角端点）拼成一个 11px 环，无填充、单色。**不含任何正交穿过中心的线**——这是与「准星」拉开距离的硬规定。

**机制**：**缺口是主角**。四段之间的四个缺口宽度随速度开合，且缺口图样整体以与速度成正比的角速度缓慢**进动**（precession）。静止时缺口合拢成一只完整细环，进入 CSS 呼吸（rAF 停）。

**两态**：醒 = 四段落在 0° / 90°（正对屏幕轴）、缺口等宽、进动停止；梦 = 四段整体偏移到 14°、缺口不等宽（每段弧长各自抖动）、进动常在。醒是「对齐的环」，梦是「没对齐、仍在慢慢转的环」。

**状态**：悬停可点元素 → 环展开成四角标（呼应 RealityGuide 的 `⌜ ⌟` 语言，语义是「圆变角」而非仪器读数）；点按 → 环收缩 1px 再回弹；长按 → 环张开成线架口，成结落在环心。

**风险**：环是站点头号母题，但也是「靶心」的近亲，已被否决的仪器感就在旁边；四段进动是每帧四次 transform，成本比 A / C / D 高。

### 方案 C · 悬丝（−4° 单笔画）

**形状**：一根 1px × 9px 的短线 + 其下端一个 2px 实心点（热点，1:1）。总共**两个元素**。

**机制**：线是**钟摆**。点在真实位置充当锚，线自点悬垂，角度由弹簧驱动：反向移动时角度滞后并过冲一次，手停后回落到 **−4°**——正是站点自己的角度（`reality.ts` 的抽线、`RealityGuide` 的演示线都是 −4°）。

> **勘误（2026-09-24，C 稿实现时发现）**：本节初稿写「速度越快线被吹得越趋向运动方向」，物理方向错了——
> 悬垂线的自由端在锚点移动时是**拖后**的（右移时线尾拖向左）。C 稿按正确物理实现（拖后 + 过冲），
> 方向符号可一键翻转；以「拖后」为准。

**两态**：醒 = 阻尼高，线几乎不摆、绷直锁在 −4°；梦 = 阻尼低，线随移动自由摆荡后才慢慢落回 −4°，末端有一点延迟的「飘」（消费 `--still`）。**同一根线：醒是绷直的一笔，梦是会摆的一笔。**

**状态**：这是四案里状态覆盖最优雅的一个——**所有状态都只是这根线的角度与长度**。文本上：线**立起来**成竖直 1px 插入符（天然的 text 语汇；Monaco 已证明插入符类动效只需 80ms transition）；链接上：线**躺平**成水平短划；点按：线快速左右各颤一下；长按：**线被抽走、延长成贯穿全屏的那根线**（它本来就是 −4°，与 `reality.ts:217` 的 `drawThread` 同角同锚点），成结 ◆ 落在原点。

**风险**：单根 9px 线的存在感偏弱，需靠端点对比度补足；摆动必须在 RM 下关闭（降级为静止 −4° 直线）。

### 方案 D · 错位双影（醒＝对齐，梦＝差一点点）

**形状**：两个**完全相同**的平面图元（两枚 3px 方点，或两根 1px 短划），静止时严格重合——所以看上去仍然只有一个极简图形。

**机制**：副本沿滞后的残余量偏移，**偏移量即其透明度**：移动时浮出淡淡双影，静止时归零、重合、双影消失。于是「**对齐**」本身成了一个可读的状态量。

**两态**：醒 = 双影始终精确重合（偏移恒为 0）；梦 = 双影沿 14° 保持 1–2px 错位并缓慢呼吸，**永不重合**。「醒是对齐的，梦是永远差一点点没对齐。」这是一条 thesis 级机制，不是装饰。

**状态**：点按 → 两影碰撞一次后归位；长按 → 两影相向分开、在闩锁那一拍合一（**光标自己把状态切换演了一遍**）。

**风险**：成本最低（两个元素、纯 transform/opacity），但机制含量也最低，单用会显得单薄；最适合作方案 C 的**梦态表达**（同一根线在梦态分裂成两笔）。

## 4 · 推荐

- **首选：方案 C，并把 D 作为它的梦态表达。** 形状最简（两个元素）、机制最贵（钟摆 + 与站点 −4° 抽线同角）、状态覆盖最优雅（全部由一根线的角度与长度完成），并且它把站点最核心的手势（长按抽线）与光标连成一体——**光标是那根线的种子，长按是把种子抽成整屏**。醒态绷直、梦态摆动、梦态可分裂成双影，正好落在「同一个东西被两种方式读出」上。
- **次选：方案 A。** 机制最独创（按距离而非时间参数化的残影），与构块场的定距回溯同源；代价是正文噪声与元素数管理。
- **方案 B** 的缺口开合与进动在四案里视觉最讨喜，但「环 / 靶心」与已否决的仪器感只隔一层，若采用必须守住「缺口常开、无形心线」。
- **明确不做：`mix-blend-mode: difference` 的反色光标。** 它看似最贴「同一个光标把页面重读一遍」，但站点上有三片 `backdrop-filter: blur(13px)` 玻璃，且两周前刚平息整视口重绘问题（见 `docs/backlog.md` 附四）：每帧重混一个叠在玻璃上的移动元素会迫使该区域重新取样，正是那一轮被消除的成本；`forced-colors` 下也不可控。

## 5 · 本轮 mock 的交付口径（四稿共用）

**共用外壳**：`design/mocks/cursor-shell.html`。四稿一律
`cp design/mocks/cursor-shell.html design/mocks/cursor-<X>-<slug>.html`，
然后**只填夹在 `CURSOR SLOT` 注释里的那一段**（`#cursor-slot` + `<style id="cursor-css">` + 一个 `<script>`）。

外壳里已就位、**不要动**：tokens、三段夜色（`?zone=`）、层序、双态引擎（长按 2200/1300ms、Shift+Space、
逐帧写 `--reality-mix`、ACCENT 插值、`--still`）、品牌字标、14° 缝线与琥珀锚点、脑电线、真实文案、
右下角调试角标、**四重门控与降级**、自检面板、`window.__cur` 句柄、
状态试验区（链接 / 正文段落 / `<input>` / `<textarea>` / 可拖元素 / 空白长按区）。

**查询参数**（四稿一致）：`?zone=light|deep|paper`、`?mix=0..1`、`?freeze=1`、`?ui=0`、
`?cursor=off`、`?reduced=1`、`?probe=1`、`?state=<name>`。

**光标层的唯一合法输入**：CSS 变量 `--reality-mix`（1 醒 → 0 梦）、`--still`、
`--amber / --dream / --umber / --ghost-ink / --wash`、`--bg / --fg / --fg-soft / --line`，
以及 `body[data-reality]` 与 `body.reality-holding` 两个类。

**rAF 纪律**：由指针事件唤醒、收敛即停；**静息 5s 内必须为 0 次**；收敛时 `will-change` 归 `auto`；
`dt` clamp ≤ 1/30s；拖尾类用节点池，零每帧分配。

### 红线（光标专用）

1. 逐帧只写 `transform` / `opacity`（禁逐帧改颜色、宽高、圆角、`filter`、`box-shadow`、`background`）。
2. **零材质**：不用 gradient、glow、`box-shadow`、`filter`、blur、次表面、折光——单色 + 透明度，
   形状只有平面图元。
3. **零仪器隐喻**（见 `cursor-notes.md`）：不得出现十字准星、穿过形心的正交线、探针、示波、
   透镜、读数刻度；文案里也不许出现「测量 / 读数 / 校准 / 增益」。
4. 禁用 `mix-blend-mode`；禁用外部库（GSAP / Framer Motion / Paper.js 一律不许）。
5. 禁逐帧 `elementFromPoint` / `getBoundingClientRect` / `getComputedStyle`；
   状态检测用 `pointerover` / `pointerout` 事件委托 + `closest`。
6. **热点同帧**：判定与点击的视觉热点与真实指针偏差 ≤ 1 帧；**跟随类装饰**（会被读成「指针在哪」的滞后体）
   与热点的偏移 ≤ 12px（自检面板给读数）。
   > **口径补充（A 稿提出冲突后裁定，2026-09-24）**：≤12px 约束的是「可能被误读为指针位置」的滞后装饰，
   > **不约束按历史采样铺出的轨迹**（残点 / 拖尾）——轨迹是已经走过的路，不与指针位置竞争。
   > 对轨迹类只要求：最靠近本体的那一枚 ≤ 12px，且整条随距离淡出。C 稿长按照自身轴向把发丝抽到 22px，
   > 属机制本身要求的「延长」，同样不在此约束内。
   > 原表述未区分这两类，使 A 稿的 6×7px 间距设计在字面上「超红线」（实测整排 28px、梦 45px）。以本补充为准。
7. 四重门控由**外壳**负责——你的层不得自己写 `cursor: none`，也不得在门控未开时显示。
8. RM 下不得有跟随动画（降级为 1:1 静态形态）；触摸 / 笔设备不接管。
9. **不抢字**：光标在正文上不得降低正文可读性（文本态必须让出字面）。
10. 只动 `design/mocks/`；不碰 `src/`；不提交 git；不改依赖。

### 静止帧必须可辨

两张 `?freeze=1` 截图（醒 `?mix=1` / 梦 `?mix=0`）必须**一眼不同**。两态差若只在「动 / 不动」
上成立就是无效的——站级原则是「同一个东西被两种方式读出」。

## 6 · 验证方法（沿用站点既有做法）

- 在 `design/mocks/` 出**自包含 HTML**（沿用 p13–p18 的 mock 惯例），配 `.shot-*.cjs` 截图脚本做 A/B：静息 / 移动 / 悬停链接 / 悬停正文 / 点按 / 长按全程 / 两态，逐帧截图。
- **参数自检**（口径沿用 p15 笔记「新增 rAF／监听 = 0」）：记录 rAF 调用点数、静息 5s 内的 rAF 次数（应为 **0**）、元素数与 `will-change` 是否归 `auto`。
- **延迟自检**：把热点元素与真实指针坐标在同一帧内采样比对，确认偏差 ≤ 1 帧；装饰层的最大偏移量实测 ≤ 12px。
- **无障碍门槛**（发布前必须过，此项为内部审查既有欠账）：200% 缩放、Windows 强制颜色模式、真实屏幕阅读器（NVDA/VoiceOver）、触摸与笔混合设备，四项不过则不得上线隐藏光标逻辑。
