## 一、接了哪些真东西

**背景。** `WanderIndex scene="essay"` 原样挂在页面上：流光、三栏栏头、导航、左下星、Ave
都还是它们自己。只做了一件事——用页面里的内联脚本把它的 canvas 卡片层
（`#w-stage`）`visibility: hidden`，没有改 `wander.js`，也没动 `WanderIndex.astro`。
键盘手势挡了一层：V / 1 2 3 / 方向键 / ± 这些会把那片空间切走、或把方向键从页面滚动里抢走的键，
在 `window` 捕获阶段 `stopPropagation`，不往 wander 递。

**内容。** 三栏全部来自 `getCollection`，只取非 draft，按日期倒序（与片空间同一套排序）：

| 栏 | 卡片上有什么 | 来自 |
| --- | --- | --- |
| 随笔 | 日期 · 字数 / 标题 / 简介 / 标签 | `articles` + `countChars(body)` |
| 瞬间 | 日期 · 张数 / 图 / 标题 / 标签 | `moments`，图走 `getImage` 的 720 webp |
| 项目 | 日期 · status / 标题 / 简介 / links 的 label | `projects` |

面板里：随笔 / 项目去取它自己那一页的 `article.prose .md`（和片空间的 `reader.js` 同一处取材），
套同一套 `.prose--essay / --project` 排版变体；瞬间用它构建期渲染好的 `html`。
「在单独的一页里读 ↗」是真的链接。

**位置。** 一处坐标也没写死：

1. 读三个 `[data-w-head]` 的 `getBoundingClientRect()`。栏头的左沿就是那一栏**在这一高度上**的左沿
   （wander 的 `colX` 把栏头摆在栏的左边界上），栏头的底就是这一栏开始的地方；
2. 三栏是顺着 `--seam-angle`（站上那条 14°，`tokens.css` 的令牌）斜下去的，每张卡的左沿按它自己的
   锚点往里退——**随笔贴底边、瞬间贴中线、项目贴顶边**。这不是新发明的规则，是片空间自己的做法
   （`wander.js` 的 `colX` 对三栏各用不同的参照高度），照抄了它，卡片才不会越过亮暗那条缝；
3. 栏宽读片空间里同一栏那几扇窗此刻的实宽（`offsetWidth × transform 里的缩放`，取缩放中位），
   读不到才退回按视口推的一档；
4. 每一栏摆几条也由量出来的空间决定（`floor((底 - 首行高) / (卡高 + 行距))`）。

1440×900 上量到的是：栏头 226.5 / 674 / 1052.9（y=72），三栏宽 362 / 294 / 380，每栏两行。

**展开 / 收起 / 焦点。**

- 点卡片先 60ms **定影**（甲把 `--d-s0/--d-s1` 推到 1、字退；乙把值偏移收拢成 fix 那一组）；
- 然后：甲用 WAAPI 把面板的 `left/top/width/height` 从卡片矩形长到目标矩形（720ms，
  `cubic-bezier(.34,.06,.2,1)`），飞行中墨反号、坡回到上浓下淡，字在 600ms 浮上来；
  乙先把面板按卡片那一刻的矩形与那一组面色画一帧，再撤掉内联值，交给 CSS 过渡
  （宽高 .64s / 左沿 .66s，面色延迟 200ms 用 240ms 翻）；
- 收起用的是**当场量的**那张卡的矩形（不是打开时缓存的），甲 360ms 落回、乙 380ms 交回卡片；
- `Esc`、`—`、点面板外都能收；收起后焦点回卡（鼠标开的加 `.quiet`，不画焦点环）；
- 打开时卡片层 `inert`，Tab 只在面板自己的可停项之间转；`aria-expanded` / `role="dialog"` /
  `aria-modal` 都接上了。

**窄屏。** 三个栏头不在一行上（片空间切成了竖排）时走另一条路：整页正常流、上下滚，
栏头用 `translate`（独立属性，不动 wander 写的 `transform`）挪到各自那一栏的顶上，
滚动时整层跟着走。

## 二、哪些地方还是假的 / 不稳

1. **位置是「读栏头 + 外推」，不是那片空间真的布局。** 一切成立的前提是栏头落在栏的左沿、三栏沿 14°。
   wander 一旦改栏头的摆法或改角度，这里会跟着错；栏宽也是从「窗的实宽」旁敲出来的，
   而那扇窗在悬停时会被呼吸放大 5%——量到的时刻不同，宽度会差几个像素，这里没跟着呼吸。
2. **宽屏每栏只摆放得下的那几条**（1440×900 是 2 条，1600×1000 是 3 条）。多出来的条目是
   `hidden`，没有入口——不像真页面那样每栏自己滚。
3. **阅读面板的几何是另一个矩形。** 原型是 620,112 起的 720×670，这里是「瞬间那一栏的左沿 + 26
   往右铺到边距」（1440 上是 690,112 起的 724×690），不是片空间阅读窗的几何
   （那个是 `min(800, vw-24)` 居中、高度贴内容）。所以它和那个阅读窗不是同一条路数。
4. **窄屏的栏头是搬过来的。** 池子钉在视口上、内容在滚；往深了滚时，浅墨的栏头会落在亮池子上
   （那一格读不出来）。卡片补了一层薄玻璃兜底（`html.d-stacked` 里那三组 `background-color`，
   取自片空间各场景窗面的玻璃色），**栏头没有兜底**。
5. **窄屏的卡片比宽屏「实」。** 那层薄玻璃是这一版加的，原型窄屏是同一张 plate 图垫着；
   我们这边是活的池子，不补就有一半的卡落在对不上的底色上。
6. **背景是活的，所以「收起后与列表逐字节相同」这条证据在这里不成立**（01 / 07 两张像素差很大，
   流光、栏头换字、品牌轮转都在动）。能保证的是：卡片矩形、材质、焦点、`aria-expanded` 都回去了。
7. **瞬间卡的面板偏空**：数据就那几行，右下一大片留白。这是资料的问题，不是版的问题（r7 的 notes 同）。
8. **正文溢出时最后一行会被裁一半**（滚动条按设计藏起来）。原型同样处理，但截图里能看见。
9. **`/draft/` 是 `noindex` 但会进 sitemap**：`@astrojs/sitemap` 的 filter 里没有排除它，
   按约束没动 `astro.config.mjs`。正式接入要么排除、要么别用 `noindex`。

## 三、接到正式页面还差什么

1. **位置的真相要收回一处。** 现在是在页面外面「旁读」栏头。正式做应该让片空间把它算好的
   栏几何（栏左沿 / 栏宽 / 每一栏的 slot）写成 CSS 变量或 `data-`，或者干脆让 canvas 与 DOM
   共用同一份 slot 计算——否则这次接入永远是一条影子实现。
2. **每栏自己的滚动。** 一屏只放得下几条，正式目录页得接上 per-column scroll（片空间是有的：
   `scroll[k]`），或者放弃「一屏三栏」，把这里降级成首页的一块。
3. **窄屏要么接管片空间的竖排版，要么不出栏头。** 最干净的是把 `window.__wander.scroll[0]`
   跟着整页滚（池子、栏头、窗一起走），再按它自己的 slot 摆 DOM 卡；现在的窄屏是「拼」的。
4. **阅读面板对齐片空间的阅读窗**（几何、标题栏的 ‹ › 翻页、地址栏换这一篇的地址）。
   现在面板是一个独立的 `<div role="dialog">`，没有地址、没有翻页。
5. **打开面板时，背后的站点框架（Toolstar / Ave / 导航）也要 inert**。现在只 inert 了卡片层，
   Tab 会被 `trapTab` 圈住，但读屏的虚拟光标还能走到底下的东西。
6. **卡片的密度是设计决定**：真页面的窗是「玻璃 + 标题栏 + 图」的一整套图面；DOM 卡现在是
   标题 / 简介 / 标签的简排。多图瞬间、项目封面要不要搬进来，得先定。
7. **性能/耗电没量过**：背景本来就是一台动画机器（WebGL 流光 + 天气 + 每帧量一堆 rect），
   再叠一层 DOM 卡与两个 WAAPI 过渡，叠起来的代价还没量。
