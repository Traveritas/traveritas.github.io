醒梦 · PHASE 19 · 正文元素补齐

把 h2 的规则，贯穿到其余元素

h2 上其实早就定下了一条规则：随笔是行内记号，项目是方框板块——随笔的小节号嵌在字里（琥珀、 0.6em、被正文读过就忘），项目的小节号是方框加一条右侧细线（自成一块）。 本轮把这条件规则铺到 h3 / ol / table / figure / code 上。两页的体温差因此变成一句话可复述的规则， 而不是「这里也不一样、那里也不一样」。

左右两栏是同一份样张放进两个变体，列宽就是两页的真实列宽（34em 各自折算：随笔 18.5px → 629px，项目 16px → 544px）。第 02–06 节逐个元素给 A（本稿主张）与 B（备选），右下角可即时切。 每节表头的数值框是实测值——脚本读计算值回填。长按空白 2.2 秒入梦、1.3 秒回醒，Shift + 空格 等价；右下角还能切夜段（浅/深/纸）、钉住醒度、冻结动效。

三级小节 h3

.md h3（公共）→ ::before（变体） 随笔字号 — · 项目字号 — 随笔记号 — · 项目记号 —

A：随笔一枚 --wake 冷灰短横（与缝线同色，不用琥珀——琥珀是小节号的专利）；项目是二级汉字序号 一·一，灰而非琥珀，代价是 h3 必须落在 h2 之下（计数器由 h2 自增，孤立的 h3 会显示「零·一」）。B：两边都不加记号，只靠字号、字重与留白分层。C：随笔照旧，项目改成一根竖发丝——同一根线横置与竖置之别，代价是丢掉层级定位。

有序列表 ol

.md ol > li::before（变体） 随笔序号 — · 项目 — 随笔记号 — · 项目记号 —

A：随笔是宋体汉字「一、二、三」（与 h2 的汉字序号同源，只是不点琥珀）；项目是 mono 两位数「01/02」（与 ul 的 mono ○、页面上的 PRJ-01 同源）。两页的项目侧，ol 与 ul 的正文左缘对齐在同一个 1.9em。B：保留浏览器原生数字，只换颜色与字体。 另有一条必修（与选项无关）：随笔的刻度与项目的 ○ 现在写在 .md li::before 上，不分 ul / ol —— 于是 ol 一被用上就会同时出现「浏览器数字 ＋ 记号」。 全站还没有一篇用过有序列表，所以一直没被踩到；落地时必须收窄成 ul > li::before（项目侧那套 li:has(input) 施工清单同理）。

06

等宽 code / pre

.md code / pre（公共）→（变体） 随笔左缘 — · 项目框 —

A：代码与引文都是「外来语」，共用一条梦色左缘（随笔）；项目侧成方框，与 table / figure 同族。底色一律 color-mix(--fg …) 而不是 --bg-sunken——后者是写死的浅色，将来正文若落到深色语境会亮成白斑（内页目前不切夜色，所以这是稳当而非现症）。 语言签直接吃 Shiki 已有的 data-language。 两条与选项无关的必修项：① Shiki 现在给 <pre> 写了行内 background-color:#24292e（github-dark），会盖掉这里的一切底色；落地时须在 astro.config.mjs 关掉默认主题（见 notes）。② 行内 code 要写成 :not(pre) > code：现状的 .md code 会把底与字号漏到 pre 里的 code 上 （症状是项目侧每行多一条底带、随笔侧字号被二次缩到 .71em）。代码里的墨只用全站已有的色（关键字 --umber、类型与字符串梦色压深、注释 --fg-soft、数字中性）——琥珀在这里一次都不出现，它属于锚点与进度。

夜内分钟与挂钟之间的换算写成 at(m) 就够了。
