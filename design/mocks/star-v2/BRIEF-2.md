# star-v2 · 第二轮：把渲染修到能看（几何与运动不动）

第一轮的几何账、轨迹、定格都通过了，不用重做：24 面 / 六支各 4 面 / six tips 等距 / 末格逐位回正位 / 触发后 rAF=0 —— 这些我都在浏览器里验过。

**只有渲染不对。** 现在是「白纸剪的海星 + 一道一像素的彩边」，不是晶体。下面是实测数字，不是形容词。

## 1. 实测（400px 画布，`?size=400`，正位静止帧）

量法：把画布裁成 400×400 后与底色 `rgb(240,243,246)` 比，差值 >6 的像素算作星内。

| 指标 | 第一轮 | NEXUS 参照（`public/nexus-slice/wake.webp`，同量法） | 这一轮目标 |
|---|---|---|---|
| 亮度 P5 / P50 / P95 | **203 / 253 / 255** | 160 / 208 / 247 | **155–175 / 200–218 / 246–252** |
| 亮度恰为 255 的占比 | 大（P95 已贴顶） | — | **< 8%** |
| 星内 B−R 平均 | ≈ +3 | ≈ +10 | **+6 ~ +14** |
| 星内 B−R 最大 | 21 | 37 | **≥ 30** |
| 星占画布面积 | 8.0% | 22%（不同画幅，仅作量级） | **≥ 15%** |
| 每支根部宽度 @400px | 支长 400px 时档口约 4px | — | **≥ 14px** |

## 2. 诊断：为什么全白

不是参数没调，是**光程太短**。吸收是 `exp(-kabs · L)`，`kabs ≈ 0.06`；支细到 root half 0.1375，一条折射光线在体内走 `L ≈ 0.05–0.15`，指数项 ≈ 0.99 —— 吸收完全不起作用，出射色就是环境色本身（近白）。再加上 `trans = mix(trans, glow*1.05, gc*0.55)` 那条光核，星心更白。

所以只有两条路，**优先第一条**：

1. **加粗到能吸收**：`rootHalf` 从 0.1375 提到 **0.24–0.28**（支长仍是 1）。这同时修掉你 notes 里那个「14% 的料看不见」——厚了才看得出六支互插。
2. 如果要保住细长，就得把 `kabs` 提 3–5 倍。但那就不再是 NEXUS 那个材料了，**不要这么做**，除非第一条走不通。

加粗后每支仍然是 4 面（方双锥不变），面数不变。如果你判断加粗到 0.26 还读不出六支互插，允许每支加到 6 面（42 面封顶）——「大面优先」让位于「读得出是晶体」。

## 3. 还得修的三处

- **星在画布里太小**：只占 8%。相机拉近或把 `--stage` 放大，让星在 400px 画布里占 15% 以上。
- **彩边只在轮廓上**：色散现在只在剪影上是 1px 的橙/绿线，看起来像描边瑕疵。它应该出现在**棱线两侧**和**透过星体看到的后方线上**。星内要有色散，不只是边上。
- **后方那条线与字几乎没被折射**：现在线穿进星里只是变淡。要求：正位下这条横线在星内被切成 2–3 段，且星内那一段与星外延长线**横向错开 ≥ 6px**（400px 画布）。这是「折射错位」唯一能被眼睛看到的证据，也是我验收的方式。

## 4. 硬要求

- 颜色的判定只能用这套离线账：写一个 `tone.mjs`，用与着色器**同一套公式**（env、吸收、色散、光核、薄膜、菲涅尔）对每个可见面 + 若干条采样光线算 luminance 与 B−R，输出分布。目的是让你在没有浏览器的前提下知道自己离上面的目标还有多远。不要凭空猜。
- 轨迹、`__star` 接口、定格节奏、rAF=0 这些**不许改**。
- 只写 `design/mocks/star-v2/`。不要起浏览器、不要截图、不要做性能测量。
- `notes.md` 追加一节「第二轮」，写清：改了什么、tone 账的读数、离目标还差什么、一个已知缺陷。
