# 开屏 2 · 从粗到细 · 迭代（跳 / 连续 / 混合）

用户上一轮最喜欢「二 · 从粗到细」。这一轮不换母题，只回答一个问题：

> **分辨率是「一段一段地跳」，还是「连续地跳」好？**

三个候选都是同一个母题、同一张假首页、同一条 **2000ms** 时间轴、同一个渲染核心，
区别只在「时间轴怎么走」。打开：

## 0. 状态与结论

**用户已选定 B（连续收细）。** 上一版用 `flat` 混合层做首帧，用户澄清那不是他要的：
他要的是「最开始分辨率不够粗」，不是叠一层纯色。本轮改成**真正的超粗起始**：
0ms 时一格 = max(视口宽, 高) × 1.2（1440×900 下 = 1728px，整屏一块），停 120ms，
再连续收细到 5px / 26 阶。A / C 保留作对照，未改。

**B 现在的样子**

| 相位 | 毫秒 | 一格 | 阶 |
| --- | ---: | ---: | ---: |
| 一整块 | 0–120 | 1728px（= max(vw,vh)×1.2） | 8 |
| 第一分裂 | **143ms** | 格宽降到屏宽以下 → 2 块（右缘一条 5px 细条开始长宽） | 8 |
| 2×2 | **203ms** | 格宽降到屏高以下 | 8 |
| 连续收细 | 120–1560 | 1728 → 5（对数 settle） | 8 → 26 |
| 停住 ／ 交接 | 1560–1780 ／ 1780–1980 | 5 | 26 |

实测首帧（`meta.json → firstFrame / split`）：四角与中心同为 `rgb(64,64,96)`
（这一块的盒均值量化到 8 阶；未量化均值 `rgb(73,71,102)`），`blocksX=blocksY=1`、`whole=1`；
大字/小字 opacity 0、脑电线 mask 全透明。5px 网点层从第一帧就在 —— 它是假首页的印刷层，
不是首帧叠上去的一块色。

**默认质感：干净（`?print=1` 关）**，旧版粗段的块级 Bayer 可用 `?print=1` 取回；
`?ease=even / creep` 保留对照。理由与对照见 §2-B。

**证据**：`.shots/contact-b-first.png`（0/40/80/120 四帧完全是同一块；160 右缘出现第二块；
240 已 3×2；400 已 7×5）、`contact-print.png`（干净 vs print）、`contact-film-b-flow.png`（80ms 胶片条）、
`compare-flat160.png`（三案同 seek 到 160ms：A 已是马赛克、B 才刚裂出第二条、C 已是马赛克）。

## 1. 机制：一片光，两个数字

首页背景是 1/5 分辨率的像素流光（`src/scripts/wander/light.js`，fbm + 4 色域 + 26 阶 Bayer）。
开屏不引入新母题，只把它的**分辨率**倒过来演：A 案从格 56 屏 px / 量化 3 阶开始，最后收到
**格 5px / 26 阶** —— 与首页 `GRAIN.home` 完全同一个数，然后画布淡出。B 案（选定）更早一步：
第一帧的一格 = max(视口)×1.2（比整屏还大），整屏就是这一格的均值；之后格宽连续收细到 5px。

这一版把渲染拆成两件事：

1. **场（只算一次）**：在 1/5 分辨率（桌面 288×180，手机 78×169）上，把流光算成每画布像素的
   **未量化颜色**，同时建一张积分图。全程静态（2s 内流光不漂移，肉眼无感；真站 shader 里时间照走）。
2. **每一帧（只做采样）**：按时间轴给的格宽求每块的**盒式均值**（积分图 O(1)），
   再量化、按 Bayer 抖动、写像素。

为什么这么做（这是这一轮真正的工程结论）：

- 上一版是**点采样 + 每帧现算 fbm**：格 5px 时每帧要算 51840 次噪声，实测 7.8ms/帧。
  这一版把噪声提前算完，末段只要量化，**0.66ms/帧**（约 12 倍）。
- 连续细化时块边界一直在动。点采样会让每块的颜色跳来跳去（整片「沸腾」）；
  盒均值是同一张图的不同分辨率版本，边界移动时颜色连续变化。
- 抖动（Bayer）的索引**锁在画布像素格（5px）上**，不跟着块走：格子怎么变，网点都不爬、不跳。
- 抖动强度由时间轴给：粗段 0（干净平色块，级数才数得清），细段一路长到 1（首页满强度）。
  粗格子上直接叠满强度抖动，会在每个大色块里长出 5px 网点，和首页那张 5px 网点互相打架。
- 此外还有一层**固定的 5px 网点**（`.boot-dot`，与假首页 `.h-flow::after` 同一张、同一相位）：
  粗段不是塑料色块，而是「印在网上的色」。交接时它跟着画布一起淡掉，底下首页自己的网点露出来，
  位置一模一样。
- **首帧的一格**（B 案）：格宽 = max(视口)×1.2，画布上只有一块，块色 = 这一块的盒均值
  （积分图直接给出，等于整屏的场均值）；量化 8 阶时是 `rgb(64,64,96)`。
  它不是「叠上去的一层纯色」—— 画布上真的只有一个块，`blocksX=blocksY=1`。
- **5px 网点层**（`.boot-dot`，与首页 `.h-flow::after` 同一张、同一相位）从第一帧就在：
  它是假首页的印刷层，不是首帧的叠加色；跟着画布一起淡出，交接时底下的自己露出来。

### 非整数网格的处理（B/C 细段的关键）

格宽是连续的（例如 7.3px = 1.46 画布像素），块边界只能落在整画布像素上，必然出现
「有的块 1px 宽、有的 2px 宽」。三件事一起做才不闪：

1. 块色用**盒均值**而不是点采样 → 边界挪动时颜色连续，没有沸腾；
2. Bayer 用**屏幕/画布像素坐标**索引，不用块序号 → 格宽怎么变，网点不爬；
3. 抖动强度随格宽长出来（格 12px 起、6px 满） → 粗段平色块，细段才见网点。

试过但否掉的方案：**块级抖动**（把上一版粗段的印刷噪点搬回来，Bayer 用块序号）。
粗段每一帧都像数字迷彩，构图读不出来（见 `.shots/contact-a-step.png` 的早期版本观感记录）。
硬切的 A 案用它可以藏住「硬」的感觉，但既然 A 也不需要，就一起关掉了 —— 引擎里仍保留
`timeline().blockDither` 这个可选项。

## 2. 三案的时间轴

总长都是 **2000ms**；交接（画布淡出 → 假首页自己的 `.h-flow`）统一 **1700–1950ms**；
首页入场（大字对焦 / 脑电线 / 小字 / 栏头 / 底部）也由同一条轴驱动，三案只是把起点错开。

### A · 一段一段跳（`a-step`）

**硬切，没有合拢、没有缓动。** 6 级 = 5 次跳，停顿依次收紧（世界越清楚、提级越快），
最后一级停 600ms 让大字对完焦。

| 级 | 毫秒 | 格（屏 px） | 量化阶 | 停留 |
| --- | ---: | ---: | ---: | ---: |
| 0 | 0 | 56 | 3 | 300ms |
| ① | 300 | 36 | 5 | 250ms |
| ② | 550 | 22 | 8 | 210ms |
| ③ | 760 | 13 | 13 | 180ms |
| ④ | 940 | 9 | 19 | 160ms |
| ⑤ | 1100 | 5 | 26 | 到 1700 开始交接 |

首页入场：小字 300–560；大字对焦 550–1250；脑电线 760–1450；栏头 940 起逐个 100ms；底部 1250–1520。

### B · 连续收细（`b-flow`，用户选定）

**首帧不是一层纯色，是一格比整屏还大的真分辨率。** 总长 2000ms：

| 相位 | 毫秒 | 一格 | 阶 | 画面 |
| --- | ---: | ---: | ---: | --- |
| 一整块 | 0–120 | 1728px = max(1440,900)×1.2 | 8 | 整屏一块，块色 = 这一块的均值 `rgb(64,64,96)` |
| 第一分裂 | 143ms | 格宽 < 屏宽 → 2 块 | 8 | 右缘先出现一条 5px 细条，随收细长宽 |
| 2×2 | 203ms | 格宽 < 屏高 | 8 | 下缘再出现一条分裂 |
| 收细 | 120–1560 | 1728 → 5（对数 settle） | 8 → 26 | 无级差 |
| 停住 | 1560–1780 | 5 | 26 | = 首页 GRAIN，等大字对完焦 |
| 交接 | 1780–1980 | 5 | 26 | 画布与网点一起淡出 |

- **首帧做法**：格宽取 `max(vw, vh) × 1.2`，所以画布上只有一块；块色就是这一块的盒均值（积分图直接给出）。
  量化 8 阶后是 `rgb(64,64,96)`（未量化均值 `rgb(73,71,102)`）。阶数取 8 而不是 3：
  一格就是一整屏时，阶数只决定「这块均值」的色准，3 阶会把它压成中灰。
- **分裂是可见的，也应当可见**：格宽降到屏宽以下（143ms）时，右缘先出现一条 5px 的细条，
  随格宽收细长宽；203ms 格宽降到屏高以下，下缘出现第二条分裂，成为 2×2。
  没有额外过渡层、没有交叉淡入 —— 看到的就是分辨率本身在变。
  实拍 `.shots/first-0000/0040/0080/0120/0160/0240/0400.png`，拼版 `.shots/contact-b-first.png`：
  前四帧完全相同；160 出现右缘第二块；240 已 3×2；400 已 7×5。
- **硬裂感**：分裂那一下的边界是硬的（240ms 时左上一块灰绿、与旁边色差很大），但它是「块数变了」，
  不是盖层或闪帧；读起来是画面在变粗/变细。若之后想更软，可把前 80ms 的收细加一点缓入（改一行曲线），
  代价是第一分裂推迟到约 270ms、分裂时的色块跳变减半。
- **缓动**：默认 settle（前快后慢）；`?ease=even`（对数匀速）、`?ease=creep`（前慢后快）留作对照，
  证据 `.shots/contact-ease.png`。

首页入场：小字 240–500；大字对焦 380–1450；脑电线 560–1600；栏头 900 起逐个 100ms；底部 1400–1680。

#### `?print=1`：把旧版的粗段质感找回来

旧版 2-grain 每个大格按块序号取 Bayer 偏移，相邻格落在相邻一阶上，粗段像「印刷棋盘」；
这一版默认关闭（干净色块）。`?print=1` 时，块级 Bayer 只在「格还粗（8px 以上）」那段生效，
随格宽收细自动退场。对照：`.shots/contact-print.png`（上排默认、下排 print，同刻
0 / 160 / 240 / 400 / 550 / 800ms）。

**默认选干净的理由**：

1. 首帧与第一次分裂需要干净的块面；print 会让「一块→两块」的边界上立刻多出棋盘噪点，
   把「分辨率在变」的读法搅成「画面在噪」。
2. 连续收细时块边界一直在动，块序号的 Bayer 每帧重排，**动起来会闪**；旧版是 4 级跳、每级停 130ms 以上，
   这个问题不明显；B 每帧都在变，问题会放大。
3. 首页本来就有 5px 网点层提供「颗粒」，干净版并不欠质感；print 是「再叠一层」。
4. 干净版的粗段更像「世界在成形」，print 更像「画面在噪」。

如果更想要旧版的印刷味，`?print=1` 一个参数就能开；它只在粗段生效，不影响末帧与交接。

### C · 粗处跳，细处连（`c-hybrid`）

**规则分两段**，时间轴是纯函数，粗段硬切、细段连续：

| 相位 | 毫秒 | 格 | 阶 | 做法 |
| --- | ---: | ---: | ---: | --- |
| 0 | 0 | 56 | 3 | 停 230ms |
| ① 跳 | 230 | 30 | 6 | 硬切 |
| ② 跳 | 460 | 15 | 10 | 硬切 |
| 连续 | 460–1380 | 15 → 5（前快后慢） | 10 → 26 | 无级差；抖动格 12→6px 长满 |
| 收束 | 1380–1700 | 5 | 26 | = 首页 GRAIN，停住 |
| 交接 | 1700–1950 | — | — | 画布淡出 |

首页入场：小字 230–460；大字对焦 420–1280；脑电线 600–1400；栏头 850 起；底部 1300–1560。
**三次跳的落点正好踩在首页字两段的起点上**：跳一级，字亮一截。

## 3. 与首页的接缝

- **终帧就是假首页静置**：末级 `cell=5 / lv=26 / dither=1` 取自 `light.js` 的 `GRAIN.home`；
  构图（三池圆心与椭圆）直接对齐假首页那四条 `radial-gradient`。A/C 的 1990ms 帧 MD5 相同
  （`0BE2096F…`）；B 与它们只差底部「下沉」两字的 164 个像素（亚像素字体栅格差，不是内容或布局差）。
  三案无 JS 帧完全相同（`C3A01330…`），即「不放时就是首页」。
- **首帧不是首页**：0–120ms 的一整块是**场的均值**（量化 8 阶后 `rgb(64,64,96)`），
  故意不映出首页构图；它是「分辨率太低」的结果，不是叠上去的色层。
  均值取自同一张场，所以它和后来的马赛克、和首页的光同源，不是外插的一个色。
- **网点无缝**：开屏那层 5px 网点与首页 `.h-flow::after` 同一张、同一相位；从第一帧就在，
  淡出时底下的自己露出来，看不出换了层。它是假首页的印刷层，不是首帧的叠加色。
- **接管入场，不让它在下面白演**：`HomeMock.line(v, t)` / `focus(v)` 由开屏时间轴驱动；
  线的抖动相位也由时间轴给（`t = ms/1000`），所以 `seek(ms)` 完全确定（含脑电线与画布）。
- **reduced-motion / 无 JS**：`prefers-reduced-motion: reduce` 时画布根本不创建，直接 `seek(2000)` 落首页；
  无 JS 时静态 HTML 已经是一张完整的假首页（`.shots/nojs-*.png`）。
- 站内从别页跳回主页时不要再叠开屏这件事，属于真站接入范畴，见 §7（交给 View Transition 余像）。

## 4. 实测（Chrome，1440×900，桌面机；脚本 `.shot.cjs`）

每帧重画耗时（`seek(ms)` 20 次平均，走的是页面真实重画路径，不是只算 canvas）：

| 时刻 | A | B（选定） | C |
| --- | ---: | ---: | ---: |
| 0ms | 0.28 | 0.06 | 0.24 |
| 300ms | 0.24 | 0.13 | 0.30 |
| 600ms | 0.38 | 0.14 | 0.57 |
| 900ms | 0.58 | 0.35 | 0.56 |
| 1200ms | 0.68 | 0.63 | 0.70 |
| 1500ms | 0.70 | 0.74 | 0.66 |

- 上一版末段 **7.81ms/帧**，这一版末段 **0.74ms/帧**（量的是同一条 seek 路径）。
- B 的粗段几乎免费：一格 = 整屏时画布上只有 1 个块（一次积分图读数 + 一次 `fill`），**0.06ms**；
  格 20px 左右时 0.14ms；只有末段（格 5px、逐像素量化）才回到 0.74ms。
- 自然播放 2s（127 帧，60fps）：A 只重画 **5** 次（只在跳级时），B **88** 次（粗段每帧格宽都在变；
  0–120ms 那一整块是静止的，缓存键不变会跳过），C **57** 次；三案都是 avg 16.6ms、p95 16.8ms、**0 帧 > 20ms**。
- **手机 390×844 + 4× CPU 降速**（B 案，最重的一版）：avg **16.62ms**、p95 16.8、max 16.9、**0 帧 > 20ms**，
  127 帧里重画 87 次。手机画布只有 78×169，比桌面小 4 倍，所以 CPU 路径也压得住。
- 一次性代价：场预计算（288×180）**19–26ms**，发生在本轮开屏开始前；首帧 ready ≈ 0.6–0.8s
  （含字体与网络）。真站走 shader 后这一项不存在。
- 动画层：画布 `image-rendering: pixelated`、只改 `opacity`；字的对焦是 `blur(14px)→0`，
  作用在一个文字元素上（不是整屏 filter），与首页入场同款。

**60fps 结论**：三案在桌面与「手机 ×4 降速」都满帧；B 在粗段比 A/C 都便宜（块少），
只有末段 0.74ms/帧，不到 16.7ms 预算的 5%。接真站 shader 后差别归零（§6）。

## 5. 三案对比

|  | 节奏 | 视觉质量 | 代价 |
| --- | --- | --- | --- |
| **A 跳** | 6 级 5 跳，可数；但 9→5、5px 两跳静帧几乎一样，**实际可数 4 级** | 粗段有「印刷」的干脆感；末段与首页一致 | 最省：2s 只重画 5 次，0.7ms/帧 |
| **B 连续（选定）** | 首帧一格 = 整屏（1728px）停 120ms → 143ms 第一次分裂 → 203ms 2×2 → 连续收细；无级差，落点干净 | 首帧就是一整块真像素；分裂可见、边界硬但读作分辨率变化；默认干净质感，`?print=1` 可取回旧印刷棋盘 | 粗段最便宜（0.06–0.14ms），末段 0.74ms；2s 重画 88 次 |
| **C 混合** | 前 460ms 三次硬跳（级数可数），之后连续收束，落点干净 | 粗段干脆、细段安静 | 居中：57 次重画，0.7ms/帧 |

**用户已选定 B。** 本轮把 B 的首帧改成了真正的超粗分辨率：不是叠一层纯色，而是**一格比整屏还大**，
所以画布上只有一块，它的颜色就是这一块的均值；往下收细时人会看到它裂成两块、四块。
如果之后还想要 A 的「一格格」读法，B 的 `?print=1` 能把粗段的印刷质感找回来，但它换不回级数可数 —— 那是 A 的性质。

## 6. 可移植：时间轴是纯函数，真站走 shader

每个候选里都能看到同一个签名（没有 DOM、没有状态）：

```js
// timeline(ms, vw, vh) → { cellPx, levels, octaves, dither, blockDither }
//   cellPx      一格多少屏 px。首页是 5；B 的首帧是 max(vw, vh) × 1.2（比整屏还大 → 画布上只有一块）；
//   levels      量化阶数（26 = 首页 GRAIN.home[2]；B 首帧 8，见 §2-B）；
//   octaves     fbm 倍频数（2 粗 / 3 细；2D mock 里由「场 = 3 倍频 + 盒均值」隐式表达，
//               真站 shader 里直接是 uOct）；
//   dither      Bayer 抖动强度 0–1（画布像素格上的抖动）；
//   blockDither 块级 Bayer 强度（0 = 干净；B 案 ?print=1 时粗段 >0，恢复旧版印刷棋盘）。
```

B 案的时间轴（节选，首帧与收细的部分）：

```js
const cell0 = Math.max(vw, vh) * 1.2;              // 1440×900 → 1728px，整屏一块
const f = 1 - Math.pow(1 - p, 2);                  // p = seg(ms, 120, 1560)，settle
const cell = cell0 * Math.pow(5 / cell0, f);       // 对数插值：比例均匀
const r = clamp01((cell - 5) / (48 - 5));
return {
  cellPx: cell,
  levels: 8 + 18 * Math.pow(1 - r, 2.2),           // 起始 8 阶（一块的均值色准），末级 26
  dither: 1 - Grain.sstep(0.02, 0.3, r),
  blockDither: print ? clamp01((cell - 8) / 20) : 0,
};
```

引擎侧不需要为它加任何分支：`cellPx = 1728` 时块边界循环只会切出一块，`meanOf` 用积分图
直接给出整屏均值；这正是「分辨率不够粗」的字面实现。

`__boot.probe(ms)` 直接返回它（对比台的曲线就是这么画的）。A 案的回车式：

```js
function timeline(ms, vw) {
  let i = 0;
  while (i + 1 < CUTS.length && ms >= CUTS[i + 1].at) i++;   // 硬切
  return { cellPx: Grain.scaledCell(CUTS[i].cell, vw), levels: CUTS[i].levels,
           octaves: CUTS[i].oct, dither: CUTS[i].dither, state: i };
}
```

C 案就是「`ms < 460` 查表 + 否则一条连续曲线」，B 案只有曲线。换成真站语言也一样。
手机上 `Grain.scaledCell` 把粗段的格宽向末级收敛（`k = clamp(vw/1200, 0.5, 1)`），
否则 390 宽的第一级只有 6 列，构图读不出来；末级永远是 5。

### 接真站：`light.js` 加 `uCell` / `uLv`（概念方案，本轮不改 `src/`）

真首页本来就有 1/5 分辨率的 WebGL2 流光、Bayer 与量化，**开屏不需要第二套渲染管线**：
开屏就是让这同一片光的 `uCell` 从粗调到 1、`uLv` 从 3 调到 26。

建议改动点（概念层面）：

1. `FRAG` 里加三个 uniform：`uCell`（画布 px，1 = 首页一格；B 的首帧 = 1728/5 ≈ 346，大于画布宽高 → 只有一块）、
   `uLv`（量化阶数）、`uDither`（0–1，乘在 bayer 项上）；`uOct` 控制 fbm 循环次数（2/3/4）。
2. `main()` 里在采样前把坐标量化到块心：
   ```glsl
   vec2 blk = floor(ys0 / uCell) + 0.5;
   vec2 fc = vec2(blk.x * uCell, uRes.y - blk.y * uCell);
   ```
   `uCell == 1.0` 时它与现在的 `fc0` 等价，首页渲染逐像素不变。
   `uCell` 很大时（例如 346）所有 fragment 落到同一块心，整屏自然就是一块的均值 ——
   不需要任何「纯色层」或均值 uniform，这正是 B 首帧在 shader 里的等价物。
3. 量化那一行 `Lq = gr.z` 改成 `Lq = uLv`（首页传 `GRAIN.home[2] = 26`；B 首帧传 8）；
   抖动项 `uG[r].x` 乘 `uDither`（首页传 1；B 粗段传 0）。
4. `createLight()` 的 `draw()` 增加 `cell / levels / dither / octaves` 参数，
   uniform 设置方式同 `uSplit / uBias`；`boot.ts` 里用 rAF 算 `timeline(ms)`，每帧传进去。
5. 时间轴在 `boot.ts`：开屏不再加任何覆盖层，而是把首页 canvas 的 `uCell/uLv/uDither` 从粗拉到位；
   首帧 `uCell = max(vw,vh)*1.2/5`。大字对焦与脑电线仍由现有 CSS / wander.js 驱动，
   起点对齐时间轴（B 案是 240ms 之后）。
6. **网点层**：首页的 5px 网点是 `.h-flow::after` 的 CSS 层，不在 shader 里，也不需要为开屏额外淡入 ——
   它本来就在，首帧的那一块就是「印在网上的一个色」。
7. `prefers-reduced-motion`：`uCell=1、uLv=26、uDither=1`，等价于不放；无 JS 时首页 CSS 兜底不变。

成本账：真站本来就是每帧 288×180 个 fragment 跑 fbm；把采样点量化到块心，**GPU 计算量不变**
（甚至粗段全屏只有一块、纹理缓存全命中，更便宜），不需要多 pass，也不需要 2D canvas 与 shader 同时占 GPU。
这也是 B 案接入最省事的地方：**开屏与首页是同一个渲染器，终帧天然一致，不需要淡出换渲染器**；
`uCell/uLv/uDither` 只是三个 float。

## 7. 已知风险 / 未做

1. **假首页的大字反相窗**仍是 CSS 近似（`_shared` 原件的做法），真站是 canvas 反相 + 字形遮罩；
   本轮的接缝讨论只对「粒子/流光」这一层成立，字的「亮/暗自动换墨」没有模拟。
2. 场的预计算是一次性 19–26ms 的阻塞；真站 shader 无需此步，但若保留 2D 兜底路径，应在 idle 时算。
3. 三案都用 `blur(14px)` 对焦大字，手机上会有一点合成开销；这是首页原有入场，未新增。
4. 对比台的三个 iframe 各自跑自己的 rAF；同时点「重播」时起跑差 <1 帧，滑杆 seek 则完全同步。
   胶片条是 `.shot.cjs` 事先拍好的 PNG（`<img>` 引用），不是实时截帧。
5. 本轮没有接真站、没有改 `src/`；§6 是改动点清单，不是已完成代码。
6. 时间轴 2000ms 比首页现有入场（大字 1.6s / 线 2.2s）短；B 案把入场放在首帧与分裂之后
   （小字 240–500、大字 380–1450、线 560–1600），接入时要么按这个压缩首页入场，要么让收束段与两条入场重叠。
7. **`?print=1` 的代价**：块序号的 Bayer 在连续收细时每帧重排，动起来会有噪点蠕动/闪烁。
   它只适合「想要旧版粗段质感」的取舍，不建议作为默认；对照帧是静帧，看不出这个动效问题。
8. **首帧那一块的颜色** = 整屏的盒均值（当前桌面 1440×900 下量化 8 阶是 `rgb(64,64,96)`，未量化均值 `rgb(73,71,102)`）。
   换视口 / 换窗口比例时它略变（手机是另一个值），这是应该的：它就是「这一屏的平均光」。
   若希望首帧颜色更接近某个目标色，调整起始阶数（8 → 更高）即可，不需要改结构。
9. **硬裂感**：143ms 第一次分裂、203ms 2×2。边界是硬的，且 240ms 时左上一块是灰绿、与旁边色差很大；
   这是分辨率真的变了，不是盖层故障。如果觉得太脆，可把前 80ms 的收细加缓入（第一分裂推迟到约 270ms、
   分裂瞬间的色块跳变减半）—— 本轮没做，按用户「分裂要保留」的要求先保留。
10. 显影/`flat` 那套逻辑已从引擎与时间轴删除；B 的首帧现在完全由 `cellPx = max(vw,vh)×1.2` 得到，
    引擎里没有任何「纯色层」分支。
