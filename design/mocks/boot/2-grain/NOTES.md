# 开屏 mock 2 · 从粗到细

`index.html` 单页，原生 JS，不依赖构建。
截图：`node design/mocks/boot/2-grain/.shot.cjs`；画一帧要多久：`node design/mocks/boot/2-grain/.bench.cjs`。

---

## 1. 机制

不引入任何新母题。它用的就是首页那片流光自己的属性：**分辨率**。

首页的流光画在一张 1/5 分辨率的画布上，再按 26 级有序抖动量化——它天生是**粗颗粒、有网点**的。开屏就把这件事倒过来演：

1. 一上来是一片**几乎看不出形状的马赛克**（48px 一格，只有 3 阶色）。
2. 每一拍提一级：格 48 → 24 → 13 → 8 → 5 屏 px，量化阶 3 → 6 → 10 → 16 → 26。
3. 走到最后一拍时，它正好落到首页那张 **5px 网点**上、26 阶——与首页的 `GRAIN.home` 完全同一个数。
4. 然后画布淡出。因为落点就是首页自己的 `.h-flow`，所以"换渲染器"这件事不可能被看见。

节奏刻意对齐全站的 `--fld-beat: 0.25s`——每一拍跳一格，与脑电在梦态的重采样间隔是同一个数。

## 2. 时间轴（总长 2020ms）

| 相位 | 毫秒 | cell（屏 px） | 量化阶 | 倍频 |
| --- | --- | ---: | ---: | ---: |
| 粗起 | 0 | 48 | 3 | 2 |
| ① | 180 | 24 | 6 | 2 |
| ② | 430 | 13 | 10 | 2 |
| ③ | 760 | 8 | 16 | 3 |
| ④ | 1150 | 5 | 26 | 3 |

每一级先用 130ms（`RAMP`）合拢，再停住让人看清。

同时由这条时间轴驱动首页的入场：

| | 毫秒 |
| --- | --- |
| 大字对焦 | 500 – 1250 |
| 脑电线画出 | 700 – 1500 |
| 小字 | 620 – 900 |
| 三个栏头 | 900 – 1240 |
| 底部（时刻 / 出口 / 下沉） | 1300 – 1580 |
| 画布淡出、交还首页 | 1760 – 2020 |

## 3. 与首页的接缝

- **落点就是终点**：`cell = 5`、`lv = 26` 取自 `light.js` 的 `GRAIN.home`，构图的三池圆心与椭圆直接对齐首页那四条 `radial-gradient`。最后一帧与首页的第一帧是同一张图。
- **网点无缝**：开屏的 5px 网点与 `.h-flow::after` 是同一张 CSS 网点，从第一帧就在，整条时间轴只是让马赛克一级级收到它的格子上。
- **接管入场**：首页的两段入场由开屏的时间轴驱动，不在底下白演。

## 4. 代价与风险（这一版最重）

实测（`.bench.cjs`，每帧完整重画 fbm + 上色 + 量化 + `putImageData`）：

| 时刻 | 每帧耗时 |
| --- | ---: |
| 0ms | 0.42ms |
| 330ms | 0.96ms |
| 600ms | 1.56ms |
| 940ms | 3.30ms |
| 1300ms | **7.81ms** |

也就是**越接近结束越贵**——因为每一级都在变细，像素数按平方涨。7.81ms 在 60fps 的 16.7ms 预算里已经吃掉近一半，而且这是桌面实测；手机 ×4 降速下会超预算。

其他风险：

1. 全程是 **CPU 逐像素** 重画（`ImageData` + `putImageData`），不是合成器。这与另外四版"只动 transform"的路子本质不同。
2. 提速办法：末两级只重画一次然后冻结（已经是静态的，没必要逐帧更新）；或整个改到 WebGL，但那就不再"零依赖"了。
3. 如果真站要让这段和首页 WebGL 同屏，会有两套渲染管线同时占 GPU。
