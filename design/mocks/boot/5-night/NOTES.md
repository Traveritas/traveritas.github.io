# 开屏 mock 5 · 夜里的一枚开口

`index.html` 单页，原生 JS，不依赖构建。截图 `node design/mocks/boot/5-night/.shot.cjs`，实测加 `--perf`（只做其中一项就加 `--shot` / `--perf`）。

---

## 1. 机制

旧开屏的问题是**换了一件东西**：暖白的圆面、碎晶的剪影、挖孔破窗 —— 首页的靛夜里本来没有窗在等着被破。这一版不加新东西，只把夜本身剖开：

1. **夜就是夜。** 幕不是一块盖在首页上的白，是把首页同一片靛夜压深之后的形状。八条带沿 **14°**（首页那根线的角度）叠成一枚叶状的夜，每条用站内三池夜色之一（项目深蓝 `#0d1524` 系、瞬间紫 `#1d1729` 系、随笔浅蓝灰 `#c6ced9` 系各取两档），上下沿各一根发丝线；带与带之间是**真的缝**，不是画出来的线。
2. **正中留着一枚开口。** 正中那两条带之间那道缝最宽，开口里是琥珀色的光、两道同心环、一粒四角星。全部八条带 ±3.5 格的排布里，开口是唯一不对称的轴心 —— 这就是标题里的「一枚开口」。
3. **开口先透光，再裂开。** 第一拍丝线/开口亮起；第二拍八条带按离中缝的远近沿 14° 各滑开一点（像套印没对准），开口自己张一线，光顺着缝漏到带上；第三拍带从中心往外飞、越飞越薄，夜淡掉，首页的流光从叶缝和开口里亮回来。
4. **交接靠「同色的退开」，不靠「撤幕」。** 夜的底色与首页 `#0e0f1d` 是同一族，压深的只是透明度；最后淡掉的那一层本来就是首页的样子，所以没有一块色跳。同时开屏接管了首页原本那两段入场（大字 1.6s 对焦、脑电线 2.2s 画出）—— 开屏一开始就把 `HomeMock.line(1) / focus(1)` 摆到静置，并 `HomeMock.stop()` 掉那个常驻 rAF，于是首页入场不会压在夜底下空演一遍。

## 2. 时间轴（总长 2040ms）

| 相位 | 毫秒 | 发生什么 |
| --- | --- | --- |
| **亮起** | 0 – 520 | 八条带从开口往外摊开（起手缩到 0.58 宽、向开口收进 26k 像素，各自错 62ms 展开）；开口的亮线从 0.06 倍宽度长到满；双环淡入起转；星从 0.2 倍亮到满 |
| **错开** | 520 – 1160 | 带按离中缝远近沿 14° 各滑开 12–30px（外层少、里层多）；开口张到 1.5 倍厚；光从缝里漏到带上；780ms 到最远，1030ms 再退到 0.7 |
| **打开** | 1160 – 1990 | 带从中心往外飞（里层飞 0.58·视高，外层到 0.97·视高），纵向压到 52%，透明度到 0；夜 1300ms 起淡、1990ms 归零；环撑散出画；星沿 14° 拉成 5.2× 的一根线然后消失 |
| **静置** | 1990 – 2040 | 只剩首页。最后一帧就是 `_shared/home-fragment.html` 静置的样子 |

对称的另一处：显影与飞散都从**开口**往外排序，所以整个 2 秒的读法是「一枚开口睁开 → 夜从它两侧退开」，不是「遮罩缩放」。

## 3. 与首页的接缝

- **同轴**：八条带、开口、环、星全挂在 `rotate(14deg)` 的骨架上，与首页脑电线同一根轴。星最后被拉成的那根线，正好落在这根轴上。
- **同色**：底色、三池夜色的取色都从 `src/data/night.ts` 的夜色池里取；夜里没有一种颜色是首页没有的。
- **接管入场**：开屏期 `HomeMock.stop()` + `line(1)` + `focus(1)`。这两段原本压在旧开屏底下白演（基线里 `html.booted` 中位 5.25s，文字还有自己的入场），现在由开屏的退开来完成「亮出来」这件事。
- **不做第二次**：真站里从别的页面跳回主页时不再放开屏，交给跨文档 View Transition 的余像；本 mock 只演示首次进入。

## 4. 四条硬约束怎么守住的

| 约束 | 做法 | 怎么验的 |
| --- | --- | --- |
| **零网络资源** | 开屏层里没有一个 `<img>`、没有一处 `url()`；八条带的颜色、开口的渐变、两环一星全是内联 SVG 与 CSS 渐变 | 实测里「开屏新增请求 = **0**」；资源清单与 `?noboot=1` 完全一致 |
| **零 mask** | 不用 `mask` / `mask-composite` / `clip-path` / `backdrop-filter`，也不用整屏 `filter`。旧版的「挖孔幕 `scale(72)`」整条路都不要了 —— 它每帧重算蒙版 | 全文 grep：开屏层里 `mask` / `clip-path` / `backdrop-filter` 一次都没出现；唯二的 `maskImage` 与 `filter: saturate()` 都在假首页的 `.h-eeg` / `.h-flow` 上（来自 `_shared/home-fragment.html`，不是开屏） |
| **纯合成器** | 所有运动只写 `transform` / `opacity`，全部走 Web Animations（`element.animate`），14 条轨道、每元素一条、时长恒为 2040ms。没有 `@keyframes`，没有 rAF 驱动的逐帧写样式 | 帧间隔中位 / p95 都是 **17ms**，与「只有首页」组一致 |
| **不等资源** | 脚本执行到的那一帧就是第一帧：量一次尺寸、建 14 条轨道、`play()`。`__boot.ready` 只等首页字体（最多 1500ms），开屏自己不等任何东西 | 对照组里 FCP 252ms / 292ms，两组几乎同时出画 |

## 5. 统一控制口

```js
window.__boot = { ready, total: 2040, pause(), seek(ms), resume(), geo() };
```

时间轴全在 JS 里，`seek(ms)` 就是把 14 条 animation 的 `currentTime` 都设成 ms 并 `pause()`，所以任何一毫秒都可以确定地重画 —— 截图脚本靠这个拍帧。
`geo()` 只是调试用，返回叶的厚度/长度、环径、星径。

## 6. 代价与已知风险

1. **叶的走向是固定的 14°，但它占满屏幕的法向 46%–56%。** 在极端宽扁的窗口（比如 21:9 竖切）里，叶会比视口还长，两端会切在屏幕外。这是刻意的（要的就是「夜比屏幕大」），但把窗口拉得特别窄时（< 360px），`perp` 已经被 `W * 0.92` 夹住，八条带会挤得比设计稿紧。
2. **`will-change` 常驻。** 14 个元素都挂着 `will-change: transform, opacity`，2040ms 内是划算的；真站里应该在开屏结束时把开屏层整个从 DOM 摘掉（这一版已做：`tail.finished` 后移除 `data-boot`）。
3. **八条带的底色靠 `linear-gradient(90deg, …)` 两头化进夜里。** 这是为了让叶没有切齐的边；代价是每张带子都要算一条渐变，首帧光栅化略贵。可以让位给纯色 + 一条伪元素，但视觉上会硬。
4. **`contain: strict` + `display: none` 的开关。** 无 JS 时 `data-boot` 从来没被加上，所以开屏层永远不出现 —— 不会留一块死幕。但这也意味着**如果脚本在写 `data-boot` 之后、建轨道之前抛错，会剩一块空夜**。已加 2.6s 兜底（`if (!window.__boot) removeAttribute`），不过真站里更稳的写法是把兜底挂在 `error` 事件上。
5. **首访和返访放的是同一个 2 秒。** 性能上已经不为难，但体验上「每次都看 2 秒」需要作者定夺；要缩短可以只压「错开」这一拍（520–1160 是最长的一段）。
6. **星最后拉成线，是为了接首页那根 14° 轴。** 如果首页最终选择了别的交接手法（比如大字对焦），这一步要跟着改，否则会多出一根没人接的线。
