# 开屏 mock 3 · 合上又睁开

`index.html` 单页，原生 JS，不依赖构建。截图：`node design/mocks/boot/3-eye/.shot.cjs`。

---

## 1. 机制

旧开屏的病根是**把破窗当成开场的动作**：窗一直是个窗，光从孔里透出来，页面从孔里长出来 —— 可首页的靛夜里本来没有一扇窗在等着被破。

这一版把那个动作反过来用：**先合上，再睁开**。

1. **安静**：旧开屏那套材质原样在里面 —— 暖白底、冷灰圆面、两道同心发丝弧（缺口里一粒四角星）、极淡的树脂在平移。弧各自慢慢地转，树脂几乎看不出在动。
2. **闭**：材质朝画面中心收，收没了；四周压上一层很浅的冷（**最暗处也只是银蓝，不是黑**），中心还留着一点暖。素幕熄掉的那一刻，那条 **14° 的缝**从白变成了夜 —— 缝里的微光同时从正中往两端长成一根发丝。收完，画面上只剩这一条缝。
3. **停**：什么都不动，只有缝里的雾在慢慢走。
4. **睁**：挖孔幕沿**法向**整体放大。夜从缝里铺出来，幕同时后退（放大）并变冷 —— 暖白 → 靛夜不是靠幕淡掉，而是靠「孔里的夜先出现、暖白幕整体后退并变冷」完成的，所以没有硬切。
5. **余**：交还首页。

**关键机制：斜孔是静态蒙版。** 孔的半宽（`--halo: 5px`）从头到尾一个像素都不变，写死在 `linear-gradient(194deg, …)` 里；「睁」不碰蒙版，只写挖孔幕的 `transform: scale()`。所以全程既没有重算蒙版，也没有把孔的宽度做成动画。

旧开屏的三层填充（纯色 / 树脂 / 104° 斜线）里，**只留了树脂**，且淡到 0.14 —— 斜线与网点那两层的工艺感太重，会把这一版拉回「套印错位」的语境。碎晶剪影不再是主剪影（它属于「破窗」那套），孔的形状换成了直线。星环从三道减到**两道**，转速也压慢了，不再有那种三道同心环的仪式感。

## 2. 时间轴（总长 2240ms）

| 相位 | 毫秒 | 时长 | 发生什么 |
| --- | --- | --- | --- |
| **安静** | 0 – 240 | 240 | 暖白整面，圆面与两道弧浮在里面各自慢转，树脂极缓平移 |
| **闭** | 240 – 840 | 600 | 材质朝中心收（scale 1 → 0.025）并在 560–940 淡掉；四周的冷从外圈压进来；素幕 620–850 熄掉，缝从白变夜；微光 640–900 从正中长成一根发丝 |
| **停** | 840 – 1040 | 200 | 不动。画面上只有那条 14° 的缝，及缝里的夜与一点微光 |
| **睁** | 1040 – 1840 | 800 | 挖孔幕 scale 1.6 → 300（沿法向），夜从缝里铺开；幕 1520ms 撤掉、冷色子层同时淡到满；夜里的雾散去 |
| **余** | 1840 – 2240 | 400 | 字对焦到位、线画完、栏头 / 时刻 / 出口 / 下沉依次浮上来 |

`total = 2240`，落在任务书要求的 1.8–2.4s 内。

## 3. 与首页的接缝

- **接管入场**：首页那两段入场（1.6s 对焦、2.2s 画线）原本压在幕底下白演一遍。这里由开屏在 `apply()` 里直接驱动 `HomeMock.pixels / line / focus`，时间点落在「睁」的同一窗口里（`pixels` 1080–1620、`line` 1300–1900、`focus` 1420–1960），所以**像素流光从粗到细、线从正中画出去、大字对焦**这三件事都发生在幕已经让开之后，而不是在幕底下。
- **同轴**：那条缝与首页脑电线是同一根 **14° 轴**，位置也都在屏幕中心。睁到最后，缝的方向就是线要画的方向，所以线画出来时读起来是「缝里那根线醒了」，而不是「又出现一根线」。
- **同色**：夜层取首页靛夜 `#0e0f1d` 一族，且**半透明**（alpha ≈ 0.95–0.965）。这一条很关键：如果夜是不透明的，它就得自己淡掉来交还首页，中途必然出现「夜里混进首页亮斑」的脏边。做成半透明之后，底下的首页一直都在，只是被压暗、起了雾；睁的过程中雾散掉，首页那片流光自然浮出来，两条夜之间没有色跳。
- **不做第二次**：真站里从别的页面跳回主页时不再放开屏，交给跨文档 View Transition 的余像。
- **减动效 / 无 JS**：`prefers-reduced-motion: reduce` 时 `data-boot` 从不被写上，开屏层 `display: none`，页面直接是首页静置的样子；脚本检测到没有 `data-boot` 时**提前返回**，不会调 `apply(0)` 把首页推成空靛夜（这条踩过，见 §5.4）。

## 4. 四条硬约束

| 约束 | 做法 |
| --- | --- |
| **蒙版静态** | 斜孔 `--halo` 写死；「睁」只写挖孔幕的 `transform: scale()` |
| **只动 transform / opacity** | 树脂走 `transform`，弧走 `rotate`，微光走 `scale + opacity`，材质走 `transform + opacity`，幕走 `transform + opacity`。没有一处动 `width / height / filter / top / left` |
| **无 `@keyframes`** | 全部时间轴在 JS 的 `apply(t)` 里；`__boot.seek(ms)` 直接调它，确定地重画任何一毫秒 |
| **`__boot` 控制口** | `{ ready, total, pause(), seek(ms), resume() }`，`ready` 等 `document.fonts.ready` |

---

## 5. 踩过的四个坑

1. **`will-change: transform` 会把带 mask 的图层降分辨率栅格化。** 挂了之后 Chrome 先按低分辨率把蒙版层画成一张位图，再放大几百倍 —— 孔边变成一级一级的阶梯（就是「一块黑条的边」那种观感）。**挖孔幕上绝对不能挂 `will-change`**，去掉之后边缘就是干净的两条直线。
2. **渐变角的镜像。** CSS 渐变角从「朝上」顺时针算，色带垂直于渐变方向。想要一条**下斜 14°** 的带子得写 `194deg`；写成 `166deg` 会得到上斜 14° 的带子，与 `rotate(14deg)` 的微光正好镜像交叉成一个 X —— 那时缝里只有中心一个点亮，两端全暗，看起来像断成两截。
3. **孔边不要羽化。** 蒙版整体放大 300 倍，任何以 px 计的柔边都会跟着放大成几十像素的雾边。两个色标挨在一起（硬边）才是对的。
4. **减动效下不能走时间轴。** 早期版本在 `reduce` 时虽然 `display: none` 了开屏层，但脚本仍然执行了 `apply(0)`，把 `HomeMock` 的线 / 对焦 / 像素全部推到 0 —— 后果是减动效的用户直接看到一整片空靛夜。现在脚本先检查 `data-boot`，没有就提前返回并把三个旋钮摆到静置。

---

## 6. 代价与风险

1. **首帧的全屏 mask 开销。** 挖孔幕是一层全屏 `mask-composite`，首帧光栅化比纯色块贵。但它只栅格化一次，之后全程只改 `transform`。若真站首帧掉帧，退路是把 `--halo` 调大（孔径更明显），或者把前 240ms 的安静期做成静态图。
2. **放大到 300× 之后幕还在合成。** 「睁」的后半程幕早已让开画面，但仍参与合成（只是被 `overflow: hidden` 裁掉）。真站里应在结束时把开屏层整个从 DOM 摘掉 —— 这一版已做（`boot.style.display = 'none'`）。
3. **夜层是半透明的。** 好处是无脏边；代价是首页将来若换成更亮的流光，夜层会被顶得偏亮，出缝的对比度会掉。届时把 `.b-hollow` 的 alpha 提到 0.97 左右。
4. **圆面 `--st: min(62vmin, 520px)`** 在极扁窗口（如 21:9 竖切）会偏大，闭的时候收缩的观感略弱。不影响正确性。
5. **雾（`mist.webp`）的收益有限。** 铺在 `inset: -20%`、`screen` 混合、opacity 0.16；缝太窄，它主要是让「睁」之后那片夜不是一块死色。嫌开销可以直接去掉，观感差别很小。
6. **每次进入都放。** 2240ms 对返访者可能偏长；要缩短的话，「停」那 200ms 最先可以压。
