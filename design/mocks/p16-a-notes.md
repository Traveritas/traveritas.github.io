# p16-a 散块自走 ↔ 聚成构造 · Solo Squares → Assembled Blocks · 自验笔记（变体一）

## 主张
两态差不在「图样」，而在**同一批方板有没有承认自己属于同一个形体**：醒态 105 块方板各自自走、结构上凑不出任何形体；梦态它们各自回到所属构造体里的格位，3–6 块压合成一个大块。这是 D 稿的反转——D 的大块在两态都成立、梦态原地化；本稿醒态**不成立任何形体**，梦态才成形。

## 醒
- 105 块方板，尺寸只取**五档模数** 40/64/88/128/176（实测分布 13/24/34/26/8），全部落在**同一条 8px 栅线**上（簇心、聚位、散位都吸附它）；散开量取 16px 整数倍（实测最大 416px）⇒「散」是有序的散，不是碎屑。
- 每块一条自走：12 种方向（整数像素，往返 2|d| ≈ 11–20px）、3 档幅度、档位时长 22–54s、24 格相位，`animation-direction: alternate` ⇒ **净位移 0**（往返振荡，不是无限平移）。**全场只有一条 `@keyframes sq-solo`**，方向/幅度/时长/相位全由 per-element 的 `--dx/--dy/--dur/--dly` 取。
- 生成期硬规则：任何一块最多与另一块轻触（叠 ≤22% 小方板面积）⇒ 醒态在结构上凑不出「块」（生成读数 `retried` ＝ 换过方向的块数，35/105）。叠深实测 3（≤3 是红线配套），`?seed=7` 换一批仍满足叠深 ≤3。
- **红线 1 的例外声明**：本稿醒态**有且只有**「每块方块各自的那条位移动画」（105 × `sq-solo`，这正是用户要的）；呼吸/脉冲/闪烁/透明度变化/颜色变化一律没有——逐帧变的只有 `transform`。

## 梦
- 每块回到构造体里的格位：25 个构造体（(u,v) 正交系里泊松排布，排斥半径＝两外接圆 +70），每个 3–6 块板、外接框 160–400px、长宽比 ≤1.5；位置与尺寸都吸附到 8px 栅线 ⇒ 静止帧里读得出整齐的边与角（证据：`.shots-p16-a-extra/zoom3x-block-{wake,dream}.png` 是**同一块区域**的两态 3× 对照）。
- 交叠规则（本稿的，不是 D 的）：**不擦不盖，只叠浓**。板面 6%、边线 13%，再乘档位浓度 0.66/0.82/0.96 ⇒ 压合处两层板面与两条边线同时叠上去（面 →11.6%、线 →24%），交叠区比周围浓一档、两条边线在那里交成一枚直角关节。为什么这条好：① 不需要任何额外元素，所以**任何中间态都成立**（掏空式的窗在板还没聚拢时会浮在空中）；② 醒态散位几乎不相交 ⇒ 醒面干净、梦面才有关节，静态差白拿一档；③ 生成期硬限同一像素最多 3 块板，最浓处不越 35% 红线。
- 静止帧差：01 是一片各自偏开、无任何可读轮廓的方板（且比梦态更松、更凉、更淡）；02 是几个边角对齐的大形体。不是「位置不同」，是「有没有形体」。

## 与 D 稿的差别（继承了什么、解决了哪条不放心的）
- **继承**：固定种子 LCG、14° 正交系做簇心泊松排布、三档尺度/浓度分层、每档的尺寸与浓度区间、`maxDepth ≤3` 抽格核算、`--cx-k` 那套 smoothstep（本稿改名 `--sq-k`）、`?freeze=1` 的确定帧口径、生成后零运行时成本。
- **反转**：D 是「同一个大块被两种方式读出」；本稿是「醒态无块、梦态成块」。运动方向也反了：D 醒态沿 14° 无限平移、梦态归零；本稿醒梦都是各自方向的小幅往返。
- **解决 D 最不放心的第 1 条（归位距离）**：D 为「首尾严格同帧」必须让平移量等于内容周期 2400u，长按把幅度压到 0 时场会沿 14° 拉回最多 2329px。本稿的自走是**净位移 0 的往返**，压到 0 时不存在任何归位位移；散↔聚的位移全部是各块的散位（≤420px）与自走（≤20px），**因此不需要周期副本**——D 的整套「两份内容 + 整周期位移」装置本稿直接不用，节点数因此减半。
- **没沿用**：掏空成 1px 琥珀窗（本稿是叠浓）、周期副本、`.cx-pan/.cx-step` 双层结构。

## 实测
- **版心（42rem，x∈[384,1056]）内背景最亮处 / 相邻墨色亮度差**（同机位逐像素 on/off，W3C 相对亮度；分母同时给标题墨与正文墨）：deep 醒 5.9%/9.8%、梦 7.9%/13.2%；light 醒 21.3%/24.5%、梦 26.6%/**30.6%**；paper 醒 23.4%/24.7%、梦 28.6%/30.2%。**最坏 30.6%**（light 梦，对正文墨），红线 35%。首屏 dream 11.5%、移动端 dream 14.3%。
- 醒态 animation 清单：**105 条，全部是 `sq-solo`**（只有一条 keyframes，不是每块一条）；`?reduced=1` 下本层 animation = 0 且方板停在散位（＝恒醒面构图）。**新增 rAF 调用点 0、滚动/尺寸监听 0、resize 重算 0**（与 `p15-shell.html` 对照：rAF 调用点 1↔1、监听 9↔9）。
- 生成：**130 个 DOM 节点**（105 板 + 25 簇）、单次 **13.1 ms**，此后零运行时成本；5 档模数 / 8px 栅线 / 16px 散位格 / 25 构造体 / 105 板；两次加载构图逐项一致。
- 无缝（钉住 mix 取确定帧，抽样 27 块）：位移均值 317.6 → 268 → 158.8 → 49.6 → 0 px，**除以 mix=1 的均值 = 0.8438 / 0.5000 / 0.1562 / 0.0000 ＝ smoothstep(mix) 到四位**（逐帧证据 `.shots-p16-a-extra/mix-{1,075,05,025,0}-deep.png`）。
- 长按（`.p16-a-extra.cjs interact`，每次按压新开页以避开 sessionStorage 闩锁）：醒→梦 **1300ms** 到位，位移 320→317→252→51→0.5→0；梦→醒 **2200ms** 到位，0→26→142→306→320；按住 600ms 松手**退回**到 320（中途截图 `hold-A-600ms-mid / hold-B-1200ms-mid / hold-C-600ms-before-release`）。
- **8× CPU 降速「有层 / 无层」帧时间**（3 次取中位，页内 rAF 同口径）：8× 滚动 5s p95 **83.4 / 16.8 ms**（+396%，帧数 85 vs 302）；8× 长按 2.4s p95 **266.6 / 33.4 ms**（+698%，帧数 23 vs 113）。**1× 不降速同口径：滚动 16.7/16.8ms、长按 16.8/16.8ms，帧数 301↔301、145↔145 ⇒ 真实机器上满帧、量不出代价**；8× 的增量折算约 4–5ms/帧。

## 最不放心的
1. **帧时间的代价就是「每个方块各自那条动画」的直接后果**（`.p16-a-perf-lab.cjs` 归因：105 条带 var() 的 keyframes 压不进合成器；8× 下有/无层 50–83 vs 16.7ms。同一实验里把自走上提到 25 个簇容器——几何完全等价、簇内 4–5 块共享一条自走——能省约一半，只有「一条动画都没有」才等于无层）。我选了忠实用户原话 + 1× 满帧，并把交换条件写在这里：若裁决要省，把 `.sq` 的 animation 移到 `.sq-cl` 即可，观感几乎不变（醒态散位把同簇方板拉开 150–400px，看不出谁与谁同步；梦态幅度为 0）。
2. 密度（25 构造体/105 板）是我按「克制」定的：要更满或更空只改 `BANDS[].n`（确定性，不动机制）。梦态最坏 30.6% 距 35% 只剩 4.4 个点，paper/light 底再亮一档就得把 6%/13% 往下调。
3. 醒态的「整齐」靠三条人造约束（只取五档模数 + 全部吸附 8px 栅线 + 每块最多轻触一块）。若裁决觉得「太整齐＝太设计」，松开第一条会立刻变成碎屑感——这是同一个开关的两端。
4. 依赖 JS 生成（无静态回退）；`?freeze=1` 下外壳把 `animation-delay` 归零，于是每块停在自走的 **+d 相位**，01/04 的散位比「生成值」再偏 ≤10px（仍是确定帧，但别把它当散位原值）。共用脚本 09 号裁片是文档坐标、落在首屏（四稿同病），我另出了视口相对的 3× 裁片。
