# 首屏原型 · lily：字是一扇窗，里面是花

页面：`/mock/hero-lily/`（`src/pages/mock/hero-lily.astro`，new.astro 副本，只重做场 0）
脚本：`src/scripts/proto/hero-lily.ts`（home-storyboard.ts 副本）

## 思路
醒 / 梦两字不再是「实心 + 波纹 + 外扩细线 + 残影」，而是两扇字形的窗。窗里是**同一片抽象百合**：
- 醒字里是冷色细线稿（花瓣轮廓、中脉、几根花蕊，衬一层极淡的雾蓝）。清楚，但只有线。
- 梦字里还是这片花，融成暖粉色的光斑，花心是一点淡金。

花只在字里出现，字外全是留白。膜不再逐帧跟着波走，而是一道静止的 14° 渐变：醒字贴线的一侧淡出（融化），梦字贴线的一侧由淡渐浓（成形）。
双态：醒面时醒字的窗全显，梦字收到 0.82；梦面时醒字窗降到 0.45、底影变淡，梦字全显、底影加深。两边都只用 opacity 过渡。

## 实现层次（每字三层）
1. `.sil`：字本身，极淡的底色（醒 #5d6c82 / 梦 #c79a8e，透明度约 0.08–0.1），用来托住字形轮廓。
2. `.win`：字形遮罩 `--gm`，与静止的 14° 渐变 `--mb` 求交。遮罩是 canvas 画一次的 PNG，算法沿用原 glyphMasks。
3. `.fl`：花田位图 `--fl`，是一张 SVG data URL，比窗大 40%。百合几何由同一个种子生成，导出两种画法：`svgLines` 和 `svgBloom`。梦字的高斯模糊烘在 SVG 位图里。

花瓣形状：宽腹、尖端带一点外翻；花瓣长度、宽度、开角、弯度都有抖动，透视压扁（tilt）也是随机的，避免放射对称。

## 性能做法
- 去掉逐帧 clip-path 切口、波纹贴图、`feMorphology` 描边、梦字的 drop-shadow，开屏也不再跑 30fps 的 rAF 节拍。
- 遮罩和花田只在初始化、resize、字体就绪时生成；有 key 缓存，内容没变就不重画。
- 动的只有 `.fl` 的 transform 动画（64s / 80s 往返），`will-change: transform`，跑在合成层上。
- 入场 `home-develop` 改成 opacity + scale，不再做 blur(18px) → 0。
- 实测（dev server，1440×900，入场后静置 3s，CDP Performance）：

  | 页面 | 样式重算 | 布局 | 脚本 |
  |---|---|---|---|
  | `/new/` | 123–135 次 | 27–52 次 | 45ms |
  | `/mock/hero-lily/` | 38–73 次 | 19–36 次 | 2–5ms |
  | `/about/`（全站页头等共享动效的基线） | 74 次 | 36 次 | 5ms |

  也就是说，开屏本身已经没有主线程开销了，剩下的来自共享 chrome 和 dev 工具条。

## 已知问题
- 醒字线稿在 1440 宽下偏细偏淡，远看像一团乱线；离近了才看得出是百合。可以试把线宽提到 1.3–1.5px，或减少花的数量、让单朵更大。
- 梦字光斑整体偏灰粉，「百合」的形象几乎认不出来。这是有意的（融化），但也可能只读成「带纹理的粉字」。
- 静态 14° 渐变表达膜比较弱：线不再切字，字和线的关系变得松散。
- 窄屏梦字压在线和问句之间，有点挤（字号和位置沿用原版）。
