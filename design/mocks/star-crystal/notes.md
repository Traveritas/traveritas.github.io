# 晶体六芒星 · 定格翻动 —— 原型说明

日期：2026-11-10 ｜ 目录：`design/mocks/star-crystal/` ｜ 端口：4653

一颗绕水平轴翻动的六支晶体星，姿态量化并保持。这份文档回答四件事：
**白底上哪种材质真的读成晶体**、**每一档的实测代价**、**图层语义怎么立**、**定格能细到什么尺寸**。

```
node design/mocks/star-crystal/serve.cjs     → http://localhost:4653/star-crystal/
```

---

## 0. 一句话结论

> 白底上只有 **`resin`** 能当「一个图层」用：它 0.18 ms/帧、愿意透明、剪影清楚。
> **`cheap`** 更像真水晶（棱面更利、明暗更硬），但要靠一块 12% 透明的底 —— 它读成「一件摆在那里的东西」而不是「一层」。
> **`refract`** 在白底上**必须**吃掉一块方形不透明底才成立，代价 1.0 ms/帧 与一整个 transmissive pass —— 不划算，除非它将来变成页面唯一的主视觉。

推荐的定格参数：**12 步 / 110 ms**（大尺寸 240px）或 **8 步 / 160 ms**（≤64px）。

## 1. 白底上的可读性（这是成败问题）

站点底色 `--bg #f0f3f6` 是一件很苛刻的事：一颗白的晶体要在一张接近白的纸上把自己交代清楚。
唯一能借的东西是**棱面之间的明暗差**，而那个明暗只能来自环境本身。

所以环境贴图不是可选的装饰，是这几档材质能不能成立的前提。`src.js` 里的 `buildEnvMap()` 用一张 1024×512 的 canvas 画了三档：
天顶白 → 地平线亮 → **地面压到 `#454e5c`**，中间撒两三个亮斑（窗）和两三块暗墙。
全是亮面的环境里，白晶体 = 白纸上的白纸。这一点第一版原型就翻车了，记在这里。

### 三档在同一姿态下的对比（`.shots/01-ground.png`）

| | 读感 | 判断 |
|---|---|---|
| `cheap` | 棱面利、边缘硬、明暗对比足。最像「水晶」。 | 成立，但要透明底 |
| `refract` | 内部有真的折射与色散，六支之间能看见被弯折的环境。**最好看的一档。** | 只在有不透明底时成立 |
| `resin` | 磨砂、柔和、边缘有一圈提亮。最像站点自己那套树脂语言。 | 成立，且原生透明 |

### 关键发现：`transmission` 在透明画布上会塌掉

这是整个原型里最要紧的一条，`01-ground.png` 下半排就是证据：

**`MeshPhysicalMaterial` 的 `transmission` 折射的是「同一个场景里」的东西。**
一张 `alpha: true` 的画布里没有地面、没有桌面、没有任何可折射的物体 —— 它把「空」折射出来，
结果是**一片毫无结构的死白**，六支的棱面全部消失，只剩一个轮廓。

对照实验（`.evidence-refract-transparent-canvas.html`、`.evidence-refract-backdrop.html`）四组：

| 组 | 画布 | 场景里有衬底吗 | 结果 |
|---|---|---|---|
| A | 透明 | 无 | **死白剪影**，与 alpha 是否 premultiplied 无关 |
| B | 透明 | 有（一道带色横条） | 极漂亮 —— 但那个横条是我们自己塞进场景的 |
| C | 不透明 | 无 | 有折射，但折射的是清屏色，几乎无信息 |
| D | 不透明 + 清屏色 `#f0f3f6` | 无 | **最佳折衷**：画布与页面无缝，棱面之间靠环境贴图分出明暗 |

结论：**要让 `refract` 读成晶体，画布必须不透明、清屏色必须是页面底色。**
代价是这个元素不再是「一个透明图层」—— 它会挖掉一块 240×240 的方形，
在那块方形里它遮住下面所有的东西（在 `03-layer-refract.png` 的左下那格里，能看见星后面那块方形比周围略深）。

`src.js` 里 `needsOpaqueCanvas('refract') === true`，切到折射档时自动把画布转成不透明；
`canvasMode: 'alpha'` 可以强制转回去 —— 那条失败轨迹本身要能被看见，所以保留了。

### 换来的东西值不值

`refract` 确实最好看。但它买到的「折射」,**大部分来自环境贴图而不是页面**。
换句话说：星星落在对话框上还是落在空白处，它内部长什么样几乎一样。
一个真正的「跨图层折射」（即把 DOM 也折进去）在 WebGL 里做不到 —— 那要用 `backdrop-filter`。

## 2. 实测代价

`.shots/30-measure.png` 是页面里那张表，数据在 480×480 缓冲、DPR 1 上测得。
三档各跑 0.5 s 纯提交 + 0.42 s 带 `gl.finish()` 的合成计时，跑三次取中位数（`.bench.cjs`）。

| 材质 | 提交 ms/帧 | 合成 ms/帧 | draw calls | 三角形 | programs | 画布 |
|---|---|---|---|---|---|---|
| `cheap` | 0.017 | **0.65** | 1 | 384 | 1 | 透明 |
| `resin` | 0.084 | **0.21** | 2 | 768 | 5 | 透明 |
| `refract` | 0.124 | **3.04** | 2 | 768 | 3 | **不透明** |

注：`cheap` 的「合成」比 `resin` 高，是因为 `resin` 是半透明材质，驱动走了另一条更省的路；
这个差别在独显上会被抹平，不要过度解读。**真正要紧的是 `refract` 比另两档贵 5–15 倍。**

### 半价白捡：`resin` 的 transmission 换成了 opacity

第一版 `resin` 用了 `transmission: 0.24`（只想要 24% 的透）。实测发现：

> **只要 transmission 非零，three 就开一遍完整的 transmissive pass。**
> `transmission: 0.24` 与 `transmission: 1` 同价：2 个 draw call、768 个三角形 —— 和 `refract` 一档完全一样。

`.probe` 作业的读数（resin 基线 → transmission 0）：

```
resin transmission .24 → calls 2, tris 768
resin transmission 0   → calls 1, tris 384
```

改成 `opacity: 0.78 + transparent: true` 后拿到同一观感，代价回到 1 个 draw call。
**这是白捡的一半，没有理由不捡。** 也就是文档里那句「transmission 默认不用」的实测依据。

### 定格模式的实际开销

定格模式下星**不是每帧都在画**，而是每 `holdMs` 画一次。所以「每秒占用」＝ 合成成本 ÷ 保持时长：

| 保持时长 | draws/s | `cheap` ms/s | `refract` ms/s |
|---|---|---|---|
| 60 ms | 16.7 | 10.6 | 17.1* |
| 90 ms | 11.1 | 7.0 | 11.4* |
| **110 ms** | **9.1** | **5.8** | **9.3*** |
| 160 ms | 6.3 | 4.0 | 6.4* |

\* 受表格里那一行「合成 ms/帧」的采样噪声影响，这一次的 refract 取值偏低；按上表 3.04 ms 算，110 ms 档应当是 ~28 ms/s，约为 `cheap` 的 5 倍。

**这个量级最值得说的不是数字本身，是它「可以完全归零」** —— 见 §5。

### `refract` 的那一遍值不值得

不值，除非它变成页面唯一的主视觉。取一个对照：全站现在没有任何一个元素常驻消耗 28 ms/s。
文档 §3.3 写的是「最多留给一两个主视觉元素」——这颗星如果是「浮在任何东西上面的一层」，
它按定义就不该是主视觉。**推荐 `resin`；美术上真需要更利的水晶感时用 `cheap`。**

## 3. 图层语义：它凭什么算「一层」而不是「一枚贴纸」

它要能浮在任何东西上面（对话框、卡片、一段正文、页角），所以需要一条规矩说明它和下面怎么相处。
`02-layer-*.png` 是三档材质各自四个位置：

| 叠法 | 读感 | 结论 |
|---|---|---|
| **压在立牌上沿** | 边界最清楚，但也最像一枚贴上去的贴纸。 | 能用，但最平 |
| **躲进磨砂玻璃后面** | 星被 `backdrop-filter` 糊成一片更亮的雾。**这是「它是一个层」唯一确凿的证据。** | 最好的一个，代价是细节全丢 |
| **被页面边裁掉一截** | 只露一部分，剩下的交给想象。最像「还有别的深度」。 | 观感最好，也最省地方 |
| **放在纯页面底色上** | 什么都不压，只和底色相处。 | 回答「它自己站不站得住」 |

### 三条由此得出的规矩

1. **它可以压在内容之上，但不要压在可读的文字上。**
   240px 的星压在正文中间，那段字就废了。`02-layer-cheap.png` 左上那格就是这个反例。
2. **「在磨砂玻璃后面」是这一个原型最值钱的一格。**
   如果这个图层将来只能有一个位置，选这个 —— 它同时交代了深度、交代了站点自己的玻璃语言，
   而且被糊掉的细节反而让它不抢戏。
3. **`refract` 与「藏在玻璃后面」互斥。**
   它自带不透明底，放后面会把整块玻璃挡掉。页面里那一格标了「折射档在这里没有位置」。
   **这是选择 `resin` 的第二个理由** —— 它才能进到玻璃后面。

### 与页面边界的相处

裁切那一格用 `mask-image` 做底部渐隐。这是唯一让星「待在页面里而不是页面之上」的做法：
它有一部分不在，而不是浮在边上。建议将来真的落地时，星至少有一边越过某个容器的边界。

## 4. 定格：参数与尺寸阈值

### 时钟

姿态量化到 `360/steps` 的格子，每格保持 `holdMs` 不动。一圈之后的那个保持格 × **3.2**（呼吸停歇）。

这个 3.2 不是编的，是照 `brand.ts` 抄的：`CYCLE_WORDS` 7 步轮转，第 0 步之后 `BREATH_PAUSE_MS = 3000`，
而正常节拍 `CADENCE_MS = 1000` —— 也就是 **3×**。同一个「走几步、停一下」的节奏。
`SiteHeader.astro` 的 `brand-pixel-float` 是 `step-end` + 整像素位移，`Eeg.astro` 是每 0.25 s 采一次样并零阶保持。
**这个仓库里的「定格」＝ 运动在离散的保持步骤里推进，不补间。** 这颗星用的是同一套语法。

因为姿态是离散的，`StarLayer.start()` 用的是 `setTimeout` 链而不是 rAF：
每格画一次，下一次唤醒按「这一格还剩多久」排。标签页被藏起来再回来，位置由时钟推出来，不会错格。

### 翻转轴

`axisVector('x')` 是水平轴；`'diag'` 是 (1,1,0) 方向的对角轴。
绕 X 轴翻、又带一点缓慢 yaw，观感是「一件东西在自己翻面」；绕对角轴更像「一颗宝石被转着看」。

yaw 每转满一圈只走 **46°**，刻意不取 90 的倍数：这颗星是八面体对称群，绕 x 转 90° 会与自身重合。
若 yaw 也不动，`steps = 8` 的一圈里就只有 2 个不重样的姿态。偏一点，四个四分之一圈才各自不同。

### 步数与保持时长的推荐

| 场景 | steps | holdMs | 一圈 | 说明 |
|---|---|---|---|---|
| **大尺寸 180–240px** | **12** | **110** | 1.54 s | 相邻格 IoU 0.37，六格全不重样；够慢，读得出「停」 |
| 同上，要更慢更稳 | 12 | 160 | 2.24 s | 更明显的定格感，单圈略拖 |
| **小尺寸 ≤64px** | **8** | **160** | 1.6 s | 格子少、每格差得远，小尺寸下反而认得出方向 |
| 想要连续感的对照 | 24 | 60 | — | 太快，读成闪烁 |

`steps = 24` 在 240px 下能用（相邻 IoU 0.50，还能分），但 60 ms 太快；要 24 步请配 ≥110 ms，一圈 3 s 以上就拖沓了。
**不推荐 16**：它在任何尺寸下都处在「既不够细、又不够狠」的中间地带。

### 尺寸阈值（实测，`.shots/grain.json`）

量的是：把每一格渲染成剪影，算**相邻两格的 IoU** 与**整圈最像的一对**（重复度）。
`.shots/08-grain.png` 是 24/32/48/64px 全部姿态的可见版本。

| 尺寸 | 8 步 | 12 步 | 16 步 | 24 步 |
|---|---|---|---|---|
| 240 px | 0.30 | 0.37 | 0.41 | 0.50 |
| 96 px | 0.31 | 0.38 | 0.42 | 0.52 |
| 64 px | 0.32 | 0.39 | 0.43 | 0.53 |
| **48 px** | 0.33 | 0.40 | 0.44 | 0.54 |
| **32 px** | 0.35 | 0.42 | 0.46 | **0.56** |

（相邻格 IoU 均值；越小＝相邻两格越不像）

**阈值结论：**

- **64px 是下限。** 往下剪影不再彼此区分 —— 32px 时所有档位的相邻 IoU 都爬到 0.42–0.56，
  也就是「相邻两格有一半是一样的」，定格不再读成翻动，读成一个抖动的点。
- **48px** 勉强可读，但只支持 **8 步**（IoU 0.33）；12 步以上（0.40）就开始糊。
- **32px 以下这个做法不成立。** 那时六支的剪影已经塌成一个带毛边的星点，
  环境贴图带来的棱面明暗全部丢失（看 `08-grain.png` 最下面两行）。
  这个尺寸该退回 2D —— `toolstar.ts` 的 `drawStar()` 在 48px 上比这个 3D 版本清楚得多。

一句话：**3D 在这个尺寸换不到任何东西。** 页角、行间那种尺寸用 2D 星；3D 只在 ≥96px 时有意义。

### 连续 vs 定格

页面控件里有「连续 · 对照」。切过去看一次就够了 —— 差别非常明显：
连续旋转是一颗「漂浮的物体」，定格之后才变成一个「在翻面的东西」。
停留感来自**静止本身**，不是来自减速。这也是为什么 `holdMs` 是主导参数、`steps` 是次要的。

## 5. 诚实的话：常驻 rAF 行不行

**不行 —— 而且这里根本不需要 rAF。**

这个站点对空闲帧的计较从注释里就能读出来：`toolstar.ts` 的帧循环「只在有东西在动时运转」；
`Eeg.astro` 把波形挪进 Worker，「主线程静置时完全空闲」；`brand.ts` 在醒来时连动画都撤掉
（「连动画都不在」）。在这种口径下，一个常驻 rAF 是明确越线的。

定格模式在这里有个天然优势：**它的姿态是离散的。** 每格画一次就够，
格与格之间是完全静止的 —— 画面上没有任何东西在变。所以：

- **定格模式：不用 rAF**（已经这么实现了）。`setTimeout` 链每格醒一次，110 ms 档 = 9.1 次/秒，
  每次 0.21 ms（`resin`）。**每秒约 1.9 ms**，且格间零占用。
- **连续模式：必须 rAF**，60 fps × 0.21 ms ≈ 12.6 ms/s。仍不算多，但它是「永不停机」的那一类。

### 建议的休眠策略

1. **`IntersectionObserver`**：滚出视口就 `stop()`，进来再 `start()`。这是文档 §3.3 已经写明的规矩。
2. **`prefers-reduced-motion`：画一张静帧就停。** 用 `freeze(k)`，选一个最好看的格（推荐第 2 格）。
   注意：定格虽然是离散的，但它仍然是动画 —— 不能因为「只是跳一下」就不尊重这个偏好。
3. **页面隐藏时停**：`visibilitychange` 里停表；回来时按时钟重推姿态（已经实现，不会错格）。
4. **不做「只在交互时动」**：这颗星如果只在被碰的时候翻，它就退化成一个装饰按钮，
   失去「自己在那里慢慢翻」的那层意思。**建议：随可见性休眠，不随交互唤醒。**
5. 再加上全局一个：**整个图层在 `prefers-reduced-motion` 下可以干脆不挂载**，
   退回到 `toolstar.ts` 的 2D 剪影。这是文档 §7 的「移动端降级阶梯」同一条路子。

## 6. 别的东西

### 一处文档与代码的不一致

`docs/tech-stack-decision.md` §3.3 与 §7 都写「`transmission` 折射材质昂贵、默认不用（最多留给一两个主视觉元素）」
—— 方向对，但**「昂贵」的具体数字原文没给，而且它其实不是「按 transmission 的量线性变贵」，
而是「非零即全价」**。`resin` 一档就是活例子：0.24 的 transmission 和 1.0 同价。
将来如果有人想「只来一点点折射」，这条实测能省一次返工。建议把这一点补进文档。

### 这个原型里没做、但落地时会撞上的

- **`backdrop-filter` 里的星**：`behind` 那一格靠 CSS 的 `backdrop-filter` 去糊 canvas。
  真机上 `backdrop-filter` 与 WebGL canvas 的合成有已知的性能与层级坑（尤其 Safari），这里只验了 Chrome。
- **共享画布**：文档 §3.3 提到用 scissor/viewport 把多个 3D 元素画进一个上下文。
  `mountGrid()` 里那套 `setViewport`/`setScissor` 循环就是这个技法的雏形（一画布 N 格），可以直接复用。
  但要注意：`StarLayer.draw()` 会把 viewport 铺满整张 canvas，多格共用时必须自己管好 viewport ——
  原型第一版就踩了这个坑（`probe()` 里补画一次，结果留下一颗盖住全表的巨星）。
- **没有做真实页面的视觉验收**：这个原型只在 `#f0f3f6` 纯底色上验过，
  没有叠到站点真实的页面（有 14° 缝线、脑电波、漂移背景）上。那一步的观感可能完全不同。

### 自检

页面暴露 `window.__star`：`probe()`（各画布覆盖率 / 对比度 / draw calls）、
`freeze(k)`（钉住第 k 格）、`setState({...})`、`measure()`。

`probe()` 的判据是「这个像素和清屏色差多少」而不是 alpha —— 不透明档的 alpha 恒为 255，
用 alpha 判断会得到「全都画上了」的假阳性。这是第一版的原型自检骗过自己一次的地方。
