# p14-d 星野标尺（Reticle Field）· 候选背景层 · 自验收

**一句话主张**：把「版心边界 + 左轨四个深度档 + 14° 缝线」这三组在滚动中恒定不变的几何，延长成一片极淡的观测场——它在测量这一页，而不是撒在背景上。

**醒（--reality-mix=1）**＝一片整齐的极淡秩序：零位移零呼吸，四根版心量线、四根深度线、四枚十字测量站落定，琥珀退成冷灰（沿用 reality.ts 的强调色插值）。**梦（=0）**＝同一片场按拍子活过来：每根线／每枚站各自 steps(1,end) 阶跃微移（±1.5 或 ±3px，周期 6.4–10.3s 各自错开，整体永不重复成同一拍），两枚琥珀节点按 7.3s 阶跃呼吸；位移一律乘 `--still`，长按入醒时随醒度归零。

## 标尺与页面内容的关系：选了哪三种、为什么

1. **纵向量线 4 条＝版心边缘本身**：`left: max(1.5rem, 50vw − 21rem)` 正是 `.container`（min(100%−3rem,42rem) 居中）左缘的精确解，56rem 同理；刻度朝版心外伸。实测本体 383px、容器左缘 384px（1px 内）。
2. **横向深度线 4 条＝左轨仪表的四档**：加载时量 `.rail .meter-label` 四枚标签盒中心写 `--depth-1..4`，起点取标签右缘 +7px。实测标签中心 y＝424.1/491.7/551.7/619.7，四条线 top＝424/492/552/620（±1px 为抽帧位移）、自 x=98px 起（标签右缘 90px）。标尺与左轨是同一把尺。
3. **十字测量站 4 枚＝①×②的交叉点**（56l×醒 / 42l×深眠 / 56r×浅梦 / 42r×晨醒），长短臂 2:1、中心留空 10px、线宽 1px、整体旋转 14°（长臂平行缝线），其中两枚嵌琥珀节点。

**为什么不选「账目行线／段落节律」**：本层是 `position:fixed`（必须——`.page` 被微沉加 transform 时会劫持 fixed 后代），fixed 层只能与同样视口锚定的东西保持真关系；文档流的行线与段落节律跟它不在一个坐标系，硬对齐只是"看起来像对齐"，正是 p13 的病。

## 实测三条

1. **背景层最亮处／相邻正文墨色亮度**（同帧采样，ΔL 相对亮度差之比，上限 35%）：标尺本体——深眠·梦 13.2% / 深眠·醒 9.2% / 光面·醒 15.9% / 纸面·梦 19.7%；琥珀节点 13.3 / 20.0 / 22.3 / 23.0%。**全场景最大 23.0%**（节点），标尺本体 ≤19.7%。第一轮同一探针读到 99.8%——取样横带压在玻璃卡与纸缘上（把卡片当成了底色），修正取样才得上表。
2. **梦态可辨识度**（同机位、全站动画静场后只改标尺相位 600ms↔3400ms，无正文横带内）：无层基线 0 像素变化（噪声地板＝0）；`small` 位移均值 **0.74px**（峰 3px）、733 像素变化＝横带 0.73%；`large` 位移均值 **1.47px**（峰 5px）、775 像素＝0.77%；两档 ΔL 峰同为 0.099（＝相邻墨色的 13.5%）——**亮度冲击完全相同，差别只在"走了多远"**。另出 25% 缩图与 3× 近观裁片复核（13/14 号）。
3. **8× CPU 降速、滚动 5 秒**（headless＋`--disable-gpu` 软件光栅）：有层 p95 **433ms**、最长帧 **467ms**（≈8.1fps）；无层 p95 **317ms**、最长帧 **333ms**（≈9.9fps）。诚实补充：同配置复测（层关闭两次）p95 落在 300–383ms、9.9–11.4fps，**环境自身抖动就有 ~40%**，有层与无层的差落在该带内；可说的是没有量得出量级的额外代价，且结构成本可控：全层 34 节点、零 backdrop-filter、零大面积 filter、位移为阶跃（每元素每 1.6–2.5s 才变一次 transform）、无新增常驻 rAF。

## 推荐哪一档抽帧、判据是什么

**推荐 `jit=large`（±3px）**，`?jit=small` 留作最保守档。判据：① 两档 ΔL 峰相同（0.099），"闹不闹"不由幅度决定；② small 实测位移均值 0.74px 是亚像素级，13% 对比度的 1px 发丝线走 0.74px 正是上一轮「看不见」的翻版；③ 节拍很慢（6.4–10.3s 一周期四步，约每 1.6–2.5s 一步），3px 一跳读作"按拍子挪一格"（本站的像素＝时间的量化）而非抖动；④ 25% 缩图与最亮处读数都显示它没有抢戏。判"看得见但不闹"用的就是这三件工具：静场相位差的像素统计（位移／受影响面积／ΔL）、25% 缩图、3× 最近邻裁片。

## 已知不足

- `.prose` 段自身的 34em 量程没有单独成线（只量 42/56rem 两级），正文列右缘缺一枚刻度。
- 深眠面读数抖动偏大（同一条线同一处：醒 9.2% / 梦 13.2%）——抽帧相位让刻度与本体交角落在整像素或半像素上，AA 不同；这也是刻度与本体之间留 2px 的原因。
- 无 JS 时 `--depth-N` 只能用 CSS 兜底档（50svh±），左轨对齐要等 JS；首屏 under（-4）下标尺被千层纸整幅挡住（真层序的结果，也是产品选择：观测场自随笔段起浮现，`?layer=through` 是它在首屏的样子）。
- RM 下真站点会让左轨立刻浮现，首屏于是出现「装饰左轨＋全局左轨」两套站名（真站点自身行为，照抄未改，见 08-rm-wake.png；内容段无此问题 20-rm-content.png）。
- 未复刻首屏指针视差与 REM 段 WebGL 玻璃签（与本层无关，省去以免干扰测量）。

## 相对 p13 失败点的针对性修正

- 无控制台／遥测／卖点：默认视图只有页面本身，调试件是右下角一枚 12×2 的 14° 小划（opacity .5，hover 才亮），截图一律 `?ui=0`（16/17 号是它的自检照）；文案全部取自 `index.astro` 与 `src/content/`（含一篇完整 `.prose` 正文）。
- 「看不见」反过来治：刻度是真的刻度（1px 本体＋短 9px/1u、中 16px/5u、长 26px/10u＋十字站），并用像素探针把"最亮处占相邻墨色多少"钉进 35%；画面文字只剩 `42REM`/`56REM`（度量，Silkscreen 8px，仅此两处）与醒/浅梦/深眠/晨醒（左轨原有分期词），没有"逻辑真值／命题坐标"式标签。
- 无全屏 blur：本层零 filter 零 backdrop-filter，随笔段玻璃片也去掉 backdrop-filter；层 fixed 且挂 `.page` 之外，under=-4（与墙同层、纸之下）/through=-2（纸之上、脑电与缝线之下）两种都出首屏截图（01/02 vs 12/18/19）；三段夜色 `?zone=light|deep|paper`（三套色板＋各自 `--rt-a` 标定），矩阵 01–06、13–15。

## 第一轮自验收：看到什么、怎么改

- **刻度太密太亮**：三层刻度叠画在同一 y 上、alpha 相乘，长刻实际到 55% 而非设计的 33%，整页像坐标纸。改：三档落在互不相同的 y 上（短刻避开长/中刻位），单位从 gap-v/4 放到 gap-v/3，横向深度线砍掉密排短刻只留 5u/10u——最亮处从 30% 掉到 13%，形态从网格纸变回一把尺。
- **深度线与左轨其实没对齐**：第一版按"仪表垂直居中"推算，实测差 60–160px。改成加载后量标签盒写 `--depth-N`，现在线就长在四枚标签上。
- **小签不该跟着抖**（文字位移最易被注意、收益为零 → 线动、字不动）；首屏 under「什么也看不见」曾被当成 bug，确认是真层序的结果后补了 through 与 12/18/19 对照。
