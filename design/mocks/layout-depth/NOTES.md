# 景深叠层 · 原型笔记

三个并行版式原型之一：每条内容是一片磨砂玻璃，全部沿 Z 轴叠放。滚动＝向前穿过这一摞；
侧看＝相机转到侧面，一排玻璃的边就是目录；展开＝玻璃铺满，字分几档从霜里析出。

## 运行

```bash
node design/mocks/layout-depth/serve.cjs          # → http://127.0.0.1:4613/
node design/mocks/layout-depth/build.mjs          # 改了 index.src.html 或 src/content/ 后重新生成 index.html
node design/mocks/layout-depth/.shot-depth.cjs    # 截图到 .shots/（puppeteer-core 取 %TEMP%/node_modules，同 hours 原型）
```

服务器根目录是仓库根：字体直接用 `public/fonts/noto-serif-sc/` 与 `node_modules/@fontsource/ibm-plex-mono/`，不复制。

| 文件 | 作用 |
| --- | --- |
| `index.src.html` | 页面骨架（外沿、阅读层），`<!--STACK-->` 处由生成器填入薄片 |
| `build.mjs` | 只读 `src/content/`，把真实标题、日期、描述、标签、正文（醒面）渲染成静态标记 |
| `index.html` | 生成结果，无 JS 时就是一份完整可读的名录 |
| `depth.css` / `depth.js` | 样式与引擎 |
| `assets/` | 瞬间配图的缩小版（1000–1100px 宽 JPEG） |
| `.shots/` | 截图 |

内容：随笔 2（《在显影处：三个声部》全文、《字面与光景 · 全样式样张》全文）、项目 2、瞬间 3（含 1 张、4 张、无图三种）、关于 1。
关于页正文现在是测试占位，原型里改用 `personal-website.md` 的醒面引言与 note。`:::dream` 块一律略去，`[[醒|梦]]` 取醒面。

操作：滚轮 / 触控滑动 / ↑↓ PageUp PageDown 空格 j k Home End 移动；回车或点击正中那片展开；Esc 收起。
侧看：右上「侧看」按钮、`-` 键、Ctrl + 滚轮外推（触控板捏合）；侧看里 ←→ 选片、回车或点边飞回、Esc / `+` 回到正面。
地址：`#co-creation-notes`（停在某片）、`#co-creation-notes/read`（展开）、`#index`（侧看）。

## 1 · 景深与叠放参数

| 参数 | 宽屏 | 窄屏（<700px） | 说明 |
| --- | --- | --- | --- |
| 薄片尺寸 | min(800, max(560, 54vw)) × min(500, max(380, 56vh)) | (vw−36, ≤460) × min(56vh, 540) | 位置取整像素 |
| 透视距离 P | 1200px | 820px | 舞台 `perspective`，原点在薄片中心 |
| 片距 D | 680px | 560px | 相邻两片的 Z 距离 |
| 版块间多出的雾距 G | 0.85 D | 0.85 D | 跨版块那一段相机要多走一截，雾层在正中 |
| 上浮 RISE | 0.42 | 0.34 | 越深越往上：在前片上沿露出一级级玻璃边 |
| 横向漂移 | −0.03·d | 同 | 远处略向左 |
| 抖动 | x ±26px，y ±14px，rotZ ±1.1°，rotY ±5° | 同 | 乘 min(1, \|d\|/D)：正对时归零，所以聚焦片永远方正 |

d＝薄片 Z − 相机 Z（正＝在前方等待，负＝已经穿过）。

| 距离 | 模糊 | 不透明度 |
| --- | --- | --- |
| 前方 d ≥ 0 | min(16, (d/D)^1.15 × 4.4) px | 1 − max(0, d/D − 0.45) × 0.26；d > 5.4D 剔除 |
| 穿过 d < 0 | \|d\|/D × 16 px | (1 − \|d\|/(0.5P))^1.4，随放大一起化开 |

**近处与远处两种虚法。** 近处（前方 < 0.72D，或刚穿过 < 0.22D）：玻璃保留 `backdrop-filter: blur(20px) saturate(1.12)`，只给字面加 `filter`；
远处：整片 `filter: blur()`，不开 backdrop（`filter` 会让子元素的 backdrop 失效，而远处的片本来就在前片的霜后面，看不出差别）。
所以同一时刻最多 2 片在算 backdrop（聚焦片 + 下一片），再加雾层一个。

**相机。** 原生滚动只给目标：每片一屏高（100vh），`scroll-snap-type: y mandatory` + `scroll-snap-stop: always`，所以一次滑动只走一片。
相机在 rAF 里指数阻尼追目标（τ = 120ms），所以停下时有一点缓缓落定的余势。

**字的清晰度。** 滚动停稳（吸附位置 ±2px、相机 ±1px、持续 140ms）后，聚焦片 `transform: none`、`will-change: auto`，浏览器按 1:1 重新栅格化：
截图 02 / 08 / 09 / 16 里正文是锐利的。飞行中字面是虚的，本来就不在阅读状态。

**位置读数。** 顶部中央「随笔 · 可言说的 01 / 08」随最近的一片实时更新；左侧细刻度轨可点。

## 2 · 版块之间的雾

- 每个版块边界一张雾平面（260vw × 260vh 的径向渐变），放在两段的正中，和薄片一样受透视。
- 不透明度：前方 0.97 × smooth(2.6D → 0.05D)，穿过后 (1 + d/0.3P)^1.6 迅速化开。
- 雾里刻着版块名与徽标（「项目 · 可构造的 · BUILDABLE」），离雾 0.55D 以内开始散开，走进雾里时字已经不在了。
- 雾在近处（−0.4P < d < 0.9D）开 `backdrop-filter: blur(14px)`，径向遮罩柔化边缘，把雾后的下一版块整个压虚。
- 雾色是发光的，不是两段底色的中间灰：进深眠前冷白 `rgb(214 221 234)`；深眠→异相暗处一团淡紫 `rgb(86 80 112)`；回晨光前暖白 `rgb(250 243 232)`。
- 天色：按相机深度在相邻两片之间插值，只在 30%–70% 这一段换（smoothstep），也就是在雾最厚的地方完成。色值取 `hours.css` 的四个时辰，入口用 tokens 的昼面略压一档。
- 外沿（品牌、位置、按钮、刻度轨）的墨跟着天色插值，只写在这几个元素上，不写根节点变量。

## 3 · 侧看（目录）

- 过渡 1250ms（飞回 1150ms），easeInOutCubic，单一进度 u 驱动所有量。
- 宽屏绕 Y 轴转 79°（一排竖立的玻璃边，从左到右是随笔→项目→瞬间→关于），窄屏绕 X 轴转 82°（一列横躺的玻璃，从上到下）。
- **推拉变焦**：透视从 1200 推到 6000，相机同步后退到缩放 0.62（窄屏 0.7）。原因：P = 1200 时靠近相机的那几片会被看成背面
  （`backface-visibility: hidden` 下直接消失）；长焦近乎平行投影，每片都只露一条匀称的边。转的过程里能看到透视在变平，像镜头拉远。
- 片距压缩到整摞占屏宽 74%（≤1180px），窄屏占屏高 70%；抖动、上浮、雾、模糊全部随 u 归零。
- 面上的字退到 0.08，图留 0.8（瞬间的配图在边上还看得出颜色）。
- 刻名：每片离相机最近的那条边投影到屏幕（脚本里手算同一套透视），标题沿边竖排（窄屏横排在边的上方），附日期；逐个 45ms 错开浮现。
  版块题签在每组下方，带一条发丝线。当前片的刻名与玻璃边带一线琥珀。
- 侧看时的天：四段夜色按各片在屏幕上的投影位置铺成一条横向（窄屏纵向）渐变。
- 点任一片或刻名：相机在侧看的掩护下先跳到那一片，再整摞转回正面，落地即是停稳状态。

## 4 · 展开（阅读）的编排

| 时刻 | 发生的事 |
| --- | --- |
| 0 | 聚焦片的面与玻璃 160ms 淡去；阅读层的玻璃以薄片的屏幕矩形为起点 |
| 0 → 620ms | 玻璃的 top/left/width/height 过渡到全屏（四周留 18px，窄屏贴边），cubic-bezier(.22,.72,.12,1)，圆角 6→8px |
| 400ms | 字开始析出：四个离散档，每档 130ms，没有连续过渡 —— 模糊 8 / 3.5 / 1.2 / 0px，不透明 .32 / .62 / .88 / 1 |
| 530ms 起 | 瞬间的图比字慢一档：模糊 26 → 14 → 6 → 2 → 0px，饱和度同步回升 |
| ≈ 1.1s | 定稳：`filter: none`，正文是普通文档流，清晰 |
| 收起 | 字倒退四档（每档 70ms）→ 玻璃 500ms 回到原位 → 薄片的面 120ms 浮回 |

阅读层的玻璃比薄片厚（不透明度约 0.6–0.78，backdrop 30px），后面那一摞只剩一点影子；正文列 36em，Noto Serif SC 17px / 2.0，两端对齐，
小节序号用琥珀小号等宽，引文、代码、表格、任务清单都按 `content-typography` 的方向做了简版。
瞬间的阅读层是左图右字（图收在 74vh 内，四图 2×2），窄屏改为上图下字。阅读层有自己的滚动，页面滚动锁住。

## 5 · 减弱动效 / 无脚本 / 窄屏

- `prefers-reduced-motion`：不飞行。玻璃原地不动（相邻两片同位），滚动时只有字面在中点前后先淡出再淡入；侧看与回正直接切换；阅读层 300ms 淡入，字一次到位。
- 无脚本（`html.nojs`，截图 28）：一列居中的名录，各版块有标题与徽标，深色时辰的版块落在各自的深底上；随笔与项目的正文就地展开，瞬间的图不加霜。
  标记就是生成的静态 HTML，Astro 里同样能产出。
- 390px（截图 21–26）：竖滑穿过；侧看绕 X 轴；提示文案换成「上滑，向前 · 轻触展开」。

## 6 · 性能

实测（无头 Chrome，AMD Radeon 610M 核显，1440×900）：从入口一路飞到关于（8 段，含 3 次穿雾），rAF 间隔均值 16.8ms，p95 16.8ms，最长一帧 33ms。
390px 手机仿真 + CPU 4 倍降速：同样的数字。注意这是主线程帧间隔，合成器掉帧要用真机 DevTools 再看。

做法：
- 每帧只给有变化的值写样式（逐片缓存上一帧的 transform / opacity / filter / z-index 字符串）；相机静止且无过渡时整个 render 跳过。
- 同时最多三处 `backdrop-filter`（聚焦片、下一片、雾层）。远处整片 `filter`。超出范围的片 `visibility: hidden`。
- 不用 `preserve-3d`：每片是透视舞台的直接子盒，相机变换并进各自的 transform；绘制先后按深度写 z-index。
- 侧看过渡期间每帧改一次舞台的 `perspective`，会让全部子层重算变换，1.25s 之内可以接受。

踩过的坑（迁移时会再遇到）：
1. `perspective` 只作用于直接子盒。薄片外面包着 `<section>`，一开始透视完全不生效（远处的片和近处一样大）——有脚本时给版块 `display: contents`。
2. 舞台用 `overflow: clip` 时透视同样失效（Chrome），只能用 `hidden`；而 `hidden` 是滚动容器，浏览器按 `#锚点` 会把舞台内部滚走，脚本里归零。
3. 浏览器自己的锚点跳转会把文档滚回顶部（目标在 fixed 舞台里）。有脚本时把薄片的 id 挪进 `data-id`，地址由脚本解析。
4. 移动端载入时视口会抖一次 resize，重排时要保持「变化前的那一片」，不能用初始的 focus。

风险：Safari 对 3D 变换元素上的 `backdrop-filter` 支持不稳，需要真机看；低端安卓同时三层 backdrop 可能吃力，可退化为只给聚焦片开。

## 7 · 好的与不好的

好的：
- 前进的手感成立：前片放大、变虚、从下方化开，后片从上方缓缓落到正中，停下时变得锐利。
- 版块边界很明确：穿过一团发光的雾，出来时天色已经换成下一段夜。
- 侧看是一个真正能用的目录，而且和正面是同一个空间，不是另一张页面。
- 读的时候就是一页干净的正文，没有 3D 在干扰。

不好的 / 没做的：
- 随笔与项目的薄片正面大片留白，正文摘录没有放上来；一摞里的每一片长得很像。
- 内容多了以后（几十篇随笔）这一摞会很深：一片一屏的滚动太长，侧看也排不下。需要「版块内压缩片距」或侧看里横向再滚一层，原型没做。
- 浅梦→深眠那团雾正中仍偏灰（底色插值到中间是灰的，雾只盖住中心）。
- 侧看时刻名压在相邻那片玻璃上，瞬间那组（三片挨得近、带图）略挤；窄屏的刻名和图有一点重叠。
- 醒梦两态（`[[醒|梦]]`、`:::dream`、入梦检验）没有接，原型只读醒面。
- 阅读层是 `aria-modal` 的对话框，但没有焦点圈定；屏幕阅读器读到的是 DOM 顺序的整份名录（这一点反而是好的）。
- 近处 / 远处两种虚法在 0.72D 处切换，慢速滚动时偶尔能看到下一片的霜感轻微一跳。

## 8 · 待定的问题

1. 一片一屏是否太慢？可以改成一屏走 0.6 片、吸附仍按整片。
2. 正面是否要露出更多摞（现在实际只看得到后面一片的上沿，第二片起就在雾里）？RISE 调大会更像台阶，但更像「卡片堆」。
3. 侧看的方向：宽屏现在是从左到右按版块排，是否要按时间（整夜）排、把入口放到最左？
4. 关于页现在只是一片；是否让最后一片之后还有一段晨光（页脚）？
5. 瞬间的薄片要不要直接是图（无玻璃字面），只在边上刻日期？

## 9 · 迁进 Astro 站点需要什么

- **路由与静态产物**：主页（或一个新的 `/stack/`）用 `getCollection` 产出与 `build.mjs` 相同的标记 —— 每片一个 `<article>`，正文放在片里（无 JS 即是名录）。
  正文直接用各集合的 `<Content />`，两态语法、浮起 / 流光、小节序号都走现有 markdown 管线，不用原型里的简化渲染器。
- **单篇页面仍然要有**：`/articles/<slug>/` 等保持现状（RSS、分享、搜索），叠层里的「展开」是同一份正文的就地阅读；
  地址可以从 `#slug/read` 改成真正的路由 + View Transitions，或者保留 hash 只作为叠层内状态。
- **脚本**：`depth.js` 改成 `src/scripts/depth.ts`，与 `reality.ts` 共存时注意它会每帧写根节点上的 `--reality-mix` 等变量 ——
  叠层每帧只写各自元素，不碰根节点；但两者同时动画时要测一次帧时间。
- **与导览轨**：`Gauge.astro` 的滚动进度 / 节点 / 筛选可以直接接到叠层的「第几片」，原型左侧的细刻度轨就是它的最小替身。
- **色板**：已经在 `hours.css`；叠层需要按相机深度插值，所以时辰不再由 `data-hour` 静态决定，而由脚本写在天空层上（无 JS 回落到 `data-hour`）。
- **图片**：瞬间配图走 `astro:assets` 出两档（薄片上的小图带霜、阅读层的大图），原型里是手工缩的 JPEG。
- **字体子集**：`scripts/fonts.mjs` 按站内用字切分，新文案（侧看、提示、雾里的字）要进子集。
- **验收**：`npm run build` 后用 `.shot-depth.cjs` 同样的路径截图；真机上看 Safari 的 backdrop + 3D、安卓中端机的帧率。
