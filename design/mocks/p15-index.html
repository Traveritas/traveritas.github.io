PHASE 15 · 背景双态无缝变换 · 第三轮

四稿并置：把「两态差」从有／无换成采样方式，并且量出它

你说「状态之间的区别不是很明显」。这句话这一轮被量出来了：在今天站点的背景下， 醒梦两态的静止帧里，没有 一个像素的亮度差超过 ΔL 6（峰值 7.7，来自那 7% 的 --wash 洗染与颗粒）——两态差几乎全部长在文字层，空间层是平的。 本轮四稿的共同口径是：两态差不再靠「有／无」，而靠「同一个东西被两种方式读出」； 醒态保持克制但在场，梦态是同一场的抽帧、点亮与量化；并且必须随 --reality-mix 连续插值、中途松手可退回。

裁决先给结论

  1. B 谐波残影是这一个方向上最该上的一件——醒态逐字就是线上现状（路径字符数 863，与 Eeg.astro 实测同相位同字符串），梦态是同一条线被采样成直角阶梯、身后再分出三道带延迟与色差的冷暖残影。 它是四稿里唯一「只变了 1.1% 的像素，却让 0.43% 的像素越过 ΔL 20」的稿子——单点冲击最强，而且 每帧路径开销比线上还低（醒 0.0124ms / 梦主波 0.0109ms）。
  2. C 磨砂晶面是面积最大、最"铺得开"的一件——背景下 25.1% 的像素越过 ΔL 6、4.51% 越过 ΔL 20 （四稿之最），且醒态不再隐身：两片晶面收成 1px 边界 + 四角标记 + 重叠区的 14° 交角斜记。 它还做了本轮最巧的一处设计：让 14° 缝线在晶面内部多出一段被平移 9px 的折射延续段 （实测夹角 0.137°、法向位移 9.46px，只在晶面内可见）——线从玻璃里穿过去时折了一下。
  3. D 构块场（你自己提的方向）落地得最完整——程序化生成 472 个节点、固定种子可复现、 交叠处被解析求交后掏空成一枚枚琥珀描边的窗（这一条让静止帧一眼可辨，不只是"动/不动"）， 醒态沿 14° 同向视差、梦态平移归零改为 steps(1,end) 原地阶跃； 平移的首尾用"内容复制两份 + 整周期位移"做到 t=0 与 t=T 逐像素零差。代价写在卡片里（醒态最吵）。
  4. A 星野微光尘粒对「醒态克制」最忠诚，但静止帧的两态差最含蓄——醒态只占相邻墨色的 6.9–7.3%（上一轮 p14-D 是 9.2–19.7%，被判偏离克制），秩序感最好、最像"背景元素"； 但它 18.8% 的面积差里只有 0.24% 越过 ΔL 20（四稿最低），且琥珀尘粒压在版心左缘时最坏对比度 3.46:1。 A 的问题是可以调的（提 alpha 即可），另外三稿的"醒态克制"反而不好补。
  5. 建议组合：B（点）+ 一件场（D 或 A）——B 给缝线上那一个"钟"，让你本来就在看的那条线 把"现在在哪一面"说清楚；D／A 给整页的空间。B 在两套组合里都在，因为它是唯一一件不增加开销、 且把"现状"本身变成醒态定义的稿子。要不要让醒态也在动（D 是唯一做到的），是你的裁决。

下面每张卡都有诚实的「最不放心的」，那是原作者自己写的，不是我的转述。 我的独立复核（.p15-verify.cjs，四稿 + 外壳同口径）在卡片之后。

  • 主会话修了两处共用 bug（四稿都已回写）：① 外壳 latch() 没有像 reality.ts:396 那样复位 src，导致闩锁过再按一次会被吞掉； ② 截图脚本的 3× 裁片把 clip 落在了页面坐标上，跑进首屏去了。

06「无缝」的机器可验证部分：中间态是不是真的中间态

静态的两态截图证不了"无缝"。这里把醒度钉在 0 / 0.25 / 0.5 / 0.75 / 1 各拍一张， 量每档与两端点的背景平均 ΔL 差。若是开关式过渡，中间档会与某一端点几乎为零； 若是连续插值，则 vs 醒 单调升、vs 梦 单调降，且 mix 0.5 处两边接近相等。

四稿在四个醒度档上都是"单调 + 中点等距 + 不与任何端点重合"，也就是没有任何一稿是开关式过渡—— 「无缝」这一条在本轮的机器可验证部分成立。真正的手感（长按 2200/1300ms 的节奏、中途松手的退回） 仍然只能实跑：四稿都做了真实指针按压的验收（1300ms 到梦、2200ms 到醒、600–900ms 松手原样退回）， 各自的 notes 里有逐帧读数。

07需要你拍板的四件事

  • 醒态要"多在场"？四稿给出的醒态存在感排序：B（＝线上原样，一点没加） < A（6.9–7.3%）< D（15.8–30.7%）< C（18.3–23.6%）。 上一轮 p14-D 的 9–16% 曾被你判为"偏离克制"——A 把它压下来了，C 反而比 p14-D 更显眼（换来的是四稿最大的两态差）。 这一条只有你能定。
  • 组合还是单上？我推荐 B + D（B 给缝线上的点、D 给整页的场，且 D 是唯一"醒态也在动"的方案） 或 B + A（更省心、更贴"醒态克制"的原话，代价是静止帧更含蓄）。B 在两套里都在。
  • 首屏要不要穿透？四稿默认都是 ?layer=through（挂 −2，在千层纸之上、缝线之下）， 与线上那条 14° 发丝线的挂法一致。?layer=below 可让首屏完全保持现状（新层只在滚过首屏之后出现）。 首屏是现在两态差最强、构图最满的地方——A/C/D 是否需要保留它的现状，是你的裁决。
  • 琥珀总量。琥珀是全站唯一异质色。四稿都在不同程度上加了它：A 是尘粒、C 是亮边与折光带、 D 是掏空窗的 1px 框、B 是暖残影。单看都克制，组合时要明确"整页同时最多几处琥珀"， 否则叠起来会破坏"琥珀只出现在极少处"这条既有纪律。

09口径提醒（务必先读）

  • 哪些数字是我算的、哪些是各稿自测的。上面第 05/06 节的两张表（两态像素差、醒度扫描）与 「rAF／监听」一列，是我用 .p15-verify.cjs 自己复算的；各卡片「实测」表里的其余数字 （占相邻墨色百分比、eegPathD 单次耗时、折射段对齐误差、生成耗时、节点数、逐像素零差） 是各稿自测，我没有逐项重算——它们与各稿 notes 里写的一致，可各自复现。
  • 四稿不是线上站点的复刻，是"共用一个简化外壳 + 各自的背景层"。所以本轮的像素数字只能用于 四稿互相比较与与外壳基线比较，不能搬去和线上比。
  • 截图一律 freeze=1（动画停在 0% 帧）。四稿的"动感"在静态图里全部丢失， 而"动感"恰恰是本轮的一半。请实跑一遍再判。
  • headless 的帧时间不可横向比较（上一轮的教训：无帧消费方时 rAF 会整段停发，环境自身抖动约 40%）。 本轮我因此没有把任何"帧时间"写进裁决——只给了页面内可复现的计算量（B 稿）与结构性计数（rAF/监听）。
  • 真正上线前应在 npm run preview 的生产构建上，用你 2026-09-22 换面卡顿取证时那套 200% 压力 A/B 方法复测一次。
