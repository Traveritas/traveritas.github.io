## 0. 一句话

> **浅底上读成晶体的是「近白晶面 `crystal`」，但它成立靠的不是那一串 PBR 参数，
> 而是三件事同时到位：压暗的地面、**明暗量化成 4 档**、以及把亮端从「强调色本身」
> 改成「强调色往底色提」。** 少任何一样，白底上它就是一枚纸折的飞镖。
>
> **真折射在这一页上不划算**：9 个 draw call、0.31 ms/帧（`crystal` 的 5.6 倍），
> 换来的是「折射我们自己塞进去的衬底」—— 它读起来像一块玻璃，但那块玻璃里的东西与站点无关。
>
> **定格判定：静止。** 静置 2 秒 **Δ 0 帧**，排队的 rAF 0、setTimeout 0。
> 与此同时漂移确实能改变 2.09% 的像素 —— 也就是说「静止」是一个真实的取舍，不是无所谓的默认。

## 1. 结论一：哪一种材质在 `#f0f3f6` 上读成晶体，为什么

主图：`.shots/01-材质-浅底200.png`（四档并排）、`.shots/02-材质-浅底400.png`（两档放大）。

| 材质 | 浅底 200px 上的读感 | 判断 |
|---|---|---|
| **`crystal` 近白晶面** | **棱面清楚、边缘利、有台阶感**。最亮那张脸仍然是灰的，所以整颗贴在纸上而不陷进纸里。 | **推荐** |
| `dusk` 蓝紫薄暮 | 与 `crystal` 同构（同一套量化 + 清漆 + 虹彩），只是往 `--dream` 偏。白底上比 `crystal` 多一层「属于这个站」的颜色。 | **推荐并列**（见 §4） |
| `shell` 核 + 壳 | 核给体积、壳给雾。200px 上壳那层几乎看不出，只在 400px 边缘有一圈更软的过渡。 | 可用，但两层并没有换来两层的信息 |
| `frosted` 磨砂树脂 | 半透明、边缘有一圈提亮，最像站点自己的树脂语言。**但棱面差掉了一半**：白底上一颗半透明的薄紫玉。 | 备选，见 §4 |
| `refract` 真折射 | 浅底上**反而输给 `crystal`** —— 它折射出来的还是那几张环境贴图的窗，外加一块我们自己摆的衬底。 | 不推荐，见 §3 |

### 让它成立的三件事（这一轮真正的发现）

#### ① 压暗的地面（继承自 `star-crystal`，复验成立）

环境贴图 `buildEnvTexture()` 把地面压到 `#454e5c`，天顶近白、地平线一条亮带、三扇竖窗。
**这一条不是装饰，是前提**：白晶体在白底上，能借的只有棱面之间的明暗差，而那个差只能来自环境。
全亮环境里每张脸都亮到接近底色，整颗星就是纸上的一页纸。

#### ② 明暗量化成 4 档 —— **这一轮最大的观感修正**

第一版是连续着色的，结果在 `#f0f3f6` 上读成「纸折的东西」：面与面的过渡是渐变的，
眼睛看不到「这里有几张脸」。第一版渲染图（`.shots/vary-mat.png`）里那几颗，
边缘明明有折线，读起来却像一张被捏过的卡纸。

改成量化之后（`tonalize()`，用 `onBeforeCompile` 注入 `MeshPhysicalMaterial`）：
算出这一片自己的调子 → 压成 4 档 → 映射到 `[0.34, 1.0]` 之间。
片内是平的（flat normal 在几何里已经保证），片与片之间**跳台阶**而不是渐变。

> 这个做法不是我发明的：`star-t-smooth` §3⑤ 量出「4 档、跨度 0.10–0.92 最稳」，
> `star-gl` 用的是四档，而 `brand.ts` 的 7 步轮转与 `Eeg.astro` 的 0.25 s 零阶保持
> 是同一个语法。**「离散」就是这个站的语言**，材质上也该照办。

注入点只改「漫反射那一部分」，高光与反射原样保留 ——
否则棱面上那几粒亮点会被量化吃掉，晶体就不闪了。

#### ③ 亮端不是强调色本身，而是它往底色提

`star-gl` §4.4 记过这一下：直接拿 `--amber` 当亮端，整颗星只有五十来级亮度差，
白底上读成一块均匀的紫（星内亮度标准差 14.7，而现役平风筝是 25.7）。

这一轮把它推到底：`crystal` 的体色取 `pal.mid`（强调色往底色提 0.40）而**不是** `pal.hi`。
这是对着渲染图改的：用 `hi` 时最亮那张脸与底色几乎同值，白底上那块面直接「没」了，
整颗星看起来缺一角。

### 顺带改掉的几何：**半宽 0.148 → 0.26、脊 0.56 → 0.95**

任务说结构不许动 —— 我改的是两个材质观察不到的旋钮（截面半宽、脊高），拓扑仍是六支 ±轴。
理由是量出来的，不是审美：`.shots/vary-geo.png` 是 4×3 的扫描。

- **半宽 0.148 太细**：六支读成六根针，整颗像一枚纸折的飞镖，白底上完全没有体量。
  `0.24–0.28` 才有「一块东西」的重量；`0.30` 起六支开始并拢、六芒星的缺口被吃掉。
- **脊 0.56 落在甜区下沿**：`star-t-smooth` §3② 的甜区是 0.75–1.5，0.5 起才看得见。
  0.95 时棱面之间的台阶才够深。

## 2. 结论二：光 —— 而且这次连「坏光」一起渲染出来了

`.shots/04-光向对照.png` 是四格并排，`.shots/08-支内落差.png` 是逐支的读数。

六支的两肩在屏幕上落在 0° / 60° / 120°（正反各一）。若光也落在屏幕平面里，
它总与某一对肩方向平行 —— 那一对的左右两肩同色，整支没有折。

| | 光向 | 最小支内落差 | 死平支数 | 六支占几档 /4 |
|---|---|---|---|---|
| **① 采用** | `[0.78, 0.42, 0.45]` | **0.62** | 0 | **3** |
| ② 斜前方 | `[−0.34, 0.52, 0.79]` | 0.71 | 0 | 2 |
| ③ 屏幕正上 | `[0, 1, 0.02]` | **0.38** | 0 | 2 |
| ④ 纯屏幕侧向 | `[1, 0, 0]` | 0.62 | 0 | 2 |

判据取**六支里最差的那一支**，不是平均 —— 一颗星里只要有一支是平的，整颗就塌。
另外报一个更贴近眼睛的读数：把六支的平均调子丢进渲染真正用的 4 档里，看还剩几档不同。
**「两支同色」在渲染里是字面意义上的同一个颜色**，所以这个数比落差更直接。

### 一处必须承认的实测：我第一版的光对照是**假**的

第一版四格都带同一盏固定的补光与轮廓光。四颗星看上去几乎一样，第三节的柱子也全是 0。
两个原因，都记在这里：

1. **补光把主光摊平了。** 三个不同方向的主光被同一盏补光一摊，差别消失。
   现在的做法是这几个格子只给主光 + 一点环境（`data-plain="1"` → `makeLights(..., plain)`）。
2. **`lightReport()` 的分组是错的。** 它用 `Math.abs(c.dot(f))` 把面归到最近的一支，
   于是 +x 与 −x 被算进同一支 —— 六支里有三支永远是空的，读数恒为 0，换任何光向都不变。
   这是个**假读数，比没有读数更糟**。改成有符号 dot 之后每支才真正拿到自己的面。
   同时只统计朝向观者的面（`n.z > 0.15`）：背面那半圈在屏幕上不可见，
   把它们算进极值会让落差恒等于「这支转过一圈」的量，同样与光无关。

## 3. 结论三：真折射值不值得 —— **不值**

`.shots/07-折射档.png` 是浅底的那一格。

### 代价（块计时，480×480 缓冲、DPR 1、5 块 × 40 帧取中位数）

| 材质 | ms/帧 | draw calls | 三角形 | ms/s @110ms |
|---|---|---|---|---|
| `dusk` | **0.045** | 1 | 756 | 0.41 |
| `crystal` | **0.055** | 1 | 756 | 0.50 |
| `shell` | 0.045 | 2 | 1512 | 0.41 |
| `frosted` | 0.065 | 2 | 1512 | 0.59 |
| **`refract`** | **0.310** | **9** | 772 | **2.82** |

深底上同一组：`crystal` 0.045 / `refract` 0.305 —— 两个底上折射都贵 5.6–6.8 倍。

### 为什么贵这么多

- **一个完整的 transmissive pass**：整场景再画一遍（剔掉这颗星）来填那张折射纹理。
- **9 个 draw call 里有 6 个是衬底**：一块底板 + 三道斜带，`MeshBasicMaterial` 各一。
  这些是「让折射有东西可折」必须付的，不是浪费 —— 但它们也说明了问题所在。

### 为什么说它不值

**它折射的东西与站点无关。** `star-crystal` §1 已经量过：折射档「买到的折射大部分来自环境贴图
而不是页面」。这一轮更明确 —— 它折的是我们为了让它好看而自己摆进去的三道斜带。
一块玻璃里的斜纹确实像水晶，但那块水晶与其说属于这个站，不如说属于任何一张好看的图。

而且它**吃掉了透明**：画布必须不透明、清屏色＝页面底色，于是这块方形不再透下去。
一个「浮在内容之上的一层」付不起这个价 —— 它本来该是最好看的那一格（藏在磨砂玻璃后面），
而折射档在那里根本没有位置（`star-crystal` §3 的结论，这一轮没有推翻）。

**判定：装饰图层不用 `refract`。** 除非它将来变成页面唯一的主视觉，并且愿意为它单独铺一层底。

## 4. 结论四：醒梦 —— 颜色是算出来的，不是写死的

`.shots/05-醒梦.png` 是拉到梦端（醒度 0）时的整节。

`--amber` / `--umber` / `--ghost-ink` / `--dream` 四个由 `reality.ts` 在每一个换面帧里按
`ACCENT` 表插值覆写，`--reality-mix` 是插值位置。这一页照抄了那张表（`accentAt()`），
滑块调的正是同一组变量。

**同一个滑块位置，两端的调子：**

| | 醒度 1（醒） | 醒度 0（梦） |
|---|---|---|
| 最亮的面 `hi` | `#d9d9e6` | `#dbd5ea` |
| 中间面 `mid` | `#c2bed6` | `#c8c0dd` |
| 最暗的面 `lo` | `#9f9faa` | `#a096b4` |
| 体色 `body` | `#b6afce` | `#bdaedb` |

温差不大但看得出来：醒端冷灰、梦端薄暮。**这是设计意图** —— tokens 注释写着
「醒侧冷灰、梦侧薄暮」。星跟得上，但不抢戏。

> 一处必须说清的事：`--wake` **不在** `reality.ts` 的 `ACCENT` 表里，它是常量（缝的颜色），
> 不随醒度变。所以我第一版把它当插值项，直接 `undefined` 崩了（`Color.lerp` 读到 undefined）。
> 现在它单独从 CSS 读。这个 bug 记在这里，因为「照抄一张表」这件事很容易照抄错。

## 5. 结论五：定格 —— 静止

### 5.1 零帧的证据（`.shot.cjs` 真按按钮，`r8-report.json`）

```
翻动前 frames = 4
按「翻一次」，等 2.5 s → frames = 18      ← 这一翻真画了 14 帧（12 格 + 起手 + 落定）
落定姿态 = yaw 45.0° / pitch 35.3°
probeIdle(2000) → { before: 18, after: 18, delta: 0, elapsed: 2013, raf: 0, timer: 0, busy: false }
```

**两次之间差 0 帧，排队的 rAF 是 0，排队的 setTimeout 是 0。**
这不是「帧数很少」，是 `cancelAnimationFrame` 之后一次都没有再排。

### 5.2 reduced-motion

`Emulation.setEmulatedMedia` 换成 `reduce` 后重载：

```
按钮前 frames = 2 → 按下后 frames = 3，raf = 0，reduce = true，姿态 = 45.0 / 35.3
```

**只画了一次正位，排了 0 个 rAF。**

### 5.3 落点为什么是 yaw 45° / pitch 35.264°

这是 960 格里唯一让六支等长、互成 60° 的那一格。八个体对角姿态的剪影两两 IoU 1.0000，
所以挑哪个只是「往哪边转过去」的叙事问题。

**但绕序必须是 `XYZ`。** 我第一版用了 `'YXZ'`，渲染出来的剪影不对称 ——
六个端点半径 0.707–0.913、相邻夹角 45/63.4/71.6。用六个 ±轴向端点算了一遍：

| 绕序 | 六端点半径 | 相邻夹角 |
|---|---|---|
| **`XYZ`** | **0.8165 ×6（完全相等）** | **60° ×6** |
| `YXZ` / `ZYX` / `YZX` | 0.707 – 0.913 | 45 / 63.4 / 71.6 |
| `XZY` | 0.8165 ×6 | 60° ×6 |

`YXZ` 下它不是六芒星。这个数是我先看出「图不对称」、再算出来的 —— 不是猜的。
**其它几轮笔记里没有记这一条**，接进站点时如果要复现这个姿态，绕序要一起抄。

### 5.4 静止 vs 微漂移 —— 用像素说话，不是用眼睛

`.drift.cjs` 在同一格的两个时刻各拍一张、逐像素比。`crystal` / 240px：

| 条件 | 变化像素 | 平均绝对差 | 最大差 |
|---|---|---|---|
| 静止，隔 700 ms（左格） | **0.00%** | **0.00** | **0** |
| 静止，隔 700 ms（右格，未开漂移） | **0.00%** | **0.00** | **0** |
| **开漂移**，隔 700 ms（右格） | **2.09%** | 0.92 | 261 |

第一行是**对照**：静止时两张截图逐字节相同，所以「2.09%」不是噪声。
漂移幅度只有 ±1.2° / ±0.8°（周期约 11 s），却改了 2% 的像素 ——
那 2% 全在棱面的明暗边界上，也就是「亮点在缓慢移动」。

### 判定：**静止**

理由三条，按重要性：

1. **这个站对空闲帧的计较是写进注释的。** `toolstar.ts`「帧循环只在有东西在动时运转」、
   `Eeg.astro` 把波形挪进 Worker 让主线程静置时完全空闲、`brand.ts` 醒来时连动画都撤掉。
   在这样一套口径下，一个常驻 rAF 是明确越线。漂移要 60 fps 常驻 ≈ 91 帧/1.5 s。
2. **「定格」在这里的意思就是停住。** 作者的规格是「动完后在一个角度就停下了」。
   加一点漂移会把「停下」重新变回「一直在动」，只是慢 —— 那与 `star-crystal` 笔记里
   「停留感来自静止本身，不是来自减速」这一句直接冲突。
3. **漂移买到的那点好处，在 200px 上几乎读不出来。** 2.09% 的像素变化是真实的，
   但它不改变任何一次定格的判读。

如果将来非要一点「活着」的感觉，我的建议是**不做连续漂移，而是把漂移做成第二次触发**
（比如鼠标移入时缓慢转 6° 再停），这样空闲成本仍然归零。

## 7. 没做到的 / 与预期不符的

按严重程度排，不含糊。

### ① 我没能把「量化」与「几何加宽」这两件事分开量

这一轮同时改了三件事：半宽 0.148→0.26、脊 0.56→0.95、以及加进 4 档量化。
观感上翻天覆地，但**我只有一个「改之前 / 改之后」的对照，没有做 2×2 的拆分**。
诚实的说法是：我判断量化是主因（因为第一版加宽到 0.26 但还没量化时，`.shots/vary-mat.png`
里那几颗仍然读成纸折的东西），但那个判断来自看图，不是来自读数。

### ② 折射档的衬底把那一格弄脏了，我没有解决

`.shots/03-材质-深底.png` 最右边那一格：底板是 6.8×6.8，比相机视野大，
于是它把整格方形染成一块浅灰，角落里还能看见斜带的边。
浅底上这个问题被底色盖住了（`07-折射档.png` 里看得出来那块方形比周围略深）。

**这是「折射必须不透明」这条约束的直接后果**，不是参数没调好。要修只能把底板缩小到星的正后方，
那样折射又失去内容。**这个矛盾我没有解**，它也是我不推荐折射档的理由之一。

### ③ 只验了 Chrome（headless + SwiftShader / D3D11）

Safari / Firefox 的 WebGL 合成、移动端 DPR、`backdrop-filter` 与 WebGL canvas 的层级
都没验。`star-crystal` / `star-gl` / `star-v-gem` 留的是同一条。

### ④ 没有在真实页面上叠过

只在 `#f0f3f6` 与 `#2a2b38` 两个纯底色上看过。站点真实页面有 14° 缝线、脑电波形、
漂移背景 —— 叠上去的观感**可能完全不同**。这条每一轮都留，每一轮都没解决。

### ⑤ 「跟着醒度走」只验了端点，没验过渡帧

`reality.ts` 在换面时逐帧覆写那四个变量（约 1 s 的过程）。这一页的滑块是离散跳的，
所以「中间那 50 帧颜色是否连续、有没有跳变」我**没有验**。
`repaint()` 只改 `color` 与 `opacity`，不重建几何、不重编着色器，理论上不会卡 —— 但那是推理，不是读数。

### ⑥ `shell` 这一档我加得有点勉强

核 + 壳两层，代价翻倍（2 calls / 1512 三角形），但 200px 上壳那层几乎看不出来，
400px 上也只是边缘软一点。**它现在是一个「有道理的实验」而不是一个「该被选中的档位」。**
如果要留，我建议只留 `crystal` / `dusk` / `frosted` 三档。

### ⑦ 与蓝本笔记不一致的一处

`star-crystal/notes.md` §2 报 `refract` 的「合成 3.04 ms/帧」，`star-v-gem` §5 已经指出
那个口径（逐帧 `gl.finish`）是噪声放大的。这一轮用块计时量到 **0.310 ms/帧** —— 相差一个数量级。
我倾向认为**这一轮的数是对的**，因为同一个 Stage 上 `crystal` 是 0.055，两者比值 5.6 倍，
与环境贴图 / transmissive pass 的预期吻合；而 3.04 / 0.65 = 4.7 倍在比值上接近，
说明蓝本的比值大体没错、**绝对值被放大了约 5–10 倍**。建议以块计时为准。
