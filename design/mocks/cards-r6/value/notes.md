# 甲 · 基准 `value`

> 面是底图的一次值偏移，边是两条 0.6px 加快一圈 0.5px 收口。除这两样之外没有第三样材料：
> 没有底色、没有投影、没有标题栏、没有图标、没有胶囊、没有贴图、没有一处 `blur()`。
> 这一条只回答一件事：光靠值和边够不够。

## 1. 面怎么做的

一句：卡上没有颜色，只有一层 **半透明的墨或白，按栏反号**，
底图那层 5px 网点连同斜向光带原样从卡里穿过去（没有 filter，振幅不损）。

```css
/* 亮栏：往下压 */
background-image: linear-gradient(180deg, rgba(23,28,40,.018), rgba(23,28,40,.092));
/* 暗栏：往上提 */
background-image: linear-gradient(180deg, rgba(255,255,255,.118), rgba(255,255,255,.022));
```

梯度不是为了好看：平涂的 1.5% 在 4× 下是一块塑料片，有了「顶几乎不动、底沉 5–6 L\*」，
卡内网点的密度变化才和卡外那道斜光接得上。三栏的三个顶/底 alpha 都不一样，理由见下。

## 2. 三栏各给了哪组数

底图实测（`plate-1440.png`，卡位上下各取 6px 高、卡宽的均值）：

| 栏 | 底图·卡位顶 | 底图·卡位底 | 面 alpha（顶→底） | 卡内·顶 | 卡内·底 | 与底图的差 |
| --- | --- | --- | --- | --- | --- | --- |
| 随笔 · 冷灰 | L\*79.2 | L\*79.9 | 墨 `.018 → .092` | L\*78.1 | L\*74.1 | −1.1 / −5.8 |
| 瞬间 · 薄暮 | L\*11.1 | L\*15.7 | 白 `.118 → .022` | L\*23.5 | L\*18.0 | +12.5 / +2.3 |
| 项目 · 深蓝 | L\*7.8 | L\*13.0 | 白 `.092 → .014` | L\*18.0 | L\*14.5 | +10.2 / +1.4 |

- **亮栏**压得最轻（顶 1.1 L\*）。近白的纸上，墨多 1% 就成灰块；这一栏的「卡感」几乎全靠那条 0.6px 的白线，
  面只负责让底下半张比上面半张沉一点。
- **薄暮**提得最重（顶 +12.5）。紫本来是中灰，提一档就够；到底只剩 +2.3，卡的下沿几乎化回纸里——
  这是故意的：抬起来的是上沿，不是整块。
- **深蓝**提得比薄暮少 2 L\*（顶 +10.2）。它的底更深（L\*7.8），同样一档白会读得更亮；
  再给 .118 就会变成一块发光的玻璃。

三组数不共用：方向反号之外，每一栏的**起点、终点、跨度**都是按那一栏的实测明度定的（亮栏跨度 5.8，
薄暮 12.5，深蓝 10.2），不是同一个梯度换三张皮。

## 3. 边：两条线加一圈收口

三样都由 `box-shadow` 给，没有伪元素、没有 border，四条边不是等宽等亮的：

```css
box-shadow:
  inset 0 .6px 0 var(--edge-hi),   /* 上沿受光，在卡内 */
  0 .6px 0 var(--edge-lo),         /* 下沿落影，紧贴卡下 0.6px */
  0 0 0 .5px var(--edge-ring);     /* 整圈闭合，极淡 */
```

| 栏 | 上沿（白，0.6px） | 下沿（暗，0.6px） | 收口（0.5px） |
| --- | --- | --- | --- |
| 随笔 · 冷灰 | `rgba(255,255,255,.46)` | `rgba(23,28,40,.27)` | `rgba(23,28,40,.16)` |
| 瞬间 · 薄暮 | `rgba(255,255,255,.55)` | `rgba(0,0,0,.28)` | `rgba(255,255,255,.10)` |
| 项目 · 深蓝 | `rgba(255,255,255,.50)` | `rgba(0,0,0,.26)` | `rgba(255,255,255,.12)` |

**暗栏怎么反**：方向不变（永远上亮下暗），反的是明度——上沿从 .46 提到 .50/.55（暗底吃得起白），
收口从墨换成白（墨在 L\*11 的纸上等于没有），下沿仍是黑，但 .28 的黑落在本来就黑的纸上只剩一线，
所以暗栏的下沿其实是由「面到底已经化回纸里」+ 一线黑共同收的，不是靠一条线画出来的。
亮栏反过来：白在近白上会先饱和，上沿只能 .46；而墨 .27 的下沿在亮纸上特别立得住。

1× 实测（截图取色，不是算的）：

- 亮栏上沿：底 `#b9c6d9`（L\*79.4）→ 线 `#c6d0df`（L\*83.1），一行；下沿 `#98a3b4`（L\*66.6）。
- 薄暮上沿：底 `#271d31`（L\*12.8）→ 线 `#746d7a`（L\*47.0）；下沿 `#2c2235`（L\*15.2）…
  再到卡外 `#272731`（L\*16.0）——只差 1 L\*，暗栏的下沿线几乎是隐形的。
- 收口在 DPR1 上其实被画成一个整像素（0.5px 没有半行可落），所以亮栏把它压到 `.16`——
  再高就不是「极淡」，是一圈描边了。

## 4. 展开：怎么从卡片来到这里

`#open` 的阅读面板不是另一套材料：**同一个值偏移，换了栏就换方向**。
面板停在夜那半边（612,108 · 700×700），所以面按暗栏提：白 `.115 → .028`，字跟着变成浅色；
那三条边也整套换成暗栏的（上 `.50` / 下 `.26` / 收口 `.11`）。

- 亮栏那两张退到 16%（它们不在面板底下，留一点「从哪来」）；夜面两栏直接收掉——
  它们正压在面板背面，透出来就是面板上的脏点。
- 面板是半透明的，所以底图上那道斜光、雨丝、薄暮到深蓝的过渡全都从字底下穿过去。
  这是「印在纸上」最直接的证据，也是它和 r5 那张不透明纸最大的差别。
- `#detail` 是第一张随笔卡的同一个盒子 `scale(3.4)`（348×224 → 1183×762），连带 0.6px 的边一起
  放大到 ~2px。**它被摊在夜那半边**：3.4 倍的宽度亮栏根本横不下（最宽处 y=0 约 635，y=900 只剩 405），
  而「压暗」的纸一旦骑到界线另一侧，字就掉进墨里。所以凑近看时它也按暗栏反号（白 `.12 → .024`）。
  卡比屏幕宽，右沿出画——凑近的代价，不是裁切失误。
- 状态全在 hash 里（`#open` / `#detail`），JS 只有一件事：把 hash 翻成 `html[data-state]`。
  锚是 0×0 的两个 `<span>`，因为 detail 那张卡比屏幕宽，id 挂在卡上会让浏览器
  为了「滚到目标」把整页横移 283px（实测）。

## 5. 最容易被否的地方

1. **亮栏的顶是空的。** 面的顶只比底图低 1.1 L\*，卡的上半截几乎是隐形的，
   整张卡的「起笔」全靠那 0.6px 的一行白。底图换一张更亮或更花的纸，这条顶就没了，卡会从上面散开。
   这是三栏里最脆的一处；暗栏反过来最稳（顶 +12 L\*）。
2. **暗栏的下沿几乎没有线。** .28 的黑落在 L\*16 的纸上只压掉 1.2 L\*。
   近看（放大图）能看出「面到底化回纸里」，远看就是没有下边。要不要给暗栏补一条 .34 的黑，是这批里
   我唯一拿不准的数——补了更像卡，不补更像印上去的。
3. **detail 的字被屏幕右沿切断。** 3.4 倍、夜里横 1183，屏幕只剩 828 给它，描述那行少 7 个字，
   「1923 字」整个在画外。要做全，就得降到 2.5 倍（870 宽，刚好塞下），
   但 2.5 违背「3–4 倍」——我选了尺寸，认了这个切口。
4. **底色偏灰。** 亮栏那张卡在 1× 下读起来像「底图上有一块稍微压暗的区域」，
   而不是「一张卡」。这正是这条案子要的；但如果评审要的是「一眼看见六张卡」，
   它会在第一眼就输给 r5 的白纸。
