星 · 预渲染烘焙

上一轮把三轴六芒星合起来时，中心撞到一件不可调和的事：halfWidth 0.26 让每支宽 8.32 单位，六支都穿过原点，半径 4 以内每个像素被三层以上的料盖住。平风筝时它们在同一张平面上，画序怎么排都对；一旦截面有了厚度，六支在中心是真穿插，任何按片排序的画家算法都排不出正确遮挡。

这一轮换一条路：离线用真深度缓冲画成像素，只交成品。深度缓冲不排片、逐像素比 z，所以根部的收坡可以取消，中心那一段重新长出脊来。

深度的读法在这里是唯一可信的：六支的 z 区间互相包住（每支的近端从 0 爬到 9.2）， 所以「哪一片在上面」不是一个排序问题，而是一个逐像素的问题。 烘焙把这件事交给 24 位深度缓冲，一次算清。

03

运动

路径沿用 star-final 那条：三轴各转 90°（体 x −90° / 体 y −90° / 体 z +90°）， 起止错开 12% / 0% / 5%，欠阻尼弹簧 k 7 / w 5，全长 1550ms。 终点是 90° 的整数倍，即立方群的一个元素，所以落定的剪影与正位**严格重合**（不是近似）。 这一页把它切成 N 格定格 —— N 就是这一节要定的那个数。

静 · 零帧

难看账：步进会不会撞进坏角度

评分器沿用 star-v-motion 的四项加权（balance 0.44 / aspect 0.26 / a6 0.20 / sixShare 0.10）， a6 的归一化基准换成正位实测的 0.434（见 star-final §7.7）。 门槛 <55 记难看、55–70 记能过、≥70 记好 —— 门槛是我选的，报数必须带着它。

采样格数难看能过好最低分难看时长全片

结论。均匀切 16 格时，第 2 格（u ≈ 0.067）恰好落在一个 45 分的姿态上 —— 连续路径上那一段只占 36ms（2.3%），但定格会把它**停住 110ms**，难看曝光反而从 36ms 涨到 110ms。 这是「步进可能比连续更难看」的具体形状：切得粗，坏角度不是被躲开，而是被放大。 贪心取格（每格在 ±半格内滑到最高分）把 16 格的最低分从 45 抬到 77。

为什么用 setTimeout 链，不用 CSS steps()

  • 这一页要的是「一格停 110ms」，不是「每屏一次」。requestAnimationFrame 在隐藏标签页里会停，回来会把落下的那一串补成一跳 —— 定格的样子就破了。
  • steps() 的每一格仍然由合成器推进：即使这一帧与上一帧的画面完全相同，合成器也不会跳过。这颗星在页面上是装饰，静置时连合成器都不该醒。
  • 定时器链的长度是有限的（N 格），最后一下自己收尾。所以「一直在转」在结构上就不可能发生。
