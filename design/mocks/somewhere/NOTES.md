# somewhere · 原型笔记（2026-11-03）

`/somewhere/` 是检索页再往下的一片空间。这一轮做的是**整体场景的五个方向**，小交互留到选型之后。

## 为什么是「第四套摆法」而不是新页面

站里已有三套摆法共用一支流光着色器：主页的池、检索的格、漫游的景深（`src/scripts/wander/light.js`）。
所以「另一个空间」在这里不是换页，是**同一片光的第四种排布**——加一个区（`uP[16]` → `uP[20]`）、一组色，
外加一次把三条带摆到新位置的转场。这样它天然是顺的：没有第二个渲染体系，没有两套状态。

正式落地时需要动的地方（这一轮都没动 `src/`）：

- `light.js`：`ORDER` / `DREAM` / `WAKE` / `GRAIN` 各加一项，`uP` 从 16 个 vec3 扩到 20 个，`uBias` / `uLift` 从 3 扩到 4；
- `wander.js`：`mode` 加一个 `'somewhere'`，`setSeams` 加一组 spec（`SPEC_SOMEWHERE`），
  底部滚到底时接住（现在那儿什么都不发生）；
- `WanderIndex.astro` / 路由：`/somewhere/` 一个入口，Toolstar 的「去处」里加一格。

## 转场怎么做的（这一轮的结论）

进来时和检索一模一样：两条 14° 的缝把屏幕分成三栏。向下滚一回（或上划、或 ↓），

1. 两条缝的支点从 `x = 1/3, 2/3` 收向中线，法向从 14° 转到 90°；
2. 于是竖着的两条斜缝躺成地平线上下的两条横线，三段色带变成「天 / 地平线那一带光 / 地」；
3. 三个栏头跟着退下去、淡掉。

全程同一个着色器、同一组调色板——**换的是缝的方位，不是色板**。这是这一轮最关键的一处：
如果转场时换色，它就会读成「进了另一个页面」；只动缝，它才读成「同一片光被重新分开」。

## 五份场景（2026-11-03 第一轮结果）

| | 一句话 | 空间语法 | 关键取舍 |
| --- | --- | --- | --- |
| **A 远处** | 一片永远够不着的远方 | 横向视差，不用 `project()` | 推 z 时地形一像素不动——「走不近」是可感的，不是说的 |
| **B 焦平面** | 远处全是影子，走到才成形 | 景深 + 焦平面 | 1/3 分辨率画布画一百多个影子，只有焦平面那件有 DOM |
| **C 长廊** | 望不到头的路，收在一个点 | 一点透视 + 路自己长 | 墙只有线没有面（填面会变成帐篷），「走不完」靠编号取内容 |
| **D 往下** | 一圈圈台面往深里去，头顶只剩一点光 | 竖直深度（另给 `dep`，不用 `cam.z`） | 变暗用遮罩不换色板；上来时浮出一架窄梯，不是倒放 |
| **E 室内** | 一间从流光里围出来的屋子 | 有界 + 透视（斜 14°） | 暗面压光、地脚用 `destination-out` 擦掉，让流光从墙脚透上来 |

五份都只有一个 WebGL context（背景那支着色器），场景自己画在 Canvas2D / DOM 上。
五份的控制台都是干净的（`report.json` 的 `log` 全为 `[]`）。
并列对比：`.shots/board-1440.png`、`.shots/board-390.png`。

### 三位作者共同指出的两件事（值得记）

1. **近处容易空**。A 与 B 都说了：转完之后画面下半很静。BRIEF 里「近处空着是构图的一部分」这句被照做了，
   但它是这一轮最弱的一头。选型时要看这一点，它决定了小东西以后长在哪。
2. **reduced-motion 下背景流光还在流**。D 与 E 都测到了（D 约 38% 像素在变）。这是 `light.js` 的 `uTime`，
   属于底子，不在这一轮五位的修改范围。**正式落地时这是一个必须解决的无障碍问题**——
   要么让 `uTime` 在 `prefers-reduced-motion` 下冻结成一个静止相位，要么接受这份动效。
