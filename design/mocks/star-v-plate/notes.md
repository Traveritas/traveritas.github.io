# 六芒星 · 板与构造 —— 原型说明

日期：2026-11-10 ｜ 目录：`design/mocks/star-v-plate/` ｜ 端口：4662

上一版（`design/mocks/star-crystal/`）把六个尖端做成一个实心尖球，判语是「3D 的不好看」。
诊断有两条：**尖球是错的剪影**，以及**白底上的白色实体没有东西可以接光**。

这一版反着下注：六个尖端不动，换**用什么把它们连起来**。
用薄的东西搭 —— 正交的薄板、一圈棱、一层壳。看的不是「像不像宝石」，
而是它在浅底上还剩不剩一个**边界**，以及那个边界后面还有没有**深度**。

```
node design/mocks/star-v-plate/serve.cjs        → http://localhost:4662/star-v-plate/
node design/mocks/star-v-plate/.shot.cjs        → .shots/（截图 + 自检）
node design/mocks/star-v-plate/.repeat.cjs      → .shots/repeat.json（读数自己的抖动）
node design/mocks/star-v-plate/.sizes.cjs       → .shots/size-cost.json（尺寸阶梯的代价）
ONLY=01,06 node design/mocks/star-v-plate/.shot.cjs
```

## 0. 一句话结论

> **`三片正交薄板` + `facet 直边轮廓` + `亚克力 + 暗边`** 是这一版唯一可以往站点上放的一组。
> 它读成「一个立着的构造」，不是贴纸也不是一团乱麻。
> 前提有两个，缺一个就塌：**轮廓必须是直边的 facet**（等臂曲线版读成弯曲的领结），
> **每块板必须有一圈压暗的边**（没有暗边，浅底上它化进纸里 —— `06-dissect.png` 前两格）。
>
> 代价：240px 下 **5.15 ms/s**（110ms 保持），全图层可以随可见性归零。
> 推荐 **12 步 / 110 ms**。

这条结论是踩了四个坑之后才成立的，四个坑都留在下面，因为其中两个是**我自己写的 bug**，
不记下来下一版还会踩。

## 1. 构造逐条：它读成什么

`.shots/01-constructs-edge.png`（浅底 / 深底两列，同一姿态）、`03-constructs-opaque.png`、
`04-constructs-spire.png`、`05-constructs-equal.png`。

| 构造 | 读成什么 | 留不留 |
|---|---|---|
| **三片正交薄板** `tri` | **一个立着的构造。** 三个面互相穿插，前面的板挡住后面的板，看得见「一层在另一层前面」。六个尖清楚。 | **留**（首选） |
| **一片薄板 + 一根正交轴** `spine` | 一张星板 + 中间一个点。正等轴下那根轴差不多正对观者，被压成一个黑点；转到侧面才读得出。**「一张板 + 一个点」不构成三轴。** | 不留 |
| **空心棱壳** `shell` | 一块半透明的多面体。「看得进去」这一条成立（后壁能看见，重叠处更暗），但**它没有星** —— 六个尖被棱壳的边吃掉，读者看到的是一块八角石头而不是六芒星。 | 不留（好看，但不是星） |
| **十二边框架** `frame` | **线。** 十二条棱读成一个三轴骨架，六个尖是六个节点。最「巨构 / 骨架」的一个，也是最小尺寸下最先崩的一个。 | **留**（次选/大尺寸场景） |
| **折起的星** `fold` | 一张略微弯的白板。**没做到「四片平面」**（见 §6）。 | 不留 |
| **双片一环** `mixed` | 两张板 + 一圈套住它们腰的环。环给了一个别的构造都没有的东西：**一个纯圆**，对冲三片板的直。 | 留作备选 |

三条要点：

1. **实心不可救。** `shell` 是这一版里唯一接近「实体」的构造，也是最不像星的那个。
   这反过来支持了最初的诊断：问题不在材质，在「用实心去回答六个尖」。
2. **`spine` 的失败不是参数问题。** 轴加粗到半径 0.07（约 240px 下 8px）之后仍然只是一个点 ——
   正等轴下 z 轴正对观者这件事与粗细无关。这是构造本身的短板。
3. **`frame` 的管子必须细到「线」。** 第一版 tube = 0.016，十二条边在白底上连成一块带棱的白面，
   完全不是骨架；压到 0.011 之后才成立。代价是它在 64px 下开始断续（见 §4）。

## 2. 四个坑（其中两个是我自己写的 bug）

### 2.1 欧拉顺序写反：六芒星从来没露出过六边形

**这是最初所有渲染都读错的根本原因。**

`toolstar.ts` 的 `drawStar()` 是：

```
x1 = x·cos yaw + z·sin yaw      // 先绕 Y
y2 = y·cos pitch − z1·sin pitch // 再绕 X
```

也就是 `R = Rx(pitch)·Ry(yaw)`。three 里只有 `Euler(x, y, 0, 'XYZ')` 是这个乘法次序。

第一版写的是 `'YXZ'`，即 `R = Ry·Rx`，两次旋转反了序。
后果：六个尖端投在屏幕上变成了**一个十字 + 中间一点**，
而不是三轴六芒星该有的六边形轮廓。

于是 `tri` 那一格看起来像「一个四芒星 + 一片乱的斜线」，
`shell` 看起来像一块斜放的菱形板 —— 全部都是错的，但错得很像「构造不好看」，
差点被当成设计结论写进报告。**这是这一版最该记住的一条：
先把基准视验对，再谈构造。**

判据（写在代码注释里）：投影后三条轴的长度必须近似相等。
实测 `pitch 35.264 / yaw 45` 下三条轴各 0.816，本来就该相等 ——
所以「角度不对」不是视角问题，是乘法次序问题。

### 2.2 环没有 material group

`TorusGeometry` 不产生 geometry group。three 就只给它 `material[0]` ——
也就是那份浅色、半透明的「面」。结果 `mixed` 那一圈环在白底上等于不存在。
显式加一个 `index 1` 的 group 之后它才吃到「边」那份压暗的材质。

**教训：凡是「一份几何吃两份材质」的做法，都得确认那份几何有 group。**
`ExtrudeGeometry` 有（0 面 / 1 侧壁），`TorusGeometry` 没有。

### 2.3 读数自检骗过自己一次

`poseSpread()` 里「整圈最像的一对」的初值我写了 `1`。只要没有任何一对 IoU 超过 1
（本来也不可能），`worst` 就永远停在 1。

结果：六种构造 × 两种步数，**十二行全部读出「重复度 1.000、pair 为空」**。
一个不存在的结论，而且看上去像是在报告「这个构造完全重复」。
改成 `-1` 之后才读出真实值（0.17–0.96）。

这和 `star-crystal/notes.md` 里那条「用 alpha 判断覆盖」是同一类错误：
**判据的初值选错，会得到一片全是同一个数的「结论」。**

### 2.4 wall-clock 计时不可重复

第一版测算取平均，表里出现 16.0 ms 的 `spine`；它的三角形比 0.9 ms 的 `tri` 还少。
改成取中位数之后更糟，出现了 5111 ms 的峰值。

于是写了 `.repeat.cjs` 专门量这件事：同一套参数连跑三轮：

```
18 个格子里 14 个的读数自己抖超过 2 倍，最大 867 倍（fold/opaque）
```

**结论：wall-clock 在这个页面里没有资格出数。** 换成
`EXT_disjoint_timer_query_webgl2`（这个 AMD 610M 上可用）之后：

```
18/18 落进 1.05–1.31 倍
```

现在页面上的表全部来自 GPU timer query，单帧 40 样本取中位与 p95。

## 3. 材质：暗边到底值多少

`.shots/06-dissect.png` 是这一整份原型里最值钱的一张。
两行分别是 `tri` 与 `shell`，四格并排：**不带暗边 / 带暗边 / 磨砂玻璃后面 / 被边裁掉一截**，
前两格之间只差那一圈边。

| 材质 | 读感 | 结论 |
|---|---|---|
| **磨砂亚克力**（无暗边） | 一片更亮的白。看得见「有个东西」，但说不清边界在哪。200px 下与背景的灰度差之和只有 129–141 | 单独用不成立 |
| **亚克力 + 暗边** | 轮廓由那圈 2–4px 的暗线交代。同一姿态、同一环境，对比 564–592 | **成立，首选** |
| **近白实心 + 暗边** | 最「实」的一档，棱面明暗来自环境贴图里的暗地面。深底上非常好看 | 成立，但偏硬，且丢掉半透明语言 |

**「带了边」与「不带边」的对比不是渐变，是台阶**（`.shots/probe.json` 的 `sizes` 一栏）：

| | 240px | 144px | 96px | 64px |
|---|---|---|---|---|
| 不带暗边 | 138 | 138 | 141 | 129 |
| 带暗边 | 592 | 582 | 582 | 564 |

四档尺寸上没有一档跌破 4 倍。也就是说**这圈边不是「大尺寸才需要」的修饰，
它是这个构造在任何尺寸下能不能被看见的开关**。

这一条来自最初的诊断：**白底上白色实体没有东西接光。**
解法不是给它加光，是给它加一个**不属于它的暗边** —— 让轮廓自己交代自己。

### 逐字符轮廓一致性

轮廓数学逐行沿用 `design/mocks/star-flat/star.js` 的 `arcs()`，没有另造第六种星。
自检 `parity()` 把本文件的 `toD()` 与 `star.js` 的 `starPath()` 逐字符对比：

```
equal: same=true
spire: same=true
facet: same=true
```

### 但默认轮廓必须是 facet，不是 equal

这是这一版最反直觉的一条。

`equal` 的边是内凹二次曲线（`pinch = 1`）。做成 2D 星芒很好看，
但**做成薄板之后，四臂各是一条弧** —— 三片正交起来，弧与弧相交成一团弯曲的领结。
读者看到的是「几片弯曲的东西」，不是「一个构造」。

`facet`（`pinch = 0`，Ave 那条直边星）让每片板都是一块**多边形**：
折痕是直线，棱线是直线，三个平面之间的关系才读得出来。

`01`（facet）/ `04`（spire）/ `05`（equal）三张截图是同一组构造在三种轮廓下的对照。
`05` 里 `tri` 那一格就是「弯曲的领结」，`01` 里同一构造是一块有平面、有折痕的构造。
**这是整个方向能成立的前提，不是参数偏好。**

## 4. 尺寸与代价

### 代价（GPU timer query，中位数，320px / 光栅 ×2）

| 构造 | 磨砂亚克力 | 亚克力 + 暗边 | 近白实心 + 暗边 | 三角形 |
|---|---|---|---|---|
| 三片正交薄板 | 1.320 | 1.053 | 0.981 | 3432 |
| 一片薄板 + 轴 | 0.804 | 0.775 | 0.758 | 1160 |
| 空心棱壳 | 1.936 | 1.866 | 1.868 | 128 |
| 十二边框架 | 0.839 | 0.566 | 0.723 | 432 |
| 折起的星 | 1.004 | 0.905 | 0.843 | 1144 |
| 双片一环 | 1.045 | 0.933 | 0.965 | 3440 |

（单位 ms/帧，320px 画布。）

**注意 `shell`：只有 128 个三角形，却是全表最贵的一档。**
这说明这里的分母不是三角形数，是**填充率** —— 八张双面半透明薄壳层层叠加，
每个像素被打了好几遍。反过来，`frame` 的 432 个三角形最便宜，因为它是线。

### 尺寸阶梯（`.shots/size-cost.json`，`亚克力 + 暗边`）

| | 64px | 96px | 144px | 240px |
|---|---|---|---|---|
| 三片正交薄板 GPU ms | 0.084 | 0.122 | 0.234 | 0.567 |
| 十二边框架 | 0.039 | 0.060 | 0.127 | 0.318 |
| 空心棱壳 | 0.090 | 0.182 | 0.376 | 1.176 |

按 110ms 保持折算成每秒占用（定格模式下这才是页面付的钱）：

| | 64px | 96px | 144px | 240px |
|---|---|---|---|---|
| **三片正交薄板** | **0.76 ms/s** | **1.11** | **2.13** | **5.15** |
| 十二边框架 | 0.35 | 0.55 | 1.15 | 2.89 |
| 空心棱壳 | 0.82 | 1.65 | 3.42 | 10.69 |

**读法：** 每百万像素的毫秒数从 64px 的 5.11 降到 240px 的 2.46 ——
固定的每帧开销（提交、状态切换）在小尺寸上占主导，纯填充从 240px 才开始显出来。
所以**小尺寸不是「免费」**，但它便宜到无所谓：64px 那颗一秒只花 0.76 ms。

对照 `star-crystal` 那一版：`cheap` 在 480px 上是 0.65 ms/帧（wall clock，那一版的表没有做可重复性检验，不能直接比）。
这里 240px / 5.15 ms/s 与它同量级。

### 尺寸与边

`.shots/11-sizes-tri.png` 是 240/144/96/64 两排（上排不带暗边，下排带）。
用 `StarFlat` 那条腰深判据：**64px 下腰深约 8px**，六臂仍然分得开 ——
比上一版 3D 实心星的「64px 是下限」宽松，因为这个构造的轮廓**本来就是二维的直边**，
不依赖棱面明暗。实测对比度在 64px 上仍有 564（不带边时 129），六档里没有一档塌掉。

`frame` 是例外：tube 0.011 在 64px 下只剩不到 1px 宽，十二条边会时断时续。
**要放小尺寸，选 `tri`，不要选 `frame`。**

## 5. 定格：步数与离散度

时钟：姿态量化到 `360/steps`，每格保持 `holdMs`，整圈最后一格保持 `3.2 × holdMs`
（照 `brand.ts` 的「7 步轮转 + 3 秒停歇」≈ 3×）。

### 姿态里为什么要叠一个点头

这个构造对 x / y / z 三个轴都有 90° 对称。**只绕竖轴自转的话，一圈里只有 4 个不重样的姿态** ——
12 步里另外 8 步是白花的。

现在的姿态 = 偏航 · 点头 · 自转 · 基准视，点头项是
`A·cos θ + B·cos 2θ + C·sin θ`。前两项都是偶对称（k 与 k+6 相同），
**必须有一个奇对称项**（`sin`）才能把差 180° 的那一对分开。

### 离散度（`.shots/probe.json` 的 `spread`）

把整圈每格渲成剪影，量相邻两格的 IoU 均值与整圈最像的一对：

| 构造 | 步数 | 相邻 IoU 均值 | 最像的一对 | 重复度 |
|---|---|---|---|---|
| 三片正交薄板 | 8 | 0.488 | 5 / 7 | 0.712 |
| 三片正交薄板 | 12 | 0.556 | 7 / 11 | 0.890 |
| 十二边框架 | 8 | 0.092 | 5 / 7 | 0.170 |
| 十二边框架 | 12 | 0.112 | 7 / 11 | 0.346 |
| 空心棱壳 | 12 | 0.812 | 1 / 5 | **0.961** |

**读法：**
- 相邻 IoU 越小＝相邻两格越不像（定格才读得出来）。`frame` 0.112 极好，`shell` 0.812 极差。
- `shell` 的重复度 **0.961** 说明它 12 步里有两格几乎是同一张图：**这个构造不适合定格**，
  它的剪影太接近球，转起来只是在抖动。
- `tri` 在 12 步下重复度 0.890，偏高。这是它唯一的短板 ——
  但它的相邻 IoU 0.556 说明相邻格是分得开的，看得到的是一次「转动」而不是「跳一下」。
  如果要求整圈没有近似帧，得退回 **8 步**（重复度 0.712）。

### 推荐

| 场景 | steps | holdMs | 一圈 | 理由 |
|---|---|---|---|---|
| **240px 主视觉** | **12** | **110** | 1.54 s | 相邻格分得开；重复度 0.890 是可接受的 |
| 要整圈无近似帧 | 8 | 160 | 1.60 s | 重复度降到 0.712 |
| ≤96px | 8 | 160 | 1.60 s | 格子少、每格差得远 |

### 不用 rAF

姿态是离散的，格与格之间画面完全不动，所以用 `setTimeout` 链每格画一次就够 ——
与 `star-crystal` 同一套做法，也是这个仓库的口径（`toolstar.ts` 的帧循环「只在有东西在动时运转」）。
页签藏起来就 `stop()`，回来按时钟重推，不会错格。

## 6. 没做到的 / 与预期不符的

**1. `折起的星` 没有做到它名字里说的那件事。**
它现在是一张**弯板**，不是「四片平面」。
原因：`ExtrudeGeometry` 的 cap 三角化是 Delaunay，顶点在面内分布很稀，
给整张板的顶点加一个位移函数只会得到连续曲面。
要真的把折痕落到两条轴上，必须**自己按象限裁四个 sub-shape、各转一个角度**再拼。
这一条没做。

**2. `shell`（空心棱壳）好看但不是星。**
这是这个方向里唯一「接近回答六个尖」的做法，也是唯一没读出六芒星的。
它作为一块半透明多面体是成立的（后壁看得见），作为星不成立。
如果将来要的是「一块晶体」而不是「一颗星」，它比上一版的尖球好得多 ——
但它不是这次要的东西。

**3. 磨砂玻璃那一格（`06` 第三列）盖住了太多。**
`backdrop-filter` 把星糊成一片雾，只能证明「它是个层」，看不出构造。
`star-crystal/notes.md` 说这是「这一个原型最值钱的一格」，**在这一版不成立** ——
因为这一版的立身之本是轮廓与折痕，被糊掉之后什么都不剩。
这个格子留着是为了让这条差别被看见。

**4. 没有接进真实页面。**
只在 `#f0f3f6` 与 `#2a2b38` 两块纯底色上验过。真实页面有 14° 缝线、脑电波、漂移背景，
叠上去的观感可能完全不同。**这是落地前必须补的一步。**

**5. 光栅倍率写死 ×2。**
发丝边在 1x 下会断成虚线，所以 `DPR = 2` 是写死的，不跟 `devicePixelRatio` 走。
代价是低 DPR 屏幕上多花 4 倍像素。真正落地时要决定：
是接受这个代价，还是在 1x 下把暗边加粗到 2 倍。

**6. `probe()` 的覆盖率判据仍然不够硬。**
它量的是「与地面色的差」，能证明东西画上去了，不能证明**好不好看**。
这一版的结论最终全部落在肉眼看截图上 —— `01`、`06`、`11` 三张。
读数只用来排除「根本没渲染」和「尺寸下崩了」这两种情况。

**7. 与上一版的直接比较没有做。**
两版用的是不同的计时方法（上一版 wall clock、这一版 GPU timer query），
数字不可直接相减。要比较，得用同一支脚本重测上一版。

### 自检

页面暴露 `window.__star`：`parity()`（轮廓逐字符对照）、`probe()`（逐格覆盖与对比度）、
`spread()`（剪影 IoU）、`measure()`（GPU 计时）、`measureSizes()`（尺寸阶梯）。

控制台错误 0 · 页面异常 0。`.shot.cjs` 每次都会把这三类问题收集起来打印。

### 一处与仓库文档的差别

`docs/design/aesthetic-direction.md` 写「倾向：巨型框架、巨大的环、无用途的高塔……」。
这一版把「巨型框架」缩到了一枚 200–240px 的图层上，**「巨型」这一层意思是丢掉的** ——
得到的是「骨架」的语法（十二条棱、正交、节点），不是它的尺度。
如果这条线索要真正成立，它迟早得回到大尺寸（整屏的框架，星只是其中一个节点）。
这一版没有试那个。
