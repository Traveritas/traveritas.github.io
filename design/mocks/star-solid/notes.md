## 一、抽出来的数学

### 姿势

六个轴端点 `±x ±y ±z`，先绕竖直轴转 `yaw`，再绕屏幕水平轴压 `pitch`：

```
x1 = x·cos yaw + z·sin yaw
z1 = −x·sin yaw + z·cos yaw
y2 = y·cos pitch − z1·sin pitch
z2 = y·sin pitch + z1·cos pitch      // z2 = 朝向观者的深度，+1 最近
屏幕点 = (x1·r, −y2·r)               // SVG 的 y 向下
```

和 `drawStar()` 一式一样，连 `toFixed(2)` 的位置都没变 —— `octaStar(TOOLBAR_PRESET)`
写出来的六支字符串与 `legacyDrawStar()` **逐字节相同**（预览页 00 段现场对比，`.verify.cjs`
也会读回 `parity: true`）。

`pitch = 35.264°` 是 `asin(1/√3)` 的近似值。精确值是 35.2643897°，工具条里写的是截断后的
35.264 —— 原语保留了这个字面量（`TOOLBAR_PITCH`），另导出精确的 `ISO_PITCH` 备查。
两者之差在 40px 画布上约 0.0002px，肉眼与像素都无差。

### 为什么 yaw 一定是 45°

支长固定 16，投影半径却随姿势变：

| yaw | 6 支投影半径 | 轮廓 |
| --- | --- | --- |
| 0° | 16 · 16 · 13.06 · 13.06 · 9.24 · 9.24 | 三长三短 |
| 22.5° | 15.20 · 15.20 · 13.06 · 13.06 · 10.50 · 10.50 | 长短差 4.7 |
| 37.5° | 13.88 · 13.88 · 13.06 · 13.06 · 12.19 · 12.19 | 长短差 1.7 |
| **45°** | **六支全部 13.06** | **六支等长、互成 60°** |
| 52.5° | 12.19 · 12.19 · 13.06 · 13.06 · 13.88 · 13.88 | 镜像 |
| 90° | 16 · 16 · 13.06 · 13.06 · 9.24 · 9.24 | **与 0° 完全相同** |

所以：**整周里只有 `yaw ≡ 45° (mod 90°)` 那一格是正六芒星**，其余都是「长短相间的星」。
观感上不是「在转」，是轮廓在 9.24–16.00 之间呼吸。

`0° ≡ 90°` 是立方对称：绕 y 轴转 90° 把 x 轴与 z 轴互换，而 `±x ±z` 本来都在，整组支不动，只换了名字。
六支半径的重数表 │16, 16, 13.06, 13.06, 9.24, 9.24│ 完全相同 —— 预览页 01 段把这 13 格并排摆出来，
数字一样就是同一颗星。

### 支的形状（`flat`，即现役）

每支一张四角风筝，四个角（屏幕坐标，`u` 是支方向的单位向量，`n` 是它的法向）：

```
A = −n·1.9      B = 端点 (r·u)      C = +n·1.9      D = −u·1.4      →  A B C D 闭合
```

- `halfWidth = 1.9`：支在原点处的半宽。它决定支有多「胖」，也决定相邻两支之间那个凹口有多大 —— 见第二节。
- `notch = 1.4`：支尾越过原点往回伸 1.4。**这一笔是现役那颗星的关键**：它让六支在中心交叠、
  并留出中心那个深色的小孔。去掉它，六支会在原点缩成一点，星看起来像被掐住了脖子。
- 深度透明度：`opacity = 0.38 + 0.5·(z+1)/2`，远的支淡、近的支实。相邻支在交界处因此永远
  一深一浅 —— 这是现役那颗星全部立体感的来源，也是它作为「实体」的天花板（见第三节）。

相邻两支之间的**凹口半径 = 2.8135 用户单位**（六对都一样）。这是「还认不认得出是六芒星」的量尺：
凹口太浅，六个内角就糊在一起成一团墨点。

## 二、哪一种读成晶体

**折脊 `ridge`**。r11 那张对比图里它的标题就是「唯一读成晶体」——我把这个说法复核了一遍，**成立**，
但理由要说准：

| 变体 | 路径数 | 读起来是什么 | 判断 |
| --- | --- | --- | --- |
| `flat` 平风筝 | 7 | 六个深色贴片贴在屏上 | 贴纸。支内无明暗分界 |
| **`ridge` 折脊** | **12** | **一块被切过、透着光的薄片** | **晶体 ✅** |
| `pyramid` 四棱锥 | 20–24 | 有真棱真剔除，但底面把支根撑宽，轮廓变钝、中心糊成一坨 | 半晶体，但形脏 |
| `silhouette` 剪影 + 轴线 | 2 | 最干净也最平的一幅线描 | 图，不是体 |

`ridge` 的做法：把**同一张风筝**沿脊线（支尾 → 端点那根）折起来 —— 两侧的肩同时朝观者抬起
`fold = 0.14·r`，于是每支成了两片互成夹角的面。**轮廓一个像素不改**（端点、半宽、支尾全部沿用
`flat` 的四个角），只是把一个四边形换成了两个三角形，明暗按面法线算。

它读成晶体的三个条件，正好是 `flat` 缺的三个：

1. **支内部有明暗分界** —— 不是整支一个色；
2. **分界落在脊线上，与轮廓不重合** —— 所以看得出「有厚度」，而不是一个剪影；
3. **相邻支的明暗相反** —— 交界处才有一道立起来的转折，六支才像折在一起的一块料。

`flat` 三条全无（整支同色、分界只在支与支的边缘）；`silhouette` 只有轮廓；
`pyramid` 有前两条，但它为了造出内侧两道棱，底面必须在垂直于支的方向上张开成正方形，
于是支根变宽、轮廓的锐角被磨圆，中心还叠成一坨深色 —— 形脏了，反而不如 `ridge` 干净。

### 明暗区间是调出来的

`ridge` 默认 `facetMin = 0.08, facetMax = 0.94`（`.probe-facets.html` 做过 0.14–0.86 / 0.08–0.94 /
0.03–0.98 三档 A/B）。收窄到 0.14–0.86 时，每支两片的差只有 0.165–0.377，最窄那对几乎看不出折过，
星退回剪纸观感；拉到 0.08–0.94 后每支内部反差明显，脊线出一道亮线，才立得住。

## 三、尺寸阈值

用上面的凹口半径（2.8135 用户单位）换算成像素（`viewBox` 宽 40 单位），对照 `.shots/final-03-size.png`：

| 画布 | 凹口半径 | 星径 | 判断 |
| --- | --- | --- | --- |
| 24 px | **1.7 px** | 15.7 px | 六个内角糊在一起，读成**一团深色墨点**（细看还有形，1 秒内认不出） |
| **40 px** | **2.8 px** | 26.1 px | **最小还读得出**：六支分得开，是六芒星 |
| 48 px | 3.4 px | 31.4 px | 现役钮里的实际尺寸，稳 |
| 96 px | 6.8 px | 62.7 px | 六支清楚，但风筝的「平」开始露头 |
| 200 px | 14.1 px | 130.6 px | **平风筝撑不住了**：六片各是各的平三角，交界处只有线、没有面 |

- **下限 40px**（凹口 ≥ 2.8px）。现役就是 40px，刚好在线上 —— 再小一档就掉进「一团」。
- **上限 96px**，此后 `flat` 露馅。要更大就得换 `ridge` 或 `pyramid`：`ridge` 到 400px 仍然读得成
  晶体（`.shots/probe-*` 里验过），代价只是路径数 7 → 12。

顺带一个反直觉的点：**24px 那颗之所以糊，不是因为太小，而是因为 `halfWidth/half` 比例固定** ——
`halfWidth = 1.9` 相对 `r = 16` 是 0.119，放大缩小都不变，所以凹口永远按比例缩。要救 24px 只能
改比例（把 `halfWidth` 压到 ~1.5 或把 `notch` 拉长），那是另一套几何，这次没做。

## 四、代价与能不能 CSS 动画

| | 路径数 | 标记字节 | 每帧生成 |
| --- | --- | --- | --- |
| `flat` | 7（6 支 + 中心圆） | 678 B | — |
| **`ridge`** | **12**（6 × 2 片） | **1048 B** | **0.046 ms**（本机 node 实测，含字符串拼接） |
| `pyramid` | 20–24（随姿势变） | 2806 B | — |
| `silhouette` | 2 | 589 B | — |

`flat` / `ridge` 的路径数**恒为 12**，与姿势无关 ⇒ 节点可以在一次创建后原地改 `d`，
不必每帧 `innerHTML`。`pyramid` 因为背面剔除，面数会随姿势在 20/24 之间跳，只能整块重画 ——
这也是它贵的主要原因。预览页的 `paint()` 就是按「节点数 + role 序列是否一致」决定原地改还是重画。

**能不能 CSS 动画：不能，必须每帧重画 `d`。** 理由：

- CSS 只能补间 `transform` / `opacity` / `filter` 这类合成器属性。路径 `d` 的补间要在主线程上
  重算几何 —— 浏览器完全不做（`transition: d` 只有少数浏览器对同构路径支持，且仍是主线程）。
- 更根本的是：这颗星的「转」不是刚体旋转。`yaw` 一变，**六支的投影长度全都变**（16 → 9.24），
  任何旋转变换都做不出这个效果 —— 这是正交投影压扁带来的，不是屏幕上的旋转。
- 现役 `drawStar()` 每帧重画，正是这个原因；`Toolstar.astro` 里那句注释（`pointer-events: none`
  「星每帧重画：点在某一支上时，按下与松开落在两个不同的节点上」）也是同一件事的旁证。

### 定格（零阶保持）

预览页 02 段照站里既有的语言做：`yaw` 一格一格跳，每格停住。**路径 `d` 从不被 CSS 补间**，
靠计时器算「现在第几格」再写属性。控件：格数 8 / 12 / 16 / 24，每格停 60–200 ms，另有
「关（连续）」对照组。`.verify.cjs` 验过：定格时同一 40ms 内的 `d` 相同（真停住）、过一格必变；
切到连续后 45ms 内就变。一圈时长 = 格数 × 停留：

| 格数 @120ms | 一圈 |
| --- | --- |
| 8 | 0.96 s |
| 12 | 1.44 s |
| 16 | 1.92 s |
| 24 | 2.88 s |

现役梦面自转是 12°/s ⇒ 一整圈 90° 要 7.5s；换算成定格就是 24 格 × 312ms（比滑杆上限 200ms 还慢），
所以真要接进梦面，`hold` 上限得放宽。

## 五、没做到的

- **24px 糊成一团没有解决**。上面第三节说过，根因是比例而非尺寸，改比例是另一套几何。
  如果工具栏将来要缩到 24px（比如手机窄屏），得单独定一组 `halfWidth / notch`。
- **`pyramid` 没有调好**。它形式上最「真三维」（背面剔除 + 面棱），但底面正方形的朝向让我两次都
  没把它调到既保住轮廓锐度、又不让中心糊掉。`baseDepth` 从 0.34 试到 0.75，中心始终偏脏。
  结论里我按「读起来像什么」把它排在 `ridge` 之后，但这是我的实现没调好，不是这个思路本身不行 ——
  要接着做，应该让底面沿支方向压扁（不垂直于支），而不是继续调 `baseDepth`。
- **`ridge` 的 `fold` 没做参数扫描**。默认 `0.14·r` 是手调的，没系统扫过。`fold` 小则折角浅、
  明暗分不出；大则两片在屏幕上又重叠回去。这个值在 40px 与 200px 下是否都合适，没分开验。
- **没验 `prefers-reduced-motion`**。预览页的定格循环没有理会 `RM`；真要接进站点，这一路得加
  「RM 时停在某一格不动」（与 `toolstar.ts` 里 `ST.auto` 回正的做法一致）。
- **`opacityFar / opacityNear` 在 `ridge` 下的语义变了**。`ridge` 没用这两个值（它按面法线算明暗），
  而是用 `facetMin / facetMax`。API 上并存两组参数容易误用，接进 `toolstar.ts` 之前应该拆开命名。
- **`silhouette` 的轴线端点**用了个经验系数（`1 − (notch/r)·1.06`）让线不戳出支尾。这个 1.06 是凑的，
  不是推的。

### 与简报不一致的地方

- 简报说「前面那一支更实」，`NOTES.md` 也这么写 —— **准确说是「z 越正越实」，不是「前面」**。
  而且在 45° 这个姿势下六个 z 只有**两个值**（±0.5774），压到 `0.38–0.88` 之后全星只有**两种透明度**：
  0.486 与 0.774，中间一档 0.288 的跳。三支淡、三支深，没有渐变 —— 这是它读成贴片的直接原因。
  简报把 `fill-opacity = 0.38 + 0.5·(z+1)/2` 当作「立体感」，实测下来它只能算「分两层的透明度」，
  连「按深度的连续明暗」都算不上。
- 简报把「±x ±y ±z 六支，正等轴视角下投影成六芒星」当作恒真的描述。**只有在 yaw 45° 时成立**；
  其他姿势投影出来的是长短相间的星，不是六芒星。`yaw` 一动就不是六芒星了 —— 这点在简报里没写，
  而它恰是「定格」这一节最有意思的地方（每一格都是一颗不同的星）。
