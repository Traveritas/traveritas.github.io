## 1 · 那件东西与那个动词

**一枚几乎看不见的细环，长在指针上。静息时它只是指针旁一圈极淡的刻度环。**

动词是**合拢 / 绽开**：环慢转、随指针移动速度多转一点；按住或点开，十二道刻度一道道亮起，
环绽开成花瓣状的工具列——**四片宽的**（要地盘的：检索 / 筛 / 目录 / 读）+ **八片窄的**（一句话就完的：
视图 / 场景 / 归处 / 门 / 出口 / 面 / 环境声 / 刻）。靠近一片瓣，它张开自己的**花瓣玻璃**；
指针离开这一圈，环合拢，回到指针上。材料就是**细线（环）+ 花瓣玻璃（瓣与瓣上张开的那片）**。

### 接住站内已有的「凝露光核」，不是另起一个光标

原型里复刻了 `Cursor.astro` 的那一枚：同一个 `STAR` 路径、同样的三道环缺口（dasharray 按弧长算）、
同样的 16s / 27s / 41s 自转与梦面倾斜微扁、同样的二维欠阻尼弹簧（ω 26 / 19 / 14，软上限 4 / 7 / 10px）、
同样的 `pointerType === 'mouse'` 门控与 `fx-cursor-on` 藏原生指针。位置由 `ring.js` 逐帧写。
**真站接法**：把 `ring.js` 里写 `S.px / S.py` 的两行换成读 `cursor.ts` 的 `ptr`，环就是加在光核外面的一层，
不必有第二个光标。

### 刻度与花瓣是同一件事的两种体量

静息时的十二道刻度就是十二件工具的缩形（长刻度＝宽瓣，短刻度＝窄瓣，角度一一对应）。
按住时刻度一道道亮起（260ms 内亮满），满的一刻环绽开——**绽开不是跳出来的，是把刻度长成了瓣**。

### 花形为什么不是机械放射对称

每一片瓣的长度 ±8%、开角 ±4.5°、侧弯 ±0.25W，以 index 为种子（每次刷新一样）。
两层半径不同（宽瓣 58→120px，窄瓣 100→142px），插在 30° 的刻度上，所以是**两层错开的瓣**而不是一圈等分的齿。
瓣形是百合式的：窄基、宽腹、收尖，中脉一道细线。

## 2 · 十二件工具各自在哪、怎么到

绽开后，一件工具＝一片瓣。名字挂在瓣尖外侧（随瓣的角度转，但永远不倒过来）。

| # | 件 | 在哪片瓣 | 怎么到 | 到了能做什么 |
| --- | --- | --- | --- | --- |
| 1 | 检索 · FIND | 上（宽） | 靠近顶瓣 / 按住唤开 | 输入即筛：标题 / 描述 / 标签 / 正文 / 图注都搜。没命中的名录行**退焦**（opacity .16 + blur）并排到后面，计数变成「命中 / 总数」；回车打开第一条 |
| 2 | 视图 · VIEW | 上右（窄） | 靠近 → 点「名录 / 散落」 | 同一批东西两种看法；`V` 也行 |
| 3 | 场景 · SCENE | 右（窄） | 点即循环，或面板里直选 | 随笔 · 可言说的 SAYABLE / 瞬间 · 即逝的 EPHEMERAL / 项目 · 可构造的 BUILDABLE（梦面：断章 / 闪念 / 造物）；目录页滚到那一栏，阅读页换成那一条 |
| 4 | 归处 · HOME | 右下（窄） | 点即回主页 | — |
| 5 | 门 · NEXUS | 下右（窄） | 点即去门 | — |
| 6 | 出口 · EXITS | 下（窄） | 面板里选 | GitHub 仓库 / RSS（真去处，新窗口） |
| 7 | 面 · SIDE | 下左（窄） | 点即翻面，或面板里选醒 / 梦 | 另有**按住环心 1400ms** 翻面（对应 reality.ts 的长按，见第 6 节） |
| 8 | 环境声 · SOUND | 左（窄） | 点即开关 | 三根微弦跟着亮；原型级 WebAudio（两个正弦 + 一个三角过 lowpass + 慢 LFO），失败静默 |
| 9 | 目录 · CONTENTS | 下（宽） | 阅读页靠近 | 列出 h2（主刻度）/ h3（细刻度），点即跳；不在阅读页时明说「去阅读页，瓣上会长出刻度」 |
| 10 | 读 · READING | 左（宽） | 靠近 → 选 | 字号 小 / 中 / 大，行距 常 / 疏；写 `xm-read-size` / `xm-read-lead`（与 `Gauge` 同键） |
| 11 | 筛 · FILTER | 右（宽） | 靠近 → 点标签 / 年月 | 标签 chip + 年月；命中数 + 结果（点开即读） |
| 12 | 刻 · HOUR | 上左（窄） | 靠近 | 真实时刻 23:07 → 06:31（一夜 444 分）、分期名（清醒 / 浅梦 / 深眠 / 异相…，取 `night.ts` 的 SEGMENTS / STAGE_INFO）、此刻百分比；五个路标点了滚过去。同一进度也画成**环上的琥珀弧** |

### 「小工具塞进花瓣会很挤」的排法

不把十二件排成十二片等大的瓣，而是**两档**：

- **四片宽瓣**给需要地盘的（检索 / 目录 / 读 / 筛）。靠近时**一次只开一片**，其余收拢、退到 0.28 的透明、
  半径退 8px 让位；开的那片是 ≤20rem × ≤21rem 的可滚花瓣玻璃。
- **八片窄瓣**给一句话就完的（视图 / 场景 / 归处 / 门 / 出口 / 面 / 环境声 / 刻）。只放「中文小标签 + 英文」，
  字号 0.72rem / 0.5rem，两行 38px 高、最宽 51px。十二个名字两两不重叠、都在屏内（脚本断言，见 `26-layout-labels`）。

也就是说：**挤的不是瓣，是内容**。要内容的那四件各有整片瓣，不要内容的那八件只占一条缝。

## 3 · 三条召唤路径（唤出的是同一个面）

| | 怎么走 | 截图 |
| --- | --- | --- |
| ① 常驻边缘露头 | 指针停住 2.2s（触屏没有指针，一开始就在）→ 环离开指针、贴到最近的一缘，只露出一小段弧（r=46 的 96° 弧，圆心落在缘外 8px，屏内看见约 34px 深的一条）＋三小道刻度＋一粒琥珀。**点它**，环滑进来在那一处绽开。触屏默认贴**下缘**（拇指够得着） | `07-path-edge-peek` · `08-path-edge-open` |
| ② 指针跟随（主路径） | 环跟着指针走，随移动速度多转（静息 3.4°/s，快划到 +30°/s）。**按住 ≥260ms** 绽开；指针离开花开半径×1.5 且不在花瓣玻璃上，320ms 后合拢 | `09a-path-follow-rest` · `09b-path-follow-bloom` · `09c-path-follow-closed` |
| ③ 快捷键 | `R` 把环唤到屏幕中央**直接绽开**，焦点落在第一片「点下就成」的瓣上；`← →` 换瓣、`↓` 进面板、`Esc` 合拢 | `10-path-key` · `10b-path-key-next` |

另外，**点环上那一圈刻度**（快按时离环心 26–62px）也算「点开」。两种手法都吞掉那一下点按，
不让它落到页面上（`S.swallow`）。

**同一个面**：指针跟随与快捷键唤出的瓣，id 序列完全一致（脚本断言 12/12，截图 `11-same-face`）。

按住的分层：260ms 绽开 → 继续按住到 1400ms 翻面。所以一根手指上叠了两件事：**先开，再翻面**。

### 环怎么在两种底子上都看得见（也是「静息要几乎看不见」的平衡点）

**环借光**：三栏并排时，环的墨色按**指针底下是哪一栏**来取（各片底子的矩形缓存起来，指针一动就判定，
不做节流——节流会让环借到「移动起点」那一栏的光，这个 bug 犯过）。更进一步，**每一片瓣按自己底下那一栏取墨**，
所以花开在三栏交界上时，左边瓣名是深墨、右边瓣名是浅墨（`26-layout-labels`）。

静息与绽开两档，浅底深底各量一次（`scene.js` 的 `report()` 按令牌算；`.shot.cjs` 的 `probe()` 再从**真像素**核一次）：

| --- | --- | --- |
| 静息 · 发丝环 | 1.22 | 1.44–1.47 |
| 静息 · 刻度 | 1.43 | 1.99–2.03 |
| 绽开 · 环上最亮/最暗（真像素） | 1.88 | 3.31 |
| 瓣面 / 底子（真像素） | 1.2（靠 1px 边立住，边 10.75×） | 14.05（一层薄膜） |

| 小标签（页面 / 玻璃上） | 5.13 / 6.09 | 8.26–8.67 / 6.44–6.7 |

阈值 1.15 / 1.3——它们不是文字，是那件东西本身。

## 5 · 我认为这个方案成不成立、最弱在哪

**成立的部分。** 「工具长在你手上」这条在触屏上最顺：一个手势（按住）就开，不用先找按钮再对准。
「刻度 → 花瓣」这层转喻自洽：静息时那十二道刻度本来就是十二件工具的缩形，按住时刻度一道道亮起，
正好是绽开的前奏；花是简报点名的母题，而「靠近就开、离开就合」是这个物件天生的行为，不用额外解释。
四宽八窄的两档排法把「挤」的问题从「把十二件塞进一个圆」变成了「让要内容的四件各得一片瓣」。

**最弱的三处**，按严重程度：

1. **静息的可见度是个两难，我没把握划对了线。** 压到「几乎看不见」时（浅底发丝 1.22 / 刻度 1.43），
   第一眼很难发现指针上还有一圈环；再淡一档就真的没人会去按它。我选的这个点靠「按住会亮刻度」来补偿，
   但**这条线要人眼在真机上定**（第 6 节第 1 条）。这是这个方案最脆的地方。
2. **环与光核的关系没说清。** 指针停住后环离场贴到边缘，光核（星）留在指针上——画面里同时有两件东西。
   真站里也许该让星一起走，或者让环不离场、只是变淡。原型按简章第 2 节「指针停住 → 环贴到某一缘」做的，
   但这是我没想透的一处，不是实现问题。
3. **花瓣玻璃是「第二层」。** 花开在指针上、那片玻璃开在瓣外，指针得再走一段才碰得到面板——比
   「面板就开在原地」多一次移动。宽瓣的面板我尽量贴瓣尖放、并夹在视口内，但花开在屏幕角上时会翻到对面，
   跟环的关系就松了。另外「点下就成」与「点开才成」两种手感并存（前者是视图/场景/归处/门/面/环境声，
   后者是检索/目录/读/筛/刻/出口），学一次的成本还在。

还有一处是**取舍不是弱点**：环加花很容易滑向特效（简报禁止「过度夸张」）。我把花瓣压到「细线 + 一层薄白」——
浅底上瓣面只比底子亮 1.2，全靠 1px 边和一点投影立住；深底上是一层 14 倍的薄膜；刻度只亮到琥珀，
不做发光、不做粒子、不做放大回弹。这条线也可能划过了头（太素）。

## 6 · 发现了但没处理 / 需要人眼确认

### 没处理的

- **长按与站内 `reality.ts` 冲突。** 这里 260ms 就绽开、1400ms 翻面；站内是 1300 / 2200ms 长按换面。
  两套手势叠在同一根指针上，真站要么合并，要么让环在长按期间闭嘴。
- **触屏长按与浏览器默认行为可能打架**（选字、呼出菜单）。原型用 `preventDefault` 吞了那一下 click，
  真机上要试。
- **检索是「即时筛」**，不是真站要的整站搜索；只搜了 `layout-plane` 的 7 条真内容。
- **环境声是原型级 WebAudio**，不是站内的 BGM 换面机制；`Sound.astro` 的整页电平退避也没接。
- **花瓣玻璃的余量很小。** 软件渲染（swiftshader）下 `backdrop-filter` 只看得见「背板根」，
  一块透明的板子会在深底上被算成亮底（我踩过：面板在深底上整块发白）。所以板子本身给到 0.82–0.88 的不透明度，
  磨砂只吃剩下 12–18% 的余量。真机上可以再透一档。
- **减弱动效**：动词退成直接显示（V 直接到 1）、光核不转、环不自转、边缘露头不呼吸；功能都在（`25-rm-bloom`）。
- **没做**：无脚本兜底（只有一句提示）；真机手感（迟滞、跟随的软硬、绽开的快慢）；更复杂的底子
  （半张图压在夜色上、正文里插图片）。
- 三栏之外，`grid` 的 `散落` 看法只是把浮窗绝对定位错开，没做真正的空间感。

### 需要人眼确认的帧（我看不到图，以脚本里的断言与报告数值为准）

1. `01-ctx-home` · `03-ctx-read` · `05-ctx-404` — **静息环的可见度到底合不合适**（浅底发丝 1.22 / 深底 1.44）。
   这是最需要人眼的一处，数值只能说明「有」，说明不了「够不够被看见」。
2. `07-path-edge-peek` · `08-path-edge-open` — 边缘露头那一小段弧（屏内约 34px 深）是不是「看得出这里可以」；
   点开后环滑进来绽开的位置对不对。
3. `09b-path-follow-bloom` · `10-path-key` · `23-m-390-bloom` — 花开之后十二片瓣的疏密、抖动幅度、
   两层半径的层次好不好看（用户要的「避免机械放射对称」+「构图有层次的丰富度」）。
4. `26-layout-labels` — 花开在三栏交界上（瓣名一边深一边浅）读不读得顺。
5. `12-verb-025` / `12-verb-05` / `12-verb-075` — 绽开中途是不是「一片片开」而不是一起开；这一层错开够不够。
6. `27-pixels-deep` / `28-pixels-shallow` — 花瓣玻璃的厚度（1.59 / 1.34）。太薄像贴纸，太厚像塑料。
7. `04-ctx-gate` — 门那一屏本来就有一个大圆环（门），工具环又是个环，两个圆同屏会不会混。
8. `13-hold-mid` — 按住时刻度亮起 7/12，够不够当「快开了」的预告。
9. `09c-path-follow-closed` — 合拢之后环回到指针上的过程顺不顺（截图只能看静帧）。
10. `25-rm-bloom` — 减弱动效下的直接显示。

**方向未定稿**——四条路并排比过之后再定。
