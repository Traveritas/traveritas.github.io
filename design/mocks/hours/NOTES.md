### 强调墨：新起 `--hour-ink`，不动 `--umber`

`--umber`（醒 `#556270` / 梦 `#765640`）在站里同时当「次强调墨」用：目录页年份、
瞬间年号、随笔文末小签、导览薄片小标题、正文里的链接、悬停时的标题……浅底上是
5 上下的对比，**深底上只剩 2.6**，等于看不见。因为 `--umber` 由 `reality.ts` 每帧
写在 `<html>` 行内样式上（BRIEF §5 点名不能覆盖），所以另起 `--hour-ink`：

- 浅色时辰（A 浅梦 / A 晨光 / B 全部）：`--hour-ink: var(--umber)` —— **一个值都不改**，
  这几支的成品与现状逐值相同。
- 深色时辰（A 深眠 / A 异相）：`color-mix(in srgb, var(--umber) 52%, #fff)`。
  与 `--umber` 同源，所以照样跟着醒梦两态插值（梦面偏暖沙、醒面偏冷灰），
  实测对深眠底 7.6 / 对异相底 6.9。

## 2 · 外壳修正四项怎么做的

四项都挂在 `html[data-hours][data-hour]` 上（不是只挂 `html[data-hours]`），
理由见 `hours.css` 开头的「前缀约定」：组件的作用域样式最深能到
`.coverband[data-astro-cid] .ghostno[data-astro-cid]`（0,4,0），只写
`html[data-hours]` 是压不过它的 —— 实测这条正是幽灵编号先没吃到，改成双属性前缀后
每条规则都稳在 (0,4,x) 之上，不再依赖「hours.css 恰好排在 `<head>` 末尾」。

**1）隐藏背景方块** —— `html[data-hours][data-hour] .fld-bg { display: none }`。
整层撤掉（不是降透明度）：它按 `--reality-mix` 在拼接 / 错开之间动，是醒梦缝的
仪器层，内页换成某个时辰的底色后它既不为那个时辰服务、又把底色搅花。
`display: none` 不移除元素，主页那个写内联动画的生成器照常找到 `#fld-bg`，
全量截图里主页无报错。
⚠ 这条**也作用于主页**（BRIEF 的表格把「隐藏背景方块」归在外壳修正里）。如果将来
只想让内页撤掉、主页留着，把选择器收成 `[data-hour='shallow'|'deep'|'rem'|'dawn']` 即可。

**2）中文不走等宽** —— 不是逐个选择器补字体，而是**重写 `--font-mono` 自己**：

```css
html[data-hours][data-hour] {
  --font-mono: 'IBM Plex Mono', ui-monospace, 'Cascadia Mono', Consolas, 'JetBrains Mono',
    'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei UI', 'Microsoft YaHei', 'Noto Sans SC',
    monospace;
}
```

一处改，全站生效：导航、`.xfile-t`、`.year`、`.row-date`、`.row-aside`、`.wn-label`、
`.wc-foot`、`.g-h`、`.tag-chip`、`.prose-meta`、`.pin-sub`（主页那四个时辰小签）……
西文与数字仍旧命中 `'IBM Plex Mono'`（一个字都没动），中文在 generic `monospace`
之前落到系统黑体。`--font-mono` 只在 `tokens.css` 的 `:root` 里声明过一处，
没有任何脚本读写它。

**3）手机 390px 导航不折行** —— 现状是 `.header-row` 用 space-between、品牌带
`min-width: 6.8em`、导航 0.75rem / 1.15rem 间距，390px 时容器只有 342px，
导航被压到每项 19px、「随笔」折成两行。修法：≤600px 把三处间距各收一档
（header 1.5→0.75rem、nav 1.15→0.72rem、项内 0.5→0.34rem、字号 0.75→0.72rem），
并给 `.site-nav a` 加 `white-space: nowrap` 兜底。实测 390px：
链接盒 40×31（单行），`off` 对照 37×55（两行），页面无横向溢出。
品牌 `min-width: 6.8em` **保留** —— 它撑的是醒「Traveritas」与梦「AveritA」两个长度
之间不跳的盒宽，收掉它换面时导航会横移。

**4）页头与内容列左缘对齐** —— 让页头 / 页脚跟着**本页正文列**走：

```css
html[data-hours][data-hour] body:has(.container-wide) .header-row,
html[data-hours][data-hour] body:has(.container-wide) .footer-row {
  width: min(100% - 3rem, 56rem);
}
```

页面里有 `.container-wide` 就同宽 56rem（目录页 / 瞬间 / 标签页），没有就维持 42rem
（阅读页 / 404）。实测 1440：目录页页头 272/896，与 `h1`、`.container-wide`、
页脚四处完全重合（现状：页头 384/672 vs 标题 272/896，差 112px）。
标签页那 35px 的差另有一半来自 `.knot-head` 的 `padding-left: 2.2rem`，
把结挪到列外（`left: -2.2rem`）后标题左缘回到列线上；窄屏空间不够，结留在列内
（`@media (min-width: 768px)`）。

**这个办法的代价**（也是我犹豫最久的一处）：从目录页点进文章时，页头会横移 112px。
我选「按页对齐」而不是「页头永远 56rem」，理由是落页体验优先：BRIEF 的问题就是从
主页点进项目后「时辰断了」，落地时页头与正文不共线会把这种断感放大；而阅读页上
正文列是整页唯一的主体，页头若永远停在 56rem，会在最常停留的那类页面上留下一条
永远看得见的 112px 错位。`:has()` 不认的老引擎整条规则作废、回落现状，不会更差。

浅色时辰那一支把原来的字面值**原样**收进变量（薄片底 .6、边 .85、高光 .6、hover .68、
投影 `38/44/51 .12`、标签底 .32），所以浅色时辰的成品与现状逐值相同，只有底色与
雾光换了 —— 这样 A / B 与「现状」的对比才是公平的。

## 4 · 我发现但没处理的问题

1. **`.wash-backdrop` 不动是故意的。** 它是 z −5 的 7% 醒梦洗染
   （梦端 `#8a5a30` / 醒端 `#556270`，由 `--reality-mix` 驱动），而它是 `BaseLayout`
   常驻的 —— 主页夜里也铺着同一层。所以变体 A 的内页**留着它才与主页那一段是同一个
   色**；撤掉反而比主页少一层。变体 B 是浅底，7% 更看不出来。
2. **脑电线（`.eeg-main`）在深底上变淡。** 它 `stroke: var(--umber)` + `opacity .62`：
   实测对比度 现状·梦面 2.69 → A 深眠·梦面 **1.75** / 醒面 1.83、A 异相 1.67。
   没动它，因为**主页夜里也是同一条淡线**（storyboard 不改 `--umber`），这是全站性的
   问题、不是「时辰页」的问题；单独给内页提亮会让内页与主页不一致。要不要提亮请站长定。
3. **关于页的天空 / 水面 / 页脚没有跟着晨光换。** `.about-sky` / `.about-stage` 的
   渐变与 `:global(.site-footer)` 的水色 `rgb(199 190 204)` 是晶体那一场戏自己的画
   （和主页故事板同理），我没碰；所以 `/about/` 上晨光底色只在正文区可见，
   晶体页仍是淡丁香天。正文区（暖奶油）与天空（淡丁香）之间靠舞台的 `mask-image`
   过渡。这是取舍，需要人眼确认（见第 5 节）。
4. **开屏面纱（`BootVeil`）是写死的浅色**，一个会话首访会放。截图脚本预热过
   `xm-boot-seen`，所以对照图里没有它。若用干净会话直接进深色项目页，面纱仍是亮的
   —— 但它是整屏的一件美术资产（主页夜里也是亮的），不在这个原型的射程内。
5. **瞬间大图层 `.g-box img` 的投影** `rgba(38,44,51,.28)`：深底上是一层看不见的
   深投影。无害（图后面本来就有 82% 的底色遮罩），没改。
6. **`.fld-bg` 一并从主页撤掉了**（BRIEF 把它归在外壳修正里）。若站长只想内页撤、
   主页留，见第 2 节第 1 条的收窄办法。
7. **`--fg-faint` 在 B 四支上是 2.77–2.94**（浅梦现状是 2.94）。它只用在
   `.g-find input::placeholder`、`.snd-str`、`.about-tag` 上，不在 BRIEF 的探针名单里，
   也没有正文用途；数值列在这里以免看起来像漏了。
8. **唯一一条控制台报错**是 `/favicon.ico` 的 404（见第 0 节），与本原型无关。

## 5 · 需要人眼确认的地方

全量截图每页只拍 2 屏（`MAXSEG=2`），关于页的晶体一屏与项目页的文末几块都落在第 3 屏
之后，所以另跑了一轮一次性探针补拍（脚本放在临时目录，没进仓库；`.shots/x-*.png`
就是它的产物，`.shots*` 在 `.gitignore` 里，不进仓库）。要用现成的脚本复现这两处：

```bash
# 关于页整页（含晶体一屏）
MSYS_NO_PATHCONV=1 VARIANTS=a,b,off ROUTES=/about/ MAXSEG=9 node design/mocks/hours/.shot-hours.cjs
# 项目页整页（封面 / 注记 / 互链 / 相关链接 / 文末导航）
MSYS_NO_PATHCONV=1 VARIANTS=a,b,off ROUTES=/projects/personal-website/ MAXSEG=9 node design/mocks/hours/.shot-hours.cjs
```

我能读图，下面这些我逐张看过了（结论写在括号里）：

- `cmp-d-wake-projects-0` / `cmp-d-dream-projects-0`（A 的深靛目录页成立，
  年份与互链的暖沙色读得清；B 的淡靛与现状能分开）
- `cmp-d-wake-moments-0` + `d-wake-moments-a-0` + `x-dream-mid-moments-a`
  （A 的暗紫 + 磨砂薄片是这一组里最好看的一屏；薄片边界够不够，我看是够的）
- `cmp-m-wake-projects-0`（390px：现状「随/笔」折成两行，A/B 单行）
- `cmp-d-wake-tags_醒梦-0`（结挪进页边后标题与页头共线）

**探针测不出、得由站长定的：**

1. **变体 B 的四个底色是否「一眼分得开」。** 数值只差 8–24 个通道值，
   最弱的一对是浅梦↔深眠。这是感知判断，我看图觉得能分，但这是我一个人的眼睛。
2. **A 深眠 / 异相的雾光强度（0.18）。** 现在是一层很薄的蓝 / 紫雾光。
   偏淡则像「脏灰」，偏浓则盖过夜色 —— 这是我拍的数，最可能需要调的一处。
3. **深底上磨砂薄片的可见度**（`.sheet` 底 0.10、边 0.20，hover 0.17）。
   暗紫那屏我看是够的；深靛目录页没有薄片，另一处薄片在导览轨的展开面板里
   （要悬停才出来，截图拍不到，我只核了计算值：底 = `--bg` 70% + 磨砂、边 0.165）。
4. **关于页晨光底与晶体天空的接缝**（第 4 节第 3 条）。
5. **脑电线在深底上的淡**（第 4 节第 2 条）—— 这是全站性的，不只是本原型。
6. **B 深眠的 `#e7edfb` 是否读作「靛」**，还是只是「更蓝一点的白」。
   色相 267 是靛的位置，但 C 卡在 0.02，观感由站长定。

## 6 · 我倾向哪一支：A「整夜」

理由三条：

1. **它是唯一真正回答 BRIEF 那句抱怨的。** 从主页「深眠」点进项目，落地就是那片
   深靛、同一层雾光 —— 时辰没断，这是「版块＝时辰」这个题目本身要的东西。
   B 的四张浅底更接近现状，换页时是「换了点色调」，不是「还在那一夜里」。
2. **它保留了主页自己的明暗交替，而不是把它抹平。** 故事板里「浅梦 / 晨光」本来就是
   浅色段，所以 A 之下 `/articles/`（浅梦）与 `/about/`（晨光）仍然是浅的 ——
   长文阅读留在纸上（宋体夜话那套排版、`--umber` 链接、晓线全都原样成立），
   只有「仪器感」的两段（项目 / 瞬间）沉进夜里。这个分工正好与站点自己的气质对得上：
   名录与正文是醒态，造物与闪念是梦态。
3. **它把「瞬间」那一屏做成了这一组里最有气氛的画面**（暗紫底上的磨砂薄片），
   而 B 会把这一屏的暗紫身份换成一张淡紫页 —— 那是这一组里最可惜的一处损失。

B 不是没有优势：**它几乎不动任何东西**。因为每一支都是浅底，`--umber` 一族、
`--ghost-ink` 残影、脑电线、写死的白玻璃全部原地成立，只有 `.fld-bg` 与字体两项
外壳修正会真的改变现状 —— 换句话说 B 的风险最小、最不挑内容。如果站长的判断是
「内页一律以阅读舒适为先、时辰只做一层薄薄的色相」，那 B 是更稳的答案，
代价是四个时辰的差别会一直停在「一层薄薄的色相」这个量级上。

两支我都没有定稿的意思：A 的浅梦 / 晨光两页与现状差别很小（第 1 节末），
这是它的短处；B 的四张浅底差得也不大，这是它的短处。**真正的选择其实是
「深色只留在主页」还是「深色跟着版块走」**，而这个选择请站长看完并排图再下。
