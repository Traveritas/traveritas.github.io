# 浮游碎片（布局原型 · 方案一）

主题：模糊 / 碎片 / 梦 与 光，加像素感。随笔、瞬间、项目各是一个场景：背景是像素化的流光，内容是远近不一、悬浮着的碎片；视角可以自由拖动、沿景深推拉，三个方向都无缝循环。

## 运行

```bash
node design/mocks/drift/server.cjs    # http://localhost:4620/drift/   （?scene=essay|moment|project 直接进某个场景）
node design/mocks/drift/.shot.cjs     # 截图 → .shots/（ONLY=scenes,drag,zoom,open,mobile）
ONLY=looks NAMES=facet node design/mocks/drift/.shot-v3.cjs      # 第三轮变体 → .shots/v3/
NAMES=thaw node design/mocks/drift/.shot-scheme.cjs              # 第四轮方案 → .shots/scheme/
```

服务根目录挂在 `design/mocks/`：数据与配图直接取 `../layout-plane/data.js` 与 `../layout-plane/assets/`（只读，不复制）。截图用本机 Chrome + swiftshader 跑 WebGL2。

文件：`index.html` · `drift.css` · `light.js`（流光着色器）· `cards.js`（画卡片与失焦档）· `deco.js`（装饰的排法 / 景深 / 失焦）· `drift.js`（空间、弹簧、输入、聚焦、场景、变体面板）· `reader.js`（阅读层）· `reg.js`（注册表 + 公共绘制助手）· `variants/`（每个变体一个文件，接口见 `variants/README.md`）· `SCHEMES.md`（第四轮方案的提案）· `server.cjs` · `.shot.cjs`（第一轮）· `.shot-v2.cjs`（第二轮 → `.shots/v2/`）· `.shot-v3.cjs`（第三轮 → `.shots/v3/`）· `.shot-scheme.cjs`（第四轮 → `.shots/scheme/`）。

## 变体（第二轮）

地址参数切换，右下角「变体」面板可点选（点了换地址重载，场景保留；面板默认收起，展开状态记在 localStorage）。默认值加粗。

| 维度 | 取值 | 做法 |
| --- | --- | --- |
| `?bg=` 背景跟镜头 | **heavy** | 背景偏移是一个独立的软弹簧（ω = 2.2，ζ = 0.9）追 cam × 0.08：起步慢、停得晚。**第三轮定为默认** |
| | stir | 平移只有内容行程的 3%；镜头在屏上的速度（uv/秒）平滑后喂进着色器：沿速度方向把采样空间压扁（光被拉成流痕）、叠一层高频扰动进 domain warp（搅乱）、并累积一个漂移（流痕顺着拖动方向走）。起势 70ms，消散时间常数 0.4s（约 1.2s 归于平静） |
| | direct | 第一轮的做法：背景硬连镜头，约为内容行程的一半——拖动时整片光一起滑，生硬 |
| | ratio | 硬连，但行程只有 6% |
| `?look=` 碎片外观 | **frost** | 半透明磨砂片（第一轮） |
| | glow | 没有面板：字 / 图背后一团场景色的椭圆漏光（画到卡片外 26 单位），边缘散几粒 2–3 单位的像素光点；点数少、沿边随机、法向 ±8 错开，不连成虚线 |
| | slab | 厚玻璃：三级像素阶梯斜边（左上亮、右下暗，每级 3 单位、越往里越淡），底更透；CSS `backdrop-filter`（轻模糊 + 提饱和 / 亮度 / 对比）让后面的流光更清楚地透过来；元素按阶梯 clip-path 裁 |
| | print | 偏暖不透明相纸（每个场景纸色略不同）、纸纹像素、上沿一道白；右下 7 / 9 单位处的 Bayer 抖动像素投影，越往外越稀；墨色统一压深 |
| `?hover=` 悬停 | **pull** | 不论在哪层，悬停那份立刻跳到清晰档、不透明，缩放 ×1.08（弹簧），层级只往前提约 0.4 层，不越过真正更近的碎片 |
| | sweep | 一道三段硬边的光带沿 14° 扫过卡面（`steps(12)`，0.72s，像素地跳进），扫完边缘留 1px 亮线；随笔用琥珀色，其余用场景亮色 |
| | lean | 卡片朝光标做最多 4.5° 的 3D 倾斜（独立弹簧），420px 内的邻近碎片沿径向让开最多 22px |
| `?open=` 展开 | **fly** | 第一轮：镜头穿过景深飞到那块（一路对焦），再从它的矩形展开 |
| | grow | 镜头不动。面板的几何（left / top / width / height，不做非等比缩放）从碎片原位长到阅读尺寸，面板里钉着碎片自己的清晰图、按卡片比例随之变宽，长到一半后一跳一跳地退掉、正文接上；其余碎片被弹簧从展开处向外推开（最多 340px）、粗一档、淡 35%；收回时回流 |
| | pixel | 镜头不动。碎片在原地每 80ms 粗一档直到最粗，面板一跳出现，碎片的画面铺在上面从最粗一档档对回清楚（每 110ms），再让位给正文——跳焦的反向；收回时反过来，碎片落回后再一档档对回焦 |
| | page | 镜头不动。碎片带着 24° 的后仰朝镜头滑近、立起，成为一页偏暖的纸；其余碎片沿 Z 退远（δ × 1.75）、变小变粗 |

随笔场景的收敛：着色器的抖动强度按场景（随笔 0.42、其余 1）、量化阶数（随笔 40、其余 26）、亮芯与光带强度（随笔 0.16、其余 0.38）在切场景时一起插值，浅色底上不再像网点印刷，推近后也没有大块死白。

## 变体（第三轮）

第二轮把变体写死在 `drift.js` / `cards.js` 的分支里，加一个要改三处。这一轮先抽了注册表：

- `reg.js` —— `DriftReg.look / hover / open / deco` 四个登记口，加上公共绘制助手（`hash`、`stepPath`、`toLODs`、`BAYER`、`rgba`、`dotEdge`）。登记时若带 `css:` 字段，样式自动插进 `<head>`。
- `variants/<kind>/<name>.js` —— 一个变体一个文件，加载时把自己登记进来。接口见 `variants/README.md`。
- 变体面板与 `?<kind>=` 的取值都从注册表长出来，不再维护第二份名单。
- 新增第四个维度 `deco`（装饰）：与碎片共用同一套空间（层、z 周期、δ、缩放、失焦档、弹簧迟滞），所以景深与视差是白拿的，`motion` 只管它自己的飘。引擎在 `deco.js`。

**背景（`?bg=`）已定：`heavy` 重弹簧。** 这一轮没再动它，下面只列新设计的三个维度与装饰。

### 外观（`?look=`）· 在第二轮四个之外新增四个

| | 做法 |
| --- | --- |
| **facet** 棱面 | 水晶棱面碎块。外形取矩形的四角沿对角线往外拉、边仍保持直线（±1.5 抖动），得到一块「切割过的料」；卡面内部用 8 个由条目 id 决定的种子点做 Voronoi 切分，每块棱面按它在光里的位置叠一层白 / 黑（左上为正），偶尔一块偏色，并沿每块棱面的边描一道淡内反射线；再压对角明暗洗、一道 5 单位外棱。远处像素化后是碎块而不是玻璃方片 |
| **petal** 花瓣 | 俯视的百合：四片宽瓣各甩向一个角，瓣根在花心附近抖动、两侧一宽一窄、瓣长取到画布边界的 0.88–1.0，宽度曲线最宽处在靠瓣根三分之一、往瓣尖收成长尖（指数 1.45），轮廓叠两条慢波。背面另压一片更短更淡的瓣。正文用 `inset: 12` 收进花心。**界线只描每片瓣「最宽处往瓣尖」的那一半**——描到瓣根会在花心周围各连出一个圈，交叠起来就是几道横穿卡面的圆弧（第一版就是栽在这里） |
| **resin** 树脂 | 厚而圆润的半透明块：圆角矩形的弧线量化到 6 单位格子（近处是台阶、远处仍圆润），底子是场景自己的暖白做上下渐变，里面一团偏暖的散射晕、迎光侧一个亮芯、底部一点沉降；边光是「宽柔光 + 窄亮棱」两圈，再压一道只取上缘、一道只取底边的内棱——厚度感在这两圈之间。文字用纸墨 |
| **membrane** 薄膜 | 最轻的一个：切角 + 边微微鼓起的不规则四边形（刻意不对称），主体是几乎透过去的花心到边沿变实的径向渐变，再叠四道同心的色带描边，共用一道淡紫→淡青→淡金的渐变——颜色只在边上露。这是审美简报说的「少量克制异质色作记忆点」 |

投影都没用网点：网点在浅色底上会散成一片小点看着像脏，而且复杂外形的 `clip` 会让每一格都重走一遍路径（实测每张卡四秒以上）。现在用「外形错开 6/8、`filter: blur(6px)` 一份」的柔影。

### 悬停（`?hover=`）· 新增四个

| | 做法 |
| --- | --- |
| **breathe** 呼吸 | 霜被指尖化开：`::before` 一层贴着四边的暖雾（边缘 0.17、内里 66% 处归零，所以只糊边不糊字）+ 棱线亮边 + 外晕，本体提亮一档；进 0.6s / 出 0.7s，落定后剩一次 4.2s 的极慢明暗起伏，`scale` 钩子再给 ±0.5% 的鼓收 |
| **defocus** 退焦 | 全部效果都在别处：留下的那块钉在最清楚档，其余 `lod + 1`、透明度 ×(1−0.22q)。回来的节奏按距离排序（离目标越远门槛越低），所以模糊从它身边向外漫开、又沿同一条路一档档退回。**四个里梦感最强的一个** |
| **ripple** 涟漪 | `enter` 里把光标在卡面内的位置算成百分比写进 `--rx/--ry`，CSS 用硬边的三圈 `radial-gradient` 配 `transform-origin` 整体放大，9 段手写关键帧 + `steps(1, end)`。波过去后 1px 内描边延迟浮出，算涟漪留在棱上的湿痕 |
| **echo** 重影 | `.frag.hot::before` 用 `background-image: inherit` 借本体那张卡面（换档、换场景自动跟），按 `data-lod` 给错位量（清楚档约 5×6 世界单位，lod 3 涨到 5.4%/11.4%，否则一个像素就十几单位、错位等于没有）；4.6s 一循环——甩出去、追回到 42%、再落到 86%、收回原点 |

悬停的门槛从 `drift.js` 里硬写的 `lod ≤ 1` 改成变体的 `gate(rec, api)`：远处只有粗块，默认不放行；`gate: () => true` 是最宽。**别用 `lod` 钩子偷偷把远处的碎片拉清楚来骗过门槛**——那是拿整片场景的景深线索换一次悬停。

### 展开（`?open=`）· 新增四个

| | 做法 |
| --- | --- |
| **bloom** 绽开 | 卡面沿中心切成 6 片扇形花瓣（切片边界由同一串角度推出、相邻两片共用一条边，所以合起来与原卡面完全重合，裂开的第一帧看不出来）；张开时各片朝外漂开、各自旋转 / 缩放 / 亮度抖动，中间亮起一块花心的光，阅读面板从 380ms 起在光里浮起；收回时重建花瓣、从外面合拢。fx 让周围碎片径向退开 120·G |
| **unfold** 折展 | 卡面复制成四层薄片，各差一点偏移 / 大小 / 转角 / 透明度，叠着时最上面那张就是碎片自己；展开时先朝两侧摊开，再依次铺到阅读面的左上角、宽度对齐面板，边铺边融掉 |
| **dissolve** 溶散 | 卡面切成 10×7 像素格（边界取整，拼起来与原卡面严丝合缝）；每格先一档档变粗、变亮、朝外飘走成一团雾，再落到阅读面上按卡面比例排回一块画面，由粗到细对回焦，最后让位给正文。**像素感最强的一个** |
| **deepen** 沉入 | 镜头不动。面板从「碎片此刻的矩形再往里收 10%」长到阅读尺寸，同时整片空间 `scale(0.955)` 往里收、周围碎片被推远 + 缩 7% + 粗 1–3 档 + 暗到约 36%，一层雾从四边合拢到面板大小。碎片**不隐藏**，所以收回时面板落回原位无缝 |

两条踩过的坑，写多段关键帧 / 做副本时都会遇到：

1. **Chrome 会算错「末帧 offset < 1」的关键帧动画**：`element.animate()` 的 `offset` 序列若最后一段停在 0.82 之类，动画会在中途冲到终点、之后又插回起点（`currentTime` 与 `progress` 都单调前进，只有值在倒着走）。**末帧一定要落在 `offset: 1`。**
2. **副本起手要用碎片「当前那一档」的图**：碎片大多停在 lod 1/2（`image-rendering: pixelated` 的粗像素），副本若直接用 `it.lod[0]` 的清晰图放大，第一帧就能看出「换了东西」。

### 装饰（`?deco=`）· 新维度，五个

| | 做法 |
| --- | --- |
| **motes** 浮尘 | 最轻的一种：几到十几世界单位的像素光点，硬芯 + 一圈晕两档形状，极慢的浮（各自相位），不承担任何信息，只让「空」有厚度。接口样板 |
| **petals** 落花 | 一片披针形的百合式花瓣（两条不对称贝塞尔：基部收尖、最宽处在中偏下、两肩鼓起不同、瓣尖偏轴），半透明树脂画法（轴向渐变 + 侧向明暗 + 中脉 + 只在中近处活下来的瓣缘线）；各自 22–38s 的飘落周期、翻滚旋转，周期两端把不透明度收到零，所以接续看不出来 |
| **lamps** 路灯 | 现实锚点：细杆 + 阶梯切角的方块灯头 + 灯下一道暖条 + 极淡的光锥 + 122 单位的琥珀色光晕。杆取场景的结构灰，光是空间里唯一刻意暖的东西。`perTile: 1`、稀疏 |
| **rings** 远环 | 只铺在 1–3 层、`noSpring`、`zBias: -420`（同深度上让位给卡片），一个 1092×872 单位的环带 + 3.4 倍的光晕带，沿环有明暗渐变（一侧受光、一侧化开）；呼吸是缩放 ±4.5% / 透明度 0.76–1.0，δ 小于 0.78 时淡出，所以永远不会变成前景物件 |
| **rain** 细雨 | 7×150 的细线画两遍（0.42 外圈 + 3.5 单位全浓芯），统一朝一个方向偏 4°；2.6–4.1s 的落下周期，两端同样收透明度；远处按 `delta` 缩到 0.66 倍并压暗 |

- `deco.js` 的排法用 `DriftReg.hash` 对 `d:<名>:<层>:<周期>:<第几个>:<格x>:<格y>` 取哈希。**`reg.hash` 早先对字符串键是退化的**（`a ^ 0x9e3779b9` 把非数字串按 0 取整、`b | 0` 同理，于是所有字符串键都返回同一个数：实例全叠在同一处、`shapes[0]` 之外的形状永远画不到）。现在两个参数都按字符串走 FNV-1a。
- 随笔场景是浅色底，近白的环与雨在那里literally看不见，所以这两个在随笔改用青灰——这是为了可读性偏离「环是黑白灰」，值得再议。
- 实测实例数：浮尘 196 · 落花 60 · 路灯 22 · 远环 27 · 细雨 200（同时在场，含视口外回收前）。

## 空间

- **Z 无限循环**：镜头在 Z 上的位置 Zc；碎片分 5 层，层按周期 D = 2.5 无限重复（层距 0.5）。δ = 层到镜头的距离 ∈ (0, D]，屏上缩放 = G / δ，δ = 1 是焦平面。δ < 0.42 看不见，0.42–0.72 淡入（离镜头最近、最大、最粗的那一层，像贴着眼前的像素块）；δ > 2.05 往远处淡出。一层越过镜头，就在最远处以新的排法重新出现——滚轮可以一直往里推。
- **XY 循环**：每层把场景的全部内容排一遍（用户认可内容少时复制多份）。各层的平面周期不同（1500–2020 × 1080–1460，内容多的场景按 √(n/2) 放大），格子顺序、格内抖动、整层偏移都按 (场景, 层, z 周期) 取哈希，所以重复错开、不成网格；每过一个 z 周期排法也换一次。
- G = clamp(视口宽 / 1200, 0.5, 1)，手机上整体缩小。
- **起点**：焦平面那一层的第一块偏左上一点，屏幕中央是一块清楚的碎片，四周是不同深浅的副本。

## 失焦＝像素化

- 每张卡在 `cards.js` 里用 canvas 2D 画一次（按 dpr，最多 2×），再两步降采样出 3 档：每像素 6 / 12 / 24 个世界单位，存成 blob URL，所有副本共用。
- 按 b = |ln δ| 选档：< 0.17 清晰；< 0.42 → 6；< 0.8 → 12；更远 → 24。显示用 `image-rendering: pixelated`。档位是离散跳变：推拉镜头时，碎片一格一格地「对上焦」。
- 透明度另随 b 略降（最多 −32%），近 / 远两端淡入淡出。
- 卡片：规整矩形、三级像素阶梯切角（每级 3 单位）、半透明场景色底、左上 1 单位迎光亮边、右下压暗；中文按字折行并做避头（标点不落行首）。

## 迟滞与超调

- 每块副本在屏幕空间里各有一组弹簧（位置 x、y 与缩放 s），追「镜头算出来的目标」。
- 刚度与阻尼按深度插值：近处（δ ≈ 0.5）k = 320、阻尼比 0.92，跟得紧；远处（δ ≈ 2.3）k = 46、阻尼比 0.36，拖得久、会超调；每块再乘 0.85–1.15 的随机。拖动、推拉或飞镜头停下时，整片场景像水一样分层落定。
- 另有极小的悬浮起伏（两个不同频率的正弦，幅度 3–10px，越远越大）。
- 半步积分（每步 ≤ 1/120s），减动效时直接到位、没有起伏。

## 流光（light.js）

- WebGL2，画布只有视口的 1/5，CSS `pixelated` 放大。
- 4 个八度的 value-noise fbm，两层 domain warp（强度 2.0 / 1.9），时间缓慢流动；镜头平移带 0.00042 的视差。
- 取值先拉开对比（(v − 0.3) / 0.42），再按场景的四色梯度上色：底 → 中 → 光带，窄带上加一层亮色、峰值处混入亮芯（上限 = 亮芯色 × 1.02，不会溢成死白）。
- 量化到 26 阶 + 4×4 Bayer 有序抖动：远看是柔的光，近看是一格格的抖动像素。
- 推拉：两个八度交叉淡化（`exp2(-s)` 与 `exp2(1 − s)`，每个八度换一组偏移），光可以无限往里推。
- 光标附近有一点余温；阅读时整体压暗 42%。场景切换时调色板在着色器里 0.9s 插值过去。
- 没有 WebGL2 时退回 CSS 径向渐变。

| 场景 | 底 · 中 · 光带 · 亮芯 |
| --- | --- |
| 随笔（浅梦） | 冷灰蓝，偏亮；亮芯是一点暖白 |
| 项目（深眠） | 深靛；冷青色的光 |
| 瞬间（异相） | 暮紫；琥珀 / 粉的光 |

## 操作

- 拖拽平移（5px 后才算拖，松手按最后 90ms 的速度给惯性，时间常数 340ms）。
- 滚轮 = 沿 Z 推拉（平滑，时间常数 170ms）；横向滚动 / Shift + 滚轮 = 平移；触控板捏合（ctrl + wheel）与双指 = 推拉，双指中点同时平移。
- 方向键平移（Shift 加倍），`+` / `-` 推拉，`1` `2` `3` 换场景。
- 悬停在清楚（0–1 档）的碎片上：微亮 + 场景色的柔光。
- 视口外 160px 以外的副本回收进 DOM 池；三个场景实测同时在场 30–40 个、可见 19–31 个。

## 点开

1. 点任意一块副本（包括远处的像素块）：镜头沿 X / Y / Z 一起飞过去（ease-in-out，560–900ms，按距离），让它落在焦平面正中——一路上它一档档变清楚，别的层从身边掠过。
2. 落定后从它的矩形展开成阅读层：面板 FLIP 长到居中 760 宽、几乎满高，640ms；正文以 `steps(5)` 从模糊里一跳一跳地显影；面板也是像素阶梯切角，上沿一道迎光亮边，底是场景色 92% + 背景模糊 18px。其余碎片半透明，流光压暗。
3. 文章 / 项目显示 data 里的正文（站内阅读排版的要点）；瞬间显示大图 + 文字，多图下方有缩略图可切换。
4. Esc / 「返回」/ 点面板外收回：正文先一跳一跳地退掉，面板缩回那块碎片此刻的矩形，碎片重新出现。
5. 场景切换：旧场景的碎片朝镜头涌来、放大、淡掉；镜头向前涌 0.6，新场景的碎片由远及近浮现；流光换色。

## 方案（第四轮）

第三轮把变体拆成四个互不相干的维度，结果是四份清单：一件东西可以配任意一种反应、任意一种展开。**它们可以任意组合，所以彼此之间没有必然联系——一份设计能成立靠的是内部自洽，不是它有多少个选项。** 挑来挑去挑不出满意的组合，病根在这里。

第四轮改切法：按**一个动词**切。一个方案 = 一件东西 + 它被靠近时怎么动 + 它怎么变成可读的面 + 聚焦时它做什么。材质是动词的材料，悬停是动词的第一次发生，展开是动词的完成——三部分不再是三个决定，而是同一个决定的三个后果。

- `?scheme=thaw|develop|mirror|hang|frame`，顶掉 `?look=` / `?hover=` / `?open=`；单轴参数仍管用（面板上点任一单轴会自动退出方案）。
- 方案的四段接口与前三轮完全一样，可以引用已登记的名字、也可以内联。见 `variants/README.md` 第 5 节。
- 提案全文在 `SCHEMES.md`（六个，做了五个）。

### 聚焦：所有方案共用的一步（交互从两级变三级）

**第一次点 = 聚焦，第二次点才展开。** 之前一次点击直接展开，于是「看清一块」和「读它」被压成了一件事。

1. 镜头飞到那块（560–900ms 按距离），让它落在**焦平面正中**——于是它自然变清楚（lod 0）。
2. 四道细线角从四方浮出来框住它（屏幕空间的一层，1px 不跟着缩放；浅底上靠一层 `drop-shadow` 暗晕立住）。
3. 周围的碎片往外让开、退一档焦、暗 30%。
4. 再点它才展开；点空处或 Esc 退出聚焦。**收回阅读层后回到聚焦态**，Esc 再退一层——自由 → 聚焦 → 阅读，三级各退一步。
5. 聚焦态下不开悬停：它已经比悬停更进一层，再叠一层轻反馈只会互相打架。

方案通过 `focus.on / off / tick / yield` 管自己那一块在聚焦态下做什么，以及周围让开多少。

### 「世界为它让开」

悬停的倾斜（`lean`）、展开的长大（`grow`）、聚焦的让位，本来是同一个动作的三处零散实现。这一轮把它提成一条通用权利：**交互不该只发生在那一块碎片自己身上**。现在聚焦时周围碎片的让位是主程序的默认行为（径向推开 + 退档 + 压暗），方案可以用 `yield` 改得更细（霜化让它旋开、显影让周围退回没有内容的状态、悬落让它往上飘）。这条对《醒梦》是贴题的——世界随时可以让开。

### 审美裁定：连续是默认，像素是选择

空间（流光、装饰、推拉时的失焦分档）本来就是像素 / 定格的；**碎片本身不必跟着做像素风**。这两极最好分工：**空间承担像素与定格，碎片承担精美与连续**。景深分档保留——它不是风格选择而是距离线索（近处是真、远处化进介质里），这正好是两种质感的共存点。

反过来，若某个方案的主题真的需要像素或定格（虚框的像素版、悬落里定格的摆动），就用——要求是**它为这个主题做的选择**，不是因为背景是像素的所以顺手也做成像素。悬落就是这么做的：物体的摆动是 8 帧写死的（`steps`，不插值），而被它推着动的空气是连续的弹簧——物件定格、空气连续。

### 五个方案

| | 物 | 动词 | 悬停 | 展开 |
| --- | --- | --- | --- | --- |
| **thaw** 霜化 | 一片结着霜的玻璃，内容就在霜下面 | 融化 | 指针是一点温度，霜从落点化开一小块（留 18% 湿膜，不成窟窿），移开约 1.4s 结满 | 霜从中心往边缘退干净——**没有面板，读的就是这块碎片**；收回时霜从边缘爬满 |
| **develop** 显影 | 一张未显影的相纸 | 浮现 | 指针附近一小片先显影（径向洞 + 两档浓度，光点跟着指针 80ms 滞后） | 灰从光点那一侧先退，字从灰里浮出来；收回时字重新沉进灰 |
| **mirror** 镜映 | 一面小镜 / 一汪静水 | 表面性质改变 | 一道反光跟着指针在面上移动（椭圆光斑 + 85ms 滞后 + ≤2.4° 朝指针倾斜） | 水面升起、翻过去、变薄，正文从暗里浮上来（`contrast(0.26)→1`） |
| **hang** 悬落 | 吊着的一片压花玻璃（细杆 + 两根绳 + 一颗琥珀珠，压着一枝花） | 整件东西移动过来 | 绕绳子的挂点摆——**8 帧写死的定格**，邻居读同一个角度但走弹簧 | 悬挂散开、玻璃抬起后仰再落平，摊成读面；收回时升回原位还在轻晃 |
| **frame** 虚框 | 一块哑光树脂板 + 一道**只描线的虚框**（两者共用同一副三级阶梯角） | 两层沿各自的错位方向滑近（对位量 .5，.44s 进 / .56s 松） | 虚框朝外张开 + 朝后仰开（rotateX −36°）+ 化掉；板的面连同印在上面的字浮起来摊到阅读尺寸 |

`frame` 的方向说明：**「虚框」读成「虚的那一个框」**——两个框里有一个没有实体。它是一道边，只是这道边暂时不属于任何一件东西。**没做像素版**，理由写进了文件头：碎片是这个原型里唯一保持「精美与连续」的一极，像素与定格已经由空间承担；框若做成一格格，读面就成了屏幕，字就不再是「印在平面上」而是「显示在一个面上」。像素版该怎么改也留在注释里了——要动的是**那道虚框**（线换成 6 单位一格的点阵），板与字留在连续里，这样两层的差别本身就是「实与虚」的差别。

霜化与显影结构相近（都是「盖着一层再露出来」），但物理分得开：**霜是有边界在退、冷的；显影是没有边界、整体一起变清楚、暖的**。

**霜化最值钱的地方**：霜是**遮蔽物**，内容是**被遮住的东西**——所以浅底深底自动都成立（浅底上霜是冷白一层、化开是深墨；深底上霜是灰白一层、化开是浅字）。前两轮所有外观都栽在「一个外观要同时伺候三种底」，这个结构天然解开了它。

## 装饰的定案（第四轮）

| 场景 | 装饰 |
| --- | --- |
| 随笔 | **风**（未做——见下面第 21 条） |
| 瞬间 | **细雨** `?deco=rain` |
| 项目 | **星尘** `?deco=stardust`（浮尘 `motes` 的冷版：点更小更硬、更稀、带一层极慢的明灭；两版都留着可以对照） |

**顺手修掉的两个装饰引擎的毛病**（两个都是「看得见才算数」的那类）：

1. **装饰与碎片同深，于是被压在卡片背后。** 装饰的 z 与碎片用的是同一个公式，同深就相等；DOM 里 `#deco` 是 `#drift` 的第一个子节点、卡片都排在它后面，所以**所有平局的都判给卡片**——一大半装饰白画。修法：装饰不落在层平面上，而是浮在**层与层之间**（`deco.js` 里的 `OFF = 0.17`，层距是 0.5）。这样它在自己那一层的卡片之前、在下一层的卡片之后，遮挡关系反而更对。修完 `rain` 与 `stardust` 立刻从「几乎看不见」变成清楚可见。
2. **尺寸的底数太小。** 一枚 9 单位的柔光点缩到焦平面上只剩六七个像素、再被径向渐变一摊，等于没有。浮尘与星尘的形状都改大了（8/14/22 与 6/11/18），并且**芯改成实心的一块**——星是「硬而亮的点」，可见度该由芯给，不该靠晕去撑。

## 还不满意的

第一轮就留下的：

1. 静态截图看不出迟滞与超调的手感，需要真机拖一拖；参数（k、阻尼比）可能还要调。
2. 随笔场景推近时亮芯面积偏大，画面有一大块偏白。
3. 远处 24 档的卡片只剩色块，同一场景里两种内容（比如两篇随笔）在远处分不出来。可以让不同条目的卡底色略有差异。
4. 阅读层仍是固定居中的面板。第三轮的 `grow` / `deepen` 已经能从碎片原位长出来、把周围碎片推开，但正文排版本身还是一条居中的窄栏，没有更空间的阅读面。
5. 没有无脚本兜底（只有一句提示）；搬进站点时要像 layout-plane 那样先输出线性名录。
6. 文章正文的双态（醒 / 梦）只取醒面，没有接入梦面切换。

第三轮新添的：

7. `petal` 是「宽瓣罗塞特」而不是两片细长交叠的花瓣：正文与图片几乎占满卡片，任何能盖住它的外形都必须很胖。花的感觉落在四个瓣尖、尖部亮棱与薄花心上，轮廓的瘦长感做不到。要更瘦的瓣得先把正文的 `inset` 加大。
8. `membrane` 花心的正文对比度是新外观里最低的（内容区最低不透明度约 0.5）——这是「极薄」的直接代价。
9. `bloom` / `dissolve` 在随笔的浅色底上吃亏：卡片本身近白，散开的花瓣与凝聚的像素画面在浅底面板上几乎看不见；深色场景（项目 / 瞬间）下才成立。
10. `unfold` 与内置的 `grow` 读起来有点像，都是「卡片长成面板」；区别在多层的摊开，要真机看动效才分得开。
11. `ripple` 的环还是平滑的硬边圆弧，「粗像素」只体现在运动的 9 级台阶上；要让环自己长成像素块得再加一层抖动遮罩。
12. `petals`（落花）在远处只剩一块色斑，分辨不出形状；这是失焦档的必然，但要它当主角就得让它更靠近焦平面。
13. 装饰与碎片之间只有一条 `zBias` 可调，没有真正的遮挡关系——装饰只是叠在同一层里，永远不会挡住卡片。
14. 变体组合是 4（外观）× 7（悬停）× 8（展开）× 6（装饰），只按单维度验收过，没有系统跑交叉组合。**第四轮改成方案之后这条作废**：一个方案一次定全，组合数从几百降到五个。

第四轮新添的：

15. **霜化在随笔的近白底上最弱**：白霜配浅玻璃，对比度天生低，化开的那块因为霜本来比玻璃亮而显得比周围暗，小尺寸下像一个水渍而不像「擦干净的一块」。它在项目 / 瞬间（深底）上最成立。
16. **显影在静止态把整个场景变成一片灰卡**——内容全部被乳剂盖住，只剩极淡的字影（9% / 5% / 7%）。「几乎说不清」还是「该完全看不见」是口味问题；另外「字从灰里浮出来」的强度只是中等，没有「整片埋进灰里再捞出来」那么戏剧，因为面板一上来太灰会在碎片交接那一帧显出「重新蒙上」的跳。
17. **镜映的「反着显影」没有真做**：正文是烘在卡面图里的，真翻会翻字（正是要避开的那种廉价特效）。改成水面那一层翻过去、正文从低对比度浮上来。另外随笔上镜面与底的明暗差只有约 1.4–1.8 倍（卡面的墨色上限锁死了它能有多暗），读起来是深静水而不是黑镜。
18. **悬落的「降下来」更像「靠近」**：镜头已经被聚焦送到正中了，屏幕上的净垂直行程只有约 20px；「朝你转正」也只是 7° 的回正（静止时画的就是正对镜头的）。收回那一拍最弱——reader 的通用收回路径不钉卡片层，缩小的读面是一块空白玻璃，杆和绳要等物件接手才回来。
19. **聚焦的四道角线框的是玻璃，不含杆和绳**（`rectOf` 返回的是 `it.w/it.h`）——现在读成「世界圈出的是那一块面」，可以接受，但也可以改成框整件东西。
20. **方案只按单场景验过**，没有系统跑「同一个方案在三种光下的连续观感」（拖动、推拉、跨场景切换下的表现）。
21. **随笔的装饰「风」还没做**。风在空里看不见，只能通过它吹动的东西看见，所以最好做进流光着色器（让那片光的 domain warp 缓慢地朝一个方向流），而不是再加一层 DOM 物件——这样随笔的「空」是真的空，只是空气在动。要按 deco 做也行（极少的、极大的、极淡的雾带），但那就和另外两个场景一样是「空间里有东西」，随笔会失去它那份空。
22. **装饰浮在层与层之间**（`OFF = 0.17`）是个全局常量，没有按实例抖动；同一层的所有装饰落在同一个深度平面上。目前看不出来，但如果某个装饰变体要成片，可能会显出一条「平面」。
23. **虚框在随笔这一档最弱**：板的面在浅底上偏灰，框的对比主要靠一条发丝线和内影撑着，整块偏「装裱感」而不是「朦胧感」。悬停那一下「两层滑近」的观感（快慢、幅度）静态截图看不出，得实机看一眼。展开时虚框张开到 1.44× 的那几帧是「一条细线张成梯形」，读得出「张开」但不够有戏。
