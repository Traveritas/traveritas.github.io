# 开口 · aperture

## 1. 命题

卡片不是贴在页面上的板，是墙上的一道开口。开口里面有它自己的空间——一片远雾、一条几乎看不见的地平线、一块挡在光前面的暗形、近处厚而虚的唇；文字不在卡片上，停在最近的那个平面上。

## 2. 卡片：信息与层级

- 内部是 8 层 DOM：底暗 / 远雾（三团错位的雾）/ 挡光的暗形 / 近处暗地 / 上唇的暗带 / 四周内阴影 / 字前的薄光 / 文字。没有边框、胶囊、标题栏。
- 两个深度平面：日期与字数在最远的那面「墙」上（开口上沿，弱到 45%）；标题、简介、标签在最近的唇上（下沿的 sill）。中间那片雾不属于任何一层。
- 标题是唯一的近景重点，24px，带一点雾里的光晕；简介退到 56%，标签更弱，落在雾脚。信息没少，只是按深度分了工。
- 图片卡：照片是开口后面的场景，压暗、去饱和、虚化，四边先融进暗里再露出来；题名下压在场景的下沿。不是「图 + 标题条」。
- 页面上那层雾是活的：左下的雾会擦过卡片的下缘和标签，右边、顶上的雾会擦过卡的边。卡片因此在空气后面，而不是在纸上面。
- 双态：这一版是醒面（晨雾）。夜面把外面的纸压暗到接近洞里的暗，开口的成立从「明暗差」换成「洞里那点远光」；里面这套雾、地平线、唇的 token 不动，只把远光提亮一档、色温偏一点。外面由 `--reality-mix` 驱，里面固定——这条语言能管整站的规则是：外面可以换，里面不能换。

## 3. 展开

- 点开＝走进这张卡的里面，不是把卡片「长大」。卡片里那片远雾就是展开后的那片光：它撑满屏，成为一条从地到天的光带；卡片四周的暗唇退到屏幕两侧，成为近壁。
- 三栏被推到近壁后面，压暗、虚掉，只剩字的残影——它们还在，只是已经在你背后的那个房间里。
- 正文落在光里（640px，约 34 字），墨是暖黑；光带上下不封口，字脚那一道微微发亮的下唇就是开口的下沿。同一套层，尺度换了。

## 4. 外推：文章详情页的顶部

- 顶部不是一块题头，而是一道开口：页面顶端留 45–55vh 的暗，标题落在开口的下沿（近平面），左对齐，不居中。
- 元信息贴在开口内侧的上沿：随笔 · 断章 / 日期 / 字数 / 1 / 2，小得像写在墙上，随滚动沉下去。
- 开篇第一段从下沿「浮」上来，首屏只露三到四行；正文像从开口里长出来，而不是接在标题下面。
- 正文两侧各留一道暗的近壁（120–160px），版心收到 30–34 字；滚过首屏后近壁退去，页面才回到普通的雾面。
- 页内导览轨走在左边的暗壁里，1px 冷白，不进光里；它属于近处，不属于正文。
- 文末的关联篇章在开口之外：光收掉，回到外面的雾，用同一套卡片缩成一行。
- 页头与工具栏都留在暗处，不浮在光上。

## 5. 成本

- 全是 DOM/CSS：一张卡 8 个 span、3 组渐变、1 张颗粒，不需要 canvas，也不需要新图（图片卡用站内现有图加滤镜）。
- 真视差：hover / 滚动时用两个 CSS 变量驱 2–3 层 transform（雾、暗形、唇各不同速度），半天到一天；全走 compositor，不碰 layout。
- 边缘折射现在是用内阴影加虚掉的近边「假」出来的。真做（光在唇边弯一下）要 SVG `feDisplacementMap` 或 WebGL，一到两周，第一版不值得。
- 性能：六张卡常驻 `filter: blur` 会吃 GPU。静止时只留两层模糊，滚动 / hover 再开；或把远雾烘焙成图。
- 组件化：Card 收四个变量（`--fx` 光源位置、`--hy` 下沿高度、`--rx` 暗形位置、`--fog` 雾的浓淡），内容不动；列表、关联卡、搜索结果共用。预计两三天做完并回填全站。

## 6. 最容易做坏的地方

- 雾一匀、一亮，就退回成「带渐变的卡」；雾一暗，洞就消失。这条语言全押在这条梯度上。
- 唇一圈加亮就会滑向发光边框。现在只在最上沿留一道 1px，四周是压暗的，不能反。
- 六张卡的雾位置如果一样，立刻变成壁纸；每张得换光源、换暗形、换下沿高度。
- 页面上的雾容易做过头，变成盖在内容上的一层滤镜；标签已经压到 44%，再淡就没了。
- 展开态最险的是「变成一个聚光灯」：光带要宽、要软、要从屏幕上方出血；三栏残影是唯一能说明「你是从那儿进来的」的东西。
- 手机端要减模糊层数，视差关掉。
